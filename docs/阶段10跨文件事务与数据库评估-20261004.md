# 阶段 10：跨文件事务与数据库评估

## 当前边界

项目仍以 JSON 和普通文件保存画布、项目、历史、对话、素材索引、任务记录和供应商配置。单文件写入已经使用临时文件加原子替换，并对重要索引增加同进程/跨进程锁。目录快照工具可以在服务停止后校验和恢复一组文件，但它不把运行中的多文件修改伪装成数据库事务。

当前明确的多文件操作包括：

- 删除项目时，先把该项目的画布改回默认项目，再保存项目索引；项目索引保存失败时，画布移动已经完成，重试会读取当前归属并继续完成删除。该语义已由隔离测试覆盖，失败不会丢画布，但短时间内存在“画布已移动、项目仍在”的中间状态。
- 删除素材时，需要同时处理素材文件、分类旁车、素材库索引，以及画布/历史/对话引用；现有删除流程保留引用保护和失败恢复边界，仍未宣称跨文件全局原子性。
- 任务记录清理先建立候选副本和 `.ready` 标记，再删除并在中途失败时恢复；视频任务记录暂不进入自动清理。

## 目前不迁移数据库的理由

现有本地数据量和并发场景仍适合文件保存：画布、项目和配置是小型文档；生成媒体本身仍在文件系统；服务主要是单机单进程，已有跨进程锁只覆盖少数读改写索引。直接引入数据库会增加迁移、备份、外部素材路径、版本回退和发布依赖，不能自动解决媒体文件与浏览器状态的一致性。

因此本轮只保留可靠文件写入、明确恢复顺序和隔离测试，不新增 SQLite/PostgreSQL 运行依赖，也不移动用户数据。

## 触发重新评估的条件

在满足以下任一条件时重新做数据库原型和迁移演练：

1. 多进程写入成为常规部署方式，文件锁等待明显影响任务提交或页面响应；
2. 画布、历史、任务或素材索引增长到单次列表/扫描已出现可重复的明显卡顿；
3. 用户需要跨画布、素材、历史和任务的查询、筛选或排序，单文件扫描无法满足响应指标；
4. 需要把项目归属、引用删除、任务清理作为跨表事务，且当前“可重试中间状态”无法接受；
5. 需要多个账号或服务实例同时修改同一份数据。

迁移前必须先建立双写/只读兼容方案、格式版本、可回滚快照、断电恢复测试和旧程序读取矩阵。数据库只负责结构化索引和事务；媒体文件、外部共享目录、浏览器 localStorage 与供应商远端任务仍需单独记录和对账。

## 验证与恢复

`tests/test_data_format_migration.py`、各索引原子写入/跨进程测试、任务记录清理回归和 `tests/test_backup_restore.py` 只使用临时目录与自制数据。正式维护前先停止服务，创建并校验目录快照，再在新目录执行格式审计和恢复；不要把当前 JSON 目录直接迁移成唯一副本。阶段 10 的数据库迁移和跨文件全局事务仍未完成，路线清单保持未勾选。
