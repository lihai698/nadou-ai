## 已确认的问题

清空路由先保存空画布，再清理生成历史和媒体。故障注入确认：历史清理失败会返回 500，此时画布已为空，媒体文件仍保留。旧的两种页面遇到非成功响应直接退出本地清空流程，不能立即使当前状态与服务端一致。

后端协议和状态码不修改。已有 CanvasSaveTransport 增加内部 clearCanvas 通信函数：POST 清空失败时，只有网络错误或 5xx 才补一次不缓存的 GET，不重复发起清空。409 和其他 4xx 保留原拒绝语义。

只有同时确认以下条件，才进入本地清空流程：画布 ID 一致，updated_at 比请求基线更新，nodes/connections/logs 都是空数组，settings 是空对象。读回失败、版本未变、ID 不匹配或仍有内容时，保持原错误和本地内容。

确认部分成功后复用各编辑器原生清空逻辑，并显示“服务器画布已清空、媒体清理未确认完成”的提示。普通画布使用可见提示框，智能画布使用原生 toast。成功清空与确认部分成功都更新保存基线、清除当前页旧草稿，避免旧草稿复原刚清空的内容。普通画布同时清除旧保存队列并拒绝跨画布回包。其他页面拥有的草稿未被删除。
