# 阶段 12：扩展接入示例

## 示例范围

新增 `backend/extensions.py` 作为最小扩展合同，和 `backend/local_media_extension.py` 作为一个可独立停用的真实内置能力。示例接收文件名、Content-Type 和最多 128 字节文件头，返回媒体类型、安全扩展名、检测到的图片格式和展示文件名。它复用了已有无状态媒体规则，不读取文件系统、不调用网络、不接触 API Key。

扩展描述固定记录：

- 输入结构：`filename`、`content_type`、`head`；
- 输出结构：`kind`、`extension`、`detected_extension`、`display_name`；
- 状态结构：`succeeded`、`failed`、`disabled`、`unavailable`，附有限错误文本和 `progress`；
- 版本：`1.0.0`；许可证：`MIT`；来源：仓库内置扩展示例；
- 依赖：无。注册表会检查声明依赖，缺失时返回 `unavailable`，不会阻断其他页面或供应商。

扩展列表同时返回 `available` 和 `missing_dependencies`，设置页或维护工具可以直接提示缺少哪些依赖；执行结果不会回显输入内容。

接口为 `GET /api/extensions` 和 `POST /api/extensions/{extension_id}/run`。文件头通过 Base64 传入，仅用于演示边界；当前接口不会保存上传内容，也不会直接写素材库。真实素材导入仍由原素材入口完成，后续若需要把扩展输出写入素材库，应在入口层显式添加保存事务和引用检查。

## 停用与替换

调用方可以在注册表中停用扩展；部署时也可以把扩展编号写入逗号分隔的 `NADOU_DISABLED_EXTENSIONS`，停用结果是 `disabled`，不会伪装成成功。替换供应商时只需要新增一个满足同一 `ExtensionDescriptor` 的连接模块，页面和任务状态可以继续使用统一结果结构。当前注册表是进程内显式列表，没有扫描任意插件目录，也没有引入插件系统。

## 验证

`tests/test_extensions.py` 5 项通过，覆盖合同字段、媒体识别、非法输入、停用、依赖缺失、HTTP 列表和运行入口。测试只使用自制字节和临时 ASGI 客户端，不读取真实素材或配置，不调用外部服务。

## 尚未完成

本示例证明了输入/输出/错误/版本/许可证和独立停用边界，但没有把探测结果自动写入素材库或画布，也没有接入真实外部服务。阶段 12 的“真实外部功能完整进入素材库和画布”以及多个真实案例比较仍待用户明确外部项目、许可证和联调授权后继续，清单保持未勾选。
