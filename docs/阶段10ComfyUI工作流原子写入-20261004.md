# 阶段 10：ComfyUI 工作流文件原子写入（2026-10-04）

本轮只处理 `workflows/` 下自定义 ComfyUI API 工作流及其字段配置的本地 JSON 保存，不读取真实工作流、素材、配置或供应商数据。

## 实现

- `POST /api/workflows` 和 `PUT /api/workflows/{name}/config` 共用 `main.py` 的 `WORKFLOW_STORAGE_LOCK`，写入统一调用 `backend.atomic_json.write_json_atomic`。
- 替换已有文件前先确认旧文件可解析且顶层为 JSON 对象。已有文件损坏、顶层类型错误或原子替换失败时，返回受控 HTTP 500，保留旧文件字节和故障现场；清理本次临时文件后可在排除故障后重试。
- 保留原有接口路径、名称校验、工作流字段校验、配置 JSON 结构和返回值，不引入第二套工作流存储入口。

## 验证

`tests/test_comfy_workflow_atomic.py` 4 项通过，覆盖：

1. 工作流上传成功并可回读；
2. 模拟 `os.replace` 失败时旧工作流字节不变，排除故障后可重试；
3. 损坏的已有工作流文件不会被覆盖；
4. 配置文件的成功保存、替换失败保护和损坏文件保护。

测试只使用临时目录和自制工作流 JSON，未读取或修改真实 `workflows/`、`data/`、素材或 API 配置。跨进程锁、备份迁移和跨文件事务仍待后续，阶段 10 整体不勾选完成。
