# 阶段 14：升级与中断恢复隔离演练（2026-10-04）

## 目标

现有在线更新回归 `tests/test_update_private_data.py` 会直接调用更新入口，
但维护人员还需要一个不依赖网络、可以从命令行重复执行的升级检查。新增
`tools/verify-upgrade-recovery.py`，把升级前目录和候选更新目录都当作只读输入，
所有写入落在调用方指定的不存在工作目录中。

## 演练步骤

工具执行以下顺序：

1. 检查源目录和候选目录均为普通目录，拒绝符号链接，并记录源文件 SHA256。
2. 用 `backend.backup_restore.create_snapshot` 创建并校验升级前目录快照。
3. 在新的 `upgraded` 副本中只应用 `main.py`、`VERSION` 和 `static/` 文件；候选目录里的
   `API/.env`、`data/`、`assets/`、`output/`、历史和其他路径会被计数并忽略。
4. 检查升级后的 `VERSION`、`static/update-notes.json` 和私人文件哈希。
5. 把快照恢复到新的 `rollback` 目录，确认所有升级前文件字节一致。
6. 在另一个副本中写入第一项更新后故意中断，再从同一快照恢复到
   `interrupted-recovered`，确认恢复结果和升级前一致。

命令示例：

```powershell
python\python.exe tools\verify-upgrade-recovery.py `
  --source <隔离旧版本目录> `
  --candidate <隔离更新目录> `
  --workspace <不存在的验收工作目录> `
  --expected-version 2026.10.03
```

候选更新必须有 `main.py`、`VERSION` 和 `static/update-notes.json`，更新说明的
`version` 必须与 `VERSION` 相同，且 `update_mode` 必须是 `in_app`。工具不会下载
网络内容，不会调用供应商，也不会删除或覆盖输入目录；失败时保留工作目录供检查。

## 本轮验证

`tests/test_verify_upgrade_recovery.py` 5 项通过，覆盖：

- 升级副本保留 `.env`、素材索引、画布、历史和媒体文件；
- 中断后从快照恢复，源目录字节不变；
- `full_install` 更新模式、符号链接、版本递增和候选 `main.py` 语法检查；
- 源/候选根目录的符号链接拒绝；
- 命令行输出不回显自制配置值。

专项还用子进程实际执行命令行入口，输出只包含版本、文件数量和布尔结果，不包含
自制配置值。该演练使用临时目录和自制文件，未读取或修改当前项目的 `data/`、
`assets/`、`output/`、配置或历史。

## 限制

这是文件边界和恢复顺序的隔离演练，不等同于真实 GitHub 更新、真实用户数据跨版本
升级、旧版本二进制运行、断电现场或 macOS 安装。正式维护仍需先停止服务、创建私有
快照、在独立端口验证页面和数据格式，再切换安装目录。
