# 第十三轮：普通视频清空后晚回包

2026-10-18。核对真实可达的“清空当前画布”与生成回包配合，限定修复普通画布直接视频运行路径；未重写所有生成器或任务协议。

## 问题与改动

普通图片完成入口先查当前 pending 任务；普通视频直接运行则保留 `{out,pending}` 作为 fallback。清空后当前任务已不存在，旧 fallback 仍可修改已移除的输出、向当前画布写生成日志并触发保存。失败回包也会写旧任务日志，原 finally 会刷新旧节点。关闭输出节点时还存在同 ID 新节点被旧结果回填的边界。

新增 4 项回归在旧代码下全部失败：清空后晚成功、晚失败、关闭输出后的同 ID 节点重建，以及提交前保存等待时删除节点。

- fallback 现在携带原节点对象，仅当原节点与其输出仍属于当前节点列表时可使用。当前有效 pending 仍优先，不破坏任务恢复入口。
- 保存、提交受理及助手受理保存后检查原节点/输出是否还存在；移除后不继续提交或查询。
- 旧失败回包不再写日志、提示或保存；finally 不刷新已移除的节点。
- 助手的 knownRejected、提交状态未知等原有记录保留。第一遍回归发现提前退出影响拒绝记录，已调整处理顺序，原测试恢复通过。
- 手动关闭输出仍可正常把结果保留在原视频节点，原测试持续通过。

本轮没有主动取消上游已受理任务，也没有声称清空会停止计费。只是阻止移除节点的旧回包写回当前画布。原生节点移除检查使用对象归属，不能仅凭相同 ID 接收旧结果。

## 页面模拟与持久化

公开代码隔离副本中，测试按钮调用真实 runVideoNode。只替换视频提交和等待两个外部边界，返回自制任务编号和可手动放行的 Promise，不调用真实供应商。原生确认框使用隔离同意替身，产品 HTML 和确认行为不修改。

分别验证成功/失败：视频进入“生成中”，在回包等待期间通过原生菜单清空画布，再放行旧结果。两页保持为空，无旧错误弹窗；磁盘 nodes、connections、logs 都为空。放行前后保存 PUT 数量均为 4，没有因旧回包新增保存。恢复原 HTML 后刷新重开，两页仍为空。
