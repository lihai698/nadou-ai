# 创作助手全面理解项目与复杂创作设计草案

日期：2026-10-09。状态：用户已回复“开始”确认设计方向；阶段 A 实施计划已编写待审阅，尚未实施本方案，未提交或上传。

## 1. 用户目标与已确认决定

用户希望创作助手比自己更熟悉本项目的画布运作和创作技巧，能够选择合适的节点组合，稳定完成复杂创作。用户后续会自行配置能力强的视觉文本模型，文本模型和图片模型继续分别手动选择。

用户已确认：按项目现有节点逐类验收，暂不指定优先创作类型。普通和智能画布都需要覆盖；覆盖必须下沉到按钮、参数和实际行为，不能只给每种节点写一句介绍。

保留项目现有界面、保存与任务数据流。沿用当前画布范围、模型选择和生成确认规则。现阶段不调用真实收费服务。了解全部功能不等于自动开放删除素材、修改服务商配置或发布等动作。

可验收的目标：助手能够依据当前版本的真实功能说明与运行状态解释节点，规划可执行流程，操作已开放功能，核对保存与执行结果，并准确报告已完成、失败和未验证部分。复杂任务中断后保留进度，不重复提交已受理任务。

## 2. 当前实现与缺口：已确认事实

| 现有实现 | 当前限制 | 源码依据 |
| --- | --- | --- |
| 有限多步 Agent 与工具回执 | 每轮最多 6 次模型请求、8 次工具调用，不能直接支撑任意长任务 | backend/canvas_assistant_agent.py，run_agent |
| 读取节点基本信息与引用素材 | 最多 100 个节点；字段截取 1800 字；连接只包含 from/to，未完整提供端口、输入角色、参数和运行状态 | backend/canvas_assistant.py，canvas_context |
| 创建、改正文、连线与图片提议 | 公开创建类型只有 prompt/text/image_generator/video_generator，不能操作所有原生节点功能 | backend/canvas_assistant_tools.py；backend/canvas_assistant_operations.py |
| 三项创作 Skill | 只覆盖海报、参考图修改、提示词优化，缺少项目全部节点的运行手册和组合案例 | backend/canvas_assistant_skills.py；skills/canvas-assistant/ |
| 图片确认与原任务回读 | 图片链路有模拟闭环；其它节点执行链路尚未通过助手逐类验收 | backend/canvas_assistant_generation.py；main.py 的助手路由注入 |
| 停止、断线续行、执行编号与保存回执 | 已有可靠性基础，尚未有分阶段复杂任务计划与逐项验收状态 | backend/canvas_assistant.py |

因此，强模型能提升判断能力，但未提供的项目规则和未开放的工具，不能靠模型能力替代。

## 3. 方案选择

推荐：项目功能索引 + 按需节点手册 + 当前状态读取 + 原生操作工具 + 持久任务计划 + 结果核验。先复用现有 Python、静态 JS、JSON、Markdown 和任务接口，首期无需新 Agent 框架、模型训练或向量数据库。

备选一：把大量源码和文档塞进每次提示词。接入快，但上下文长、容易过时，也不能自动获得可执行接口，不作为主方案。

备选二：允许模型通过浏览器或任意脚本操控全部界面。表面覆盖广，但控件变化、重复点击和状态恢复难以保证，不作为日常执行方式。浏览器用于开发验收，运行时优先调用受控原生接口。

## 4. 功能知识：让模型认识整个项目

### 4.1 两层知识，分别维护

- 项目功能地图：两种画布、素材库、提示词库、模型配置、工作流、任务、保存与导出之间的关系。描述实际数据流和使用条件，私人配置不进入静态手册。
- 节点与功能卡片：每种节点及其子功能的完整说明，按需读取，不把全项目知识一次塞给模型。

每张功能卡片必须包含：稳定编号、画布种类、原生类型、用途、入口与按钮、输入输出、参数名称/类型/默认值/范围、素材角色、连接规则、执行条件、状态转换、结果位置、错误与恢复、保存重开、复制导入行为、组合示例、来源文件/函数、版本以及验收状态。

内置提示词、预设、模板变量与替换规则也纳入卡片；动态工作流参数从用户当前配置读取。ComfyUI、RunningHub 和供应商能力不能由静态说明猜测，缺少实际配置时明确标记不可执行。

运行时先提供简短索引，再让模型读取相关卡片；大画布按选中节点、上游下游和任务相关范围分页读取。模型可以要求补读完整正文，不能把截断内容当成全部内容。

### 4.3 版本与覆盖状态

知识索引按节点和子功能记录四种相互独立的状态：说明已核对、读取已接入、操作已接入、验证已完成。实际工具开放状态以程序注册表为准，文档不能扩大权限。

每张卡片关联来源函数与版本摘要。相关源码、预设或参数规则变化时，检查应标记受影响卡片待复核；不得把有文件路径等同于说明正确。开发时维护说明并验证对应行为，模型运行时不直接读取整个源码目录。

## 5. 实际状态与操作：让模型能正确使用知识

扩展当前读取工具，按节点提供完整且必要的正文、参数、上游有效输入、端口/连接角色、分组成员、循环展开规则、可用模型/工作流、当前任务编号、运行状态、已生成结果、错误和画布版本。显示草稿、已提交输入与最终结果的区别。

配置读取只提供模型名称、能力和是否可用等字段，不把密钥发给模型。未保存的手动修改仍沿用先保存/冲突检查流程；执行前复核当前版本，发生变化时重新读取和规划。

节点操作按类型接入原生处理逻辑：创建、允许的字段修改、连接、预览执行计划、确认运行、查询与结果读取。参数校验、输入展开、连线规则和执行请求尽量复用本项目已有规则；发现前后端重复规则时只提取当前任务所需的共享部分，不做全项目重构。

前端独有功能通过明确的画布适配接口调用，不让模型执行任意 JS，也不依靠模拟点击。每类接口都返回实际保存编号、差异、任务和错误；没有处理器的功能提示未开放。

沿用原生任务服务和已受理 taskId，禁止另建助手专用供应商队列。工具重复请求先检查已有回执；刷新只查询原任务。新生成、失败后重新提交和批量运行使用明确确认与范围，不自动循环消耗额度。

## 6. 复杂任务计划与创作质量

### 6.1 可恢复的计划

为当前画布当前会话保存：用户需求、必须保留的内容、输出目标、可核验要求、选用功能、步骤依赖、实际节点/素材/任务编号、已完成步骤、等待确认、失败原因和剩余预算。

执行过程：理解需求 → 查功能规则与实际输入 → 制定计划 → 程序校验 → 执行一个阶段 → 查回执/任务 → 读取结果 → 对照要求 → 完成或提出具体修正。

阶段依赖决定执行顺序；规划图和原生画布的循环不是同一概念。循环节点按原生规则展开，不能简单禁用所有循环。保留原有回合预算；复杂任务预算按阶段累计并有明确总上限，达到上限保存进度并显示继续入口，不用无限循环解决任务长度。

停止后保留已完成操作，不重复生成；页面断线与用户主动停止继续区分；旧执行器不能写入新执行，使用已有执行编号保护。

### 6.2 创作技巧与视觉核验

项目使用手册解决“怎样使用节点”；创作 Skill 解决“怎样得到符合要求的作品”。扩充现有 Skill 的按需参考文档：构图/视觉层级、参考一致性、产品与人物保持、提示词组织、多图风格一致性、分镜连续性、剪辑节奏与声音等。随节点功能验收逐步接入，不能把新增技巧说明宣称为效果已经验证。

优先复用用户所选同一个强视觉文本模型执行规划和结果检查，无需另外配置一组文本模型。图像检查读取原始结果及参考图，按需要提供局部放大与多图联系图；视频检查使用可追溯关键帧/时间戳及实际支持的音视频输入。

程序先检查硬性要求：文件可读取、任务成功、数量、尺寸/时长、素材与任务归属、必要节点和连接。视觉模型再检查主体、构图、文字、参考保持和连续性等语义要求，输出具体证据与问题位置。

验收状态为通过、需修改、无法判断；模型自评分数不能独自证明高质量。不能看清文字、不能读取音频或仅抽查关键帧时，说明检查范围。再生成需提出修改方案并确认；不因模型认为不好看而自动无限重试。

## 7. 逐类验收与完成标准

用户选择按现有节点逐类验收。建立“画布 → 节点 → 子功能”的清单，每项记录来源、说明、接口、自动检查、真实页面、外部服务结果和未确认部分。

每项适用功能至少验证：正常输入、边界参数、输入输出匹配、保存重开、复制导入、执行失败、任务等待/中断恢复及结果读取。显示类按钮验证实际显示，运行类按钮验证请求和最终结果；不适用项明确原因。

组合验收覆盖：提示词到生成到结果复用、LLM 驱动生成、循环与分组、动态工作流、视频/分镜、剪辑导出。组合案例由节点功能清单产生，不先限定某一种作品。

知识准确性检查：模型在真实保存样例中解释输入、预测展开内容、指出非法连接和缺失参数；答案与原生解析结果对照，不能由模型自判正确。

执行稳定性检查：重复操作不新增重复节点/任务；历史读取不抢执行权；断线后恢复原任务；失败时报告真实原因，保留原素材和已保存结果。

供应商与模型效果单列：开发阶段模拟边界，接入实际配置后逐条验收。只有用户明确指定测试模型、任务范围与额度后才进行真实收费验证。未配置依赖的功能标记未验证，不计为全功能通过。

## 8. 建议实施顺序与文件落点

1. 全量盘点与知识索引：先逐类读源码和现有 UI，形成可追溯功能清单、节点手册、版本与验收状态；替换目前过于简略的项目说明。
2. 状态与原生工具：按节点清单扩展读取、参数校验与操作处理器，逐项跑模拟和真实页面验证；保留已有可用入口。
3. 复杂任务与质量核验：接入持久计划、阶段执行和视觉验收，按组合案例验证恢复及输出要求。
4. 真实模型验收与交付：用户配置模型后，按批准范围验证；用户确认成功后仅提交本功能源码、测试和说明，排除已有其它任务改动。

拟使用知识目录 docs/创作助手项目知识/ 与受控运行时索引；后端扩展 backend/canvas_assistant.py、canvas_assistant_tools.py、canvas_assistant_operations.py、canvas_assistant_agent.py；复用 main.py 注入与现有任务模块。两种画布在 static/js/canvas.js、static/js/smart-canvas.js 适配原生动作，助手继续使用 static/js/canvas-assistant.js。

新增模块只按职责拆分，例如能力目录和持久计划；具体文件与接口在用户审阅本设计后写入实施计划。产品界面沿用现有助手的步骤、确认卡与历史结构；需要新增计划/验收展示时，先提供匹配普通/智能画布的桌面与窄屏预览，再改产品 UI。

新工具接入并验证后，删除被完全替代的旧映射与重复说明；未迁移功能不得删除唯一可用实现，不建立另一套 new/v2 助手。

## 9. 当前结论与审阅事项

本设计已获用户批准并开始实施。阶段 A 已接入21类节点知识、项目/创作说明、知识快照与来源版本、白名单状态和可补读分页，以及真实Agent读取工具；239章节可读、422子功能验收行分别记录范围。原生默认控件和两画布只读流程已有截图/DOM证据；21类真实路由接入使用模拟模型，未修改正式用户画布或调用真实收费供应商。

阶段 B 全节点操作覆盖、阶段 C 持久复杂任务/质量核验与阶段 D 真实模型效果仍待继续。动态结果态按钮、保存/导入/复制各边界和供应商效果不因A知识接入而自动通过；当前完整范围以实施计划、执行ledger和验收清单为准。

用户已确认采用上述方向，并选择按现有节点逐类验收。阶段 A 具体计划见 `docs/superpowers/plans/2026-10-09-creative-assistant-project-knowledge.md`；后续阶段沿用本目标，按实际接口与节点核对结果编排。“全面理解”以知识与实际行为一致、工具覆盖和逐项验收为依据，不能仅凭换强模型或增加提示词宣布完成。
