# 创作助手可安装 Skill 设计

日期：2026-10-09。状态：设计草案，待用户审阅；尚未实施、测试或批准具体第三方安装。

## 1. 用户目标与成功标准

用户希望沿用在 Codex 中安装、发现、调用 Skill 的流程和习惯：在创作助手聊天中提供 GitHub 链接、SkillHub 链接或安装说明，请助手安装；安装完成后可用 `$技能名` 指定，也可让助手根据创作需求自动选用。创作工作流 Skill 应通过本项目原生节点和连接搭建、推进创作流程，而不止生成一段提示词。

用户已认可此前关于安装来源、显式/自动调用和工作流编排的方向，并明确要求实现相同使用习惯。本文把该方向落为具体设计；本文不代表产品代码已实现。原 B→C→D 的接手对话持有助手业务修改权，本对话只编写独立设计文件，实施前需协调同文件修改归属。

完成标准：用户直接请求安装一个已支持来源的兼容 Skill 后，助手完成下载、校验、落盘和目录刷新，报告真实结果及调用示例；在两画布中均可显式调用和自动匹配，按需读正文/引用，真实保存并回读工作流；刷新后安装和管理状态保留；错误、依赖缺失及未支持来源明确呈现。

### 全局基础能力（本设计的关键决定）

创作助手内置两项全局 Skill，不把它们当作普通用户安装包：

- `find-skills`：负责发现、搜索、评估和安装可用 Skill。当用户说“找一个能完成某种创作的 Skill”“帮我安装这个 Skill”或只提供 Skill 名称时，它负责进入发现/安装流程。安装来源可以是 GitHub、SkillHub、直接 `SKILL.md`、压缩包或本地目录；它不能因为模型自行判断就安装或执行未知包。
- `agent-reach`：负责互联网资料获取和平台路由。创作需要查找参考资料、阅读网页、搜索 GitHub、查看视频或社交平台内容时，助手通过它获取资料并把来源带回创作上下文。它不负责发布、评论、点赞，也不替用户登录；需要登录态的平台先做对应健康检查，涉及账号、Cookie、系统依赖或外部服务时停在授权边界。

这两个全局 Skill 在普通画布、智能画布、新旧会话中都可用，不能被用户 Skill 卸载或覆盖。它们拥有“发现/获取资料”的基础职责，但不因此获得画布写入、节点删除、模型切换或收费生成权限。其它创作 Skill 属于可安装目录，仍受启用、自动调用和兼容性策略控制。

全局调用规则：任务涉及“找 Skill、安装 Skill、扩展能力”时优先匹配 `find-skills`；任务涉及互联网搜索、链接、GitHub 或外部平台资料时优先匹配 `agent-reach`；任务同时需要资料和创作时，先由 `agent-reach` 获取并核验资料，再由创作 Skill 和原生画布工具执行。用户显式指定其它 Skill 时，显式选择优先，但不能绕过这两项全局安全规则。

## 2. 参考与现状

官方参考：OpenAI Docs《Build skills》，2026-10-09实际检索并打开 https://learn.chatgpt.com/docs/build-skills 。参考其目录文档结构、元数据发现、按需加载、显式/隐式调用和调用策略；本项目安装来源适配和画布执行属于自己的设计，不据此宣称任意 Codex Skill 均兼容。

已核对真实源码：

- `backend/canvas_assistant_skills.py`：SkillCatalog只遍历固定三个BUILTINS，读取SKILL.md/references/*.md，记录版本哈希；不执行脚本。
- `backend/canvas_assistant.py`：ChatPayload.skillId使用固定三个id的正则；status返回Skill目录；聊天开始建立Skill快照。
- `backend/canvas_assistant_tools.py`：ReadSkill.skillId是固定Literal；read_skill读取本轮快照。
- `backend/canvas_assistant_agent.py`：手选Skill正文加入上下文，自动模式暴露索引并按需读，skillsUsed持久记录id/name/version。当前第三方文档权限分层与按需引用需复核，不能直接把任意安装内容当作最高优先级指令。
- `static/js/canvas-assistant.js`：现有Skill按钮、自动选项、手选状态和聊天payload；无安装管理、动态名称提及或安装过程。
- `main.py`：注入DATA_DIR下canvas_assistant存储根及现有登录用户、画布、模型和原生操作接口。

固定三项名单和前端选择需扩展为动态目录；项目知识索引仍是独立受版本约束的内置知识，不可被用户Skill替换。

目标目录分三层：全局基础 Skill（`find-skills`、`agent-reach`，随产品提供）、项目内置创作 Skill（当前三项，随源码提供）和用户安装 Skill（按用户隔离存储）。三层都使用同一套渐进式发现/按需读取协议，但权限、更新和卸载规则不同。

## 3. 路线选择

| 路线 | 体验与代价 |
| --- | --- |
| 推荐：现有助手接入受控安装服务与动态Skill目录 | 保留聊天安装、$调用和自动匹配习惯，复用本项目Agent和画布执行；按来源增加下载适配 |
| 仅增加上传/粘贴提示词 | 改动少，但无法满足链接安装和完整Skill资源组织，不能作为本需求交付 |
| 引入通用终端、任意脚本与整套外部插件运行时 | 兼容范围更大，但改变运行架构、依赖和权限；属于后续单独设计范围 |

本设计采用推荐路线，完整保留Skill文件结构，明确区分“文件安装成功”与“当前助手可执行”。安装阶段不执行Skill包内脚本；本期运行依赖现有原生画布工具。以后如需执行脚本/MCP，按具体能力单独接入，不把尚未支持的能力说成成功。

## 4. 使用流程

### 聊天安装

支持“帮我安装这个Skill：<链接>”以及 `$skill-installer <链接>`。内置安装入口的名称保留，不允许第三方覆盖。现有Skill按钮也提供“安装Skill”，两种入口使用同一服务。

用户明确请求安装且来源/目标唯一、无替换冲突时，直接完成必要安装步骤，不再重复询问是否安装。用户只分享链接、讨论安装例子、引用命令或询问可行性时不启动安装。仓库含多个Skill且用户未指定、来源不明确或要替换不同来源的同名Skill时，只问对应缺项；不下载全部Skill猜测用户目标。

支持粘贴常见安装说明。已支持的安装格式会解析成结构化来源、namespace、skill名称、版本等信息，目标始终明确显示为“当前用户的创作助手”。例如包含--agent codex的说明可识别来源并说明实际目标转换，不修改用户Codex目录。未支持命令不能当任意shell执行，也不能假称安装完成；返回未支持来源/格式和可接受的链接输入。

成功回复示例：“已安装 商品海报。可用 `$product-poster`，或直接描述商品海报需求，由助手自动选用。”依赖未满足则分别报告文件已安装、暂不可运行及具体原因，不能只回复成功。

### 显式与自动调用

输入`$`展示已启用Skill的搜索候选，选择后形成绑定真实id的提及；支持直接输入`$skill-name`，也支持原Skill按钮。未知名称明确报错，同名不同来源显示来源并选择，不能静默挑选。美元金额、代码、引用文本中的名称不误识别为调用。用户显式选择优先，自动模式按描述匹配。

默认对已兼容且启用的Skill允许自动调用；遵守agents/openai.yaml中的policy.allow_implicit_invocation=false，并允许用户单独关闭自动调用。该设置不关闭显式调用。缺失声明按兼容规则处理，不能把未知字段解释成新权限。

索引只提供名称、适用说明、内部id和兼容状态；模型决定使用后再读取正文和需要的引用。目录很多时分页/检索，不把全部正文塞进上下文。模型自动选择是匹配机制，不保证每种措辞都会触发；通过正向/反向例子验证。

工作流Skill首先读取本项目规则与真实节点/输入/模型状态，再以已开放原生动作创建、配置、连接和回读。未开放动作明确说明，收费生成按既有确认与预算机制处理，不因调用Skill扩大权限。多步执行和恢复接原B/C任务计划及回执，不另造收费任务队列。

## 5. 来源与兼容性

- GitHub：支持仓库、指定分支/提交、Skill子目录以及SKILL.md链接；解析仓库树与Skill根，保留引用和模板。多候选走明确选择。记录实际下载提交，分支名不得冒充固定版本。
- 第三方SkillHub：通过独立来源适配器读取平台提供的元数据和包。MOKE示例列入目标验收来源；其真实API、包结构、许可证与下载行为尚未核验，是该适配器实施前必须完成的只读核对。不假定平台地址就是ZIP下载地址。
- 本地：文件夹或ZIP作为补充入口，使用相同校验与目录登记。
- 支持标准SKILL.md的name/description以及references、assets、templates等配套资源；agents/openai.yaml只读取已支持的展示、调用策略和依赖字段。脚本可作为包文件保留，但不在安装/调用时执行。
- 明确依赖本机终端、Codex专有工具或未接入MCP的Skill标记依赖未满足。自动检测是声明检查加必要静态核对，不承诺能证明任意文档完全兼容；运行遇到缺能力明确中止该步骤。
- 用户安装请求不授权自动安装Python/npm系统依赖、修改后台模型、连接外部账号、使用收费额度或写入包要求的任意目录。

`find-skills` 和 `agent-reach` 的来源、版本和许可证在产品构建时固定登记；本设计已核对的参考来源为 Vercel `vercel-labs/skills` 中的 `find-skills`（MIT）和 Panniantong `Agent-Reach`（MIT）。产品内置的是适配后的只读/受控能力层，不直接把第三方脚本当作本项目的系统权限。Agent Reach 当前上游声明需要 Python 3.10+，并可选依赖浏览器、Cookie、MCP 等能力；这些依赖必须逐项检测，缺失时显示“资料获取能力不可用/需配置”，不能自动安装系统依赖。

## 6. 数据与安装事务

复用应用DATA_DIR与safe_user_id，用户存储根为`DATA_DIR/canvas_assistant_skills/<用户键>/`，与内置源码目录分开，跨该用户普通/智能画布可用。固定内置三Skill继续可用。目录位置通过后端配置注入，不用前端传绝对路径决定写入位置。

安装记录包含：内部唯一id、名称/显示名、description、来源类型/原地址/namespace、实际版本或提交、安装时间、内容摘要、许可证信息或未提供标记、enabled、allowImplicit、兼容状态及依赖说明。名称与目录键分离，第三方不能覆盖内置名称或写入其它用户目录。

安装状态：解析→下载→校验→写入临时目录→原子登记→刷新目录→成功/失败。限定文件数量、总大小、超时和解压后大小；拒绝路径穿越、外部符号链接和不合法路径。下载地址与每次重定向都校验协议/目标，防止链接访问本机服务或私有网络。具体阈值由实施计划结合当前约束给出并测试，不开放无限大小。

重复安装同来源同版本返回已安装，不覆盖其它来源。同来源更新先下载校验再切换新版本；失败保留旧版本。不同来源同名必须显式选择。安装完成后立即可发现，不要求重启应用。

每回合固定Skill内容快照，存真实版本和使用回执。更新、停用、卸载对新回合生效；历史/活跃回合按已有快照恢复，不静默换版本、不重放已执行动作。卸载只操作该用户安装记录和包文件，素材和画布结果保留；共享资源有引用时不误删。

## 7. 接入边界与界面

安装解析/下载/校验/落盘由后端专门服务负责，通过现有用户鉴权暴露安装状态和目录管理接口。模型可提出安装意图，但确定来源与写入范围由服务校验，不执行模型生成的shell命令。动态目录统一服务status、手选、read_skill及$名称解析，移除被完整替代的固定校验名单，保留内置注册与安全限制。

聊天安装在用户明确请求时进入持久安装流程，不能误当普通创作回复；恢复或重复点击查同一个安装任务，不重复下载/写入。输入混合安装与创作时，先安装并确认可用状态，再按用户已给的创作要求进入正常Agent流程，收费边界不变。

现有Skill按钮增加搜索、已安装列表、安装入口和详情；详情提供来源/版本、启用、自动调用、更新、卸载及兼容提示。界面使用本画布原生颜色/字体/按钮，安装进度和Skill使用过程沿用“一行进度＋可展开详情”。收费确认、失败和必要选择保持外显，结果区域优先作品与回复。实施前提供桌面/390px预览并验收两画布实际布局。

## 8. 验收与实施顺序

1. 全局基础能力：`find-skills` 的名称搜索/来源评估/安装意图识别，`agent-reach` 的资料获取路由、健康检查、来源记录和无登录态降级；两者在两画布和新旧会话中都可用且不能被卸载。
2. 动态目录、元数据解析、资源读取与回合版本快照：三个项目内置Skill回归；不同用户隔离；启用/停用、显式优先及禁止自动调用。
3. GitHub及本地安装：真实公开小型Skill下载；目录/子目录/固定版本/多候选；非法格式、解压穿越、重定向、超时、重复安装、失败不损旧版。
4. 第三方安装说明与SkillHub：先核对真实平台下载协议再接入适配，使用用户示例逐项验收；未支持平台明确失败。安装测试保证包内脚本零执行、Codex目录及其它目录零写入。
5. 聊天安装、$提及和管理UI：两画布实际操作、桌面/390px、刷新重开、错误/禁用/同名选择；引用的安装例子不得触发安装。
6. 创作工作流Skill：显式和自动各完成一个原生节点/连接/参数保存回读案例，加不应触发的相邻需求；停止/恢复不重复创建，不新增收费提交；依赖缺失不虚报成功。
7. 相关测试与独立审查通过后清理旧固定名单/重复入口并再次验证。真实模型效果与收费供应商测试需用户明确范围，不由隔离mock代替。用户手动确认可用后才按AGENTS精确提交/推送，不发布。
