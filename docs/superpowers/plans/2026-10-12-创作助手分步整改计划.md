# 创作助手分步整改计划

> 实施人员：按 superpowers:executing-plans 逐项执行；本次只编写计划，尚未开始产品改造。每次完成一个可独立验收的任务，再继续下一项。

**目标：** 保留已有有效能力，让助手界面清楚、操作有真实结果，并逐步形成可重新执行的创作流程。

**实现方式：** 复用现有 Python 助手执行器、原生节点及两种画布适配器。先整理界面呈现，再补齐模型分析链，不更换框架、不另建一套助手。

**现有技术：** Python 后端、JavaScript/CSS 前端、原生画布节点及现有模型接口。

**依据：** 用户本次要求、《项目长期维护与二次开发路线.md》、[现状分析](../../创作助手现状与画布IDE差距分析-20261012.md)。

## 一、先统一这次到底做什么

用户要的是能帮助完成创作的画布 Agent：理解要求，读取画布，创建正确节点，连接真实模型，执行并检查结果，失败后可以定位和继续。

这次按阶段整理已有实现，不一次重写。Skill 安装、在线技能市场和完整 IDE 功能暂缓；已有内置 Skill 继续保留。暂不扩充更多引擎或复杂生成类型。

“助手在聊天里生成内容，再填入节点”和“节点本身能再次调用模型执行”是两种能力，界面和说明必须分清。后者才是本次后续要补齐的可执行流程。

| 项目 | 已确认情况 | 本次处理原则 |
| --- | --- | --- |

| 普通和智能画布故事节点图 | 已有内容落地、连线及编辑同步 | 不再称为完整可执行流程 |

| 助手界面 | 状态和计划信息占用较多；日志本身已经默认折叠 | 整理仍暴露在折叠区外的信息，避免重复建设 |
| 参考项目经验 | 已采用工具循环、回执、持久化等思路 | 针对具体缺口补齐，不为名称引入整套运行时 |

| 全部供应商和创作效果 | 未全部实际验收 | 不把源码存在或模拟通过写成真实生成通过 |

此前页面尺寸测量来自 3034 隔离测试页，不代表用户全部页面。实际整改前还要核对当前真实入口、两种画布和当前工作区差异。

## 三、所有阶段共同遵守

- 保留现有模型选择、模板库、素材引用、内置 Skill、历史、新建对话、停止、继续及原生节点能力。
- 采用对应画布现有配色、图标、控件和交互，不另建视觉体系。
- 保留任务编号、去重、画布归属、用户模型配置、原子保存和真实错误记录。
- 不自动运行收费任务；模拟验证与真实供应商验证分开记录。
- 不删除用户画布、素材、任务历史或个人配置，不混入其他尚未确认的工作区改动。
- 被替代代码在新实现通过验证后清理；未查清调用关系的代码不凭感觉删除。
- 用户确认功能成功后，按项目约定选择性提交、上传源码；此前不上传。
- 每阶段记录：实际修改、验证结果、清理项目、未验证部分、用户验收状态。

## 四、第一阶段：让助手界面清楚、可读、可操作

### 4.1 本阶段成果

打开助手后，主要看到对话正文和输入框。执行过程中只显示一处当前状态；详细日志可以展开；需要确认、失败或受理状态不明的操作必须清楚可见。已有按钮和执行能力保持可访问。

本阶段不改变模型调用、收费确认规则、后端任务状态或节点生成逻辑。界面整理完成不代表创作流程已经打通。

### 4.2 涉及文件与职责

| 文件 | 作用 | 修改边界 |
| --- | --- | --- |
| `static/js/canvas-assistant.js` | 共用助手面板、状态、历史和操作卡片 | 主要修改位置；整理显示与事件绑定 |
| `static/css/canvas-assistant.css` | 面板、阅读区、输入区和卡片样式 | 复用现有变量，减少无效占用 |
| `static/canvas.html` | 普通画布脚本入口 | 仅在需要时更新资源版本 |
| 智能画布实际页面入口 | 智能画布资源加载 | 实施前查明真实引用，再决定是否更新版本 |
| `tests/canvas_assistant_*.test.cjs` | 现有助手行为回归 | 复用相关测试；行为缺口增加针对性用例 |

实施前重点读 `showStatus`、`addProgress`、计划呈现、`drawHistory` 和原生操作卡片。不得只改 CSS 隐藏内容而留下无法访问的控制按钮。

### 4.5 任务 C：统一折叠详情和已完成操作

## 五、第二阶段：打通文本到模型分析再到分镜

第一阶段验收后再细化此阶段代码任务，不在当前文档中猜测尚未核对的节点接口。

- [ ] 对照普通、智能画布原生 LLM 节点，查清输入端口、模型字段、执行入口及结果保存方式。
- [ ] 固定最小链：原文输入 → 已绑定文本模型的分析步骤 → 结构化分镜结果。
- [ ] 明确助手聊天模型与画布执行模型的用途；已有明确模型选择可显式传入，不擅自猜选。
- [ ] 明确分析结果怎样转成分镜表，格式错误时给出真实错误，不能用预填内容伪装执行成功。
- [ ] 支持原文修改后的明确重跑；原文编辑本身不自动触发收费调用。
- [ ] 保存重开后输入、模型、连接和结果保持一致；旧故事结果图不自动付费迁移。
- [ ] 模拟验证通过后，记录一次经用户授权的真实模型执行；用户检查分镜内容再验收。

完成条件：能看到实际请求使用的原文和模型，获得对应结果；改原文重跑后结果更新；缺模型、格式错误和请求失败可定位。两种画布分别验收。

## 九、统一检查重点

1. 历史重开后不重复提交任务，不重新弹出已经完成的确认。
2. 失败和受理状态未知始终可见，不被折叠策略掩盖。
3. 切换画布或会话后，旧结果不能回填到当前错误位置。
4. 长中文、小窗口及弹层打开时，发送、停止和必要确认仍可操作。
5. 用户已有模型配置和生成结果在升级、编辑、保存重开后保持完整。

相关行为分别在所属阶段验证，不为每次样式调整重复执行全项目耗时检查。
