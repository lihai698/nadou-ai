# 音频节点接入计划

修订：2026-10-10。用户已批准实施当前方案。
规范：[设计](../specs/2026-10-09-audio-node-design.md)。主方案：[方案](../../音频节点与API联动方案-20261009.md)。

## 实施边界

在当前源码接入，保留其他任务改动。只有音频连接 API 时自动识别；平台、模型和运行手动。API 增加音频生成／识别分支，识别文字→现有 LLM。无独立 audio-generator、无 Prompt 转写按钮、无新增手动模式按钮。原图片分支及级联行为不改。普通音频节点复用媒体引用；智能画布保持 smart-image 原媒体容器与原 API 面板，分别适配外观。

## 任务与验收

1. 音频契约：补识别能力与模型校验、实际文本返回、媒体安全校验；先运行失败测试再实现，保留已有生成规则。
2. 后端任务：识别复用音频持久任务路由；安全解析音频、OpenAI 兼容 multipart 转写、文本结果、幂等及响应丢失；隔离测试不调用真实供应商。
3. 普通画布：素材创建／旧形状读取迁移／播放器与素材操作；原 API 入口增加音频分流；手动选择模型、原音频编号恢复查询；识别结果→LLM原输入与运行。
4. 智能画布：原 API 参数与手动选择模型、音频来源自动识别、原素材播放、识别结果→已有 LLM；保留原图片／视频配置和运行路径。
5. 数据兼容与清理：保存重开、复制编号隔离、组与输出引用；新入口验证后清理完全替代的草稿／旧创建分支，搜索遗留。
6. 验收与审查：单元／关键流程、JS/Python语法、隔离真实页面操作、深浅主题与中文显示。只以已运行证据报告；用户手动确认成功前不提交、不推送、不发布。

## 特别检查

- 连线本身不提交、不选平台、不覆盖图片模型，不吞掉其他类型素材。
- API 识别文本作为文本结果，LLM不收到音频URL或假文字。
- 不支持的参考音频、空文本／假音频、失效素材、保存失败均明确报错。
- 任务编号持久化后提交；重复编号不重复调用，网络中断暂停查询，不自动重提。
- 正在执行时连线变化只影响下次；复制节点不能复用运行中任务编号。
- 原图片并发、参数、轮询、输出、级联及素材库回归。
