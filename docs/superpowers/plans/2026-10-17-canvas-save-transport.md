# 画布保存通信边界迁移计划

> 按 executing-plans 执行，使用失败测试固定合同；用户已授权继续。保留前三轮未提交修改，不提交推送或发布。

**目标：** 从两个画布核心文件提取保存 HTTP 请求、响应解析和冲突版本读取边界。

**架构：** 新增无 DOM、无持久状态的 `CanvasSaveTransport`，两个适配函数分别保留普通与智能画布的协议差异。编辑器仍管理排队、快照、草稿、合并、任务编号清理、历史及状态提示。

**技术：** 原生 JS 脚本、Node 测试、原 FastAPI；不新增依赖、不改接口。

## 事实与边界

- `canvas-save-recovery.js` 已管理合并、IndexedDB 草稿和跨页恢复，不重复建设。
- 普通画布成功回包必须有 nodes，冲突回包可来自 detail.canvas 或 canvas，没有补读 GET。
- 智能画布成功回包继续交给原编辑器，冲突只有 detail.canvas；缺少较新完整版本时补读 GET，仍不可用则失败。
- 智能画布在发现 409 时立即清除旧的排队标记，早于 JSON/GET 等待；新编辑可在等待期间重新排队。此时序必须保留。
- 普通冲突比较响应处理时的当前版本，智能冲突比较冲突 JSON 解析后的已保存快照版本；不改变现有动态读取时机。
- 两边的 URL 编码、错误文案、JSON 失败行为、请求字段、500 条日志等现有语义保持。

## 接口

- `CanvasSaveTransport.saveClassic({id, payload, request, getVersion})` 返回 `{kind:'saved', canvas}` 或 `{kind:'conflict', canvas}`。
- `CanvasSaveTransport.saveSmart({getId, payload, request, getVersion, onConflict})` 返回 `{kind:'saved', data}` 或 `{kind:'conflict', canvas}`。onConflict 在 409 响应到达后同步调用；getVersion 在解析冲突 JSON 后读取一次；getId 沿原时机用于 PUT 与补读 GET。
- 失败抛出原错误，原 saveCanvas 的 catch/finally 仍负责草稿、提示和排队。模块不重试 PUT、不生成任务、不修改画布。

## 验收重点

1. 请求正文、任务编号与版本不丢失，保存失败不假成功。
2. 普通元信息冲突和智能 GET 回退保持差异；旧版本不误当新版本。
3. 409 排队清理先于异步等待，期间的新编辑不会被清除。
4. 并发已受理任务、等待中的保存、离开页面与撤销重做由原整合测试覆盖。
5. 两个 HTML 必须在编辑器前加载模块；修改源码后同步知识来源摘要。
