# 自动保存调度生命周期计划

> 用户已授权继续，按 executing-plans 和失败测试推进，完成后独立审查。保留前五轮，不提交、推送或发布。

**目标：** 统一自动保存计时器归属，处理防抖替换、取消、手动保存、后续保存及画布身份变化后的旧回调。

**架构：** 新增 CanvasSaveScheduler，宿主注入 save/getCanvasId，可注入计时器用于确定性测试。一个编辑器一个实例。Session 继续管保存队列，Transport 管 HTTP，Recovery 管持久草稿。草稿备份的时机和内容不变。

**技术：** 原生 JS、Node/unittest，无新依赖。

## 明确的行为修正

普通画布取消/执行计时器后仍保留 truthy 的 saveTimer，清洁画布可能被当成仍有待保存任务。本轮用回归证明自动保存成功后返回仍多发一次 PUT，再把判断改成实际 pending。dirty、正在保存及 queued 仍独立保护未保存内容。

取消或替换后即使旧计时回调已进入队列，也不能再执行；回调绑定的画布 ID 与当前不同则丢弃。此为保存调度生命周期修正，不迁移用户数据，不改变请求或生成行为。

## 接口

`CanvasSaveScheduler.create({save,getCanvasId,setTimer,clearTimer})` 返回只读 pending、schedule(delay)、cancel()。默认计时器使用浏览器原有 setTimeout/clearTimeout。schedule 先取消旧任务；回调先清 pending，再核对票据和画布身份并调用 save。取消使票据失效，handle=0 也必须可取消。
