# 创作助手 Skill 交互设计（2026-10-11）

状态：已完成源码核对及交互预览，正式界面尚未接入本方案。用户本次指出选择不明显、列表位置不合适，并要求考虑未来大量 Skill。

## 已确认的问题

- `static/js/canvas-assistant.js` 的 `selectedSkill()` 按用户和画布读取保存的选择；聊天请求已发送 `skillId`。因此不是选择没有参与请求，而是前端缺少持续展示。
- `fillSkills()` 选择后关闭列表，仅调用短暂状态提示；按钮仍写作 Skill。
- `static/css/canvas-assistant.css` 将选择列表绝对定位于助手内部，而助手自身 `overflow:hidden`。大量选项会遮挡对话，并有被裁切的风险。
- 后台 `ChatRequest.skillId` 与 `SkillCatalog.BUILTINS` 都固定三个编号。未来扩充必须同时处理目录、请求验证和发布资源，不能仅画出更多按钮。
- `backend/canvas_assistant_agent.py` 已记录实际 `skillsUsed`。后续消息标记应取服务端本轮实际记录，通过受控公开字段提供给前端，不能用当前输入选择倒推历史轮次，也不能在自动模式尚未使用 Skill 时编造使用记录。

## 推荐：旁侧选择

1. 按用户最新反馈，取消输入框上方独立的 Skill 行；在输入框内部首行开头显示 `[提示词优化 ×] / 输入内容`。正文紧随 `/`，换行后使用完整输入宽度，不增加输入框高度。点击 × 恢复自动选择，移除前缀并归还输入空间；保留草稿，不把 Skill 名称或分隔符写入正文。
2. 原 Skill 按钮保留，小圆点提示已有手选项；点击开启独立选择面板。
3. 宽屏把面板放在助手旁边，默认左侧。助手移动或调整高度时同步定位；左侧空间不足时翻到右侧。面板不放入助手裁切容器，也不挤压对话高度。
4. 窄屏使用独立底部选择面板；关闭后回到完整聊天界面。
5. 选择面板提供名称/用途搜索、分类、选中勾选，固定高度并独立滚动；空搜索结果显示明确提示。选择后收起，Escape 或点击外侧关闭，焦点返回 Skill 按钮。
6. 每轮消息显示该轮实际使用的 Skill；历史轮次保留原记录。自动选择仍允许系统按需求读取多个 Skill，用户手选保持当前单选逻辑。

备选：独立居中的选择窗口。可用更宽的列表，但会暂时遮住聊天，需要关闭窗口后继续输入。两种方案在预览中均可切换。
