# 助手作品检查模块化验收（2026-10-21）

本批把 `inspect_result` 与 `record_result_review` 的完整业务迁入 `backend/canvas_assistant_result_review.py`。真实助手路由仅转交本轮数据，仍由原会话执行器负责执行归属、停止、检查点和评价持久化。底层图片完整性、视频容器与抽帧检查继续由既有质量模块负责。

## 边界与行为

- 服务持有六个只读应用端口：画布、平台能力、本地文件解析、允许根目录、原图片任务、原生任务查询。每次调用的检查、任务、评价数据均为局部变量；服务不写画布或会话，不提交生成任务。
- 本轮方案仍通过原异步查询读取；原视频任务列表、确认状态、归属与结果完整性均保留。图片参考图、所有结果、去重顺序、最多两段视频及“图片数 + 三倍视频数不超过八”的规则未变。
- 检查前复制画布，文件检查后重读画布；保存评价前重新检查文件、任务与快照，变化时拒绝旧评价。
- 图片与三张带时间戳视频抽查帧须确实进入后续模型输入，才能登记视觉结论；文本模型、缺帧、未送达及未确认条件继续拒绝或降为 unknown。硬条件失败不能被模型自评覆盖。视频抽查不证明整片连续性和音频语义。
- Agent 与检查服务共用的 `model_image_identity` 原主体移入既有纯规则模块，两个真实调用方均限定调用新所有者；视频帧送达证据使用摘要，不重复保存原始帧。
- 路由中的旧检查主体、专用 hashlib 导入及旧身份函数均已清理，无兼容转发。其他助手业务本批未迁移。
