## 维护工具编码

`tools/backup-restore.py`、`check-data-formats.py`、`cleanup-task-records.py`、`prepare-release.py` 在解析命令行参数之前，将标准输出及错误输出设置为 UTF-8，沿用项目已有做法。错误仍返回原有非零退出码，没有忽略异常或修改备份、检查、清理规则。

`tests/test_maintenance_cli_encoding.py` 强制子进程使用 `PYTHONUTF8=0` 和 `PYTHONIOENCODING=cp1252:strict`，覆盖四个工具的中文帮助，以及备份、数据检查、清理预览的成功/失败路径；旧代码实测失败，修复后 4 项通过。既有三个测试文件显式按 UTF-8 读取命令输出，原有 18 项继续通过。

旧的依赖系统默认编码的输出方式已在原入口替换，没有新增另一套维护工具。

## 八项页面验收

隔离环境使用真实画布页面、原生前端适配器、助手 HTTP 入口、原有画布文件保存和图片任务队列。仅助手模型决策、文本模型边界和图片供应商结果使用确定性的本地模拟；图片为自制 PNG，不代表实际模型效果。

| 任务 | 普通画布 | 智能画布 | 关键核对 |
| --- | --- | --- | --- |
| 文本整理 | 通过 | 通过 | 正文更新，保留一个节点，重开一致 |
| 故事到分镜 | 通过 | 通过 | 原故事保留，运行真实原生文本节点，导入两镜分镜表；每项授权并使用一次节点调用 |
| 单镜修改配图 | 通过 | 通过 | 仅改第一镜，第二镜与旧图保留；修改内容进入文本节点，图片请求使用其实际输出；每项授权并使用两次节点调用 |
| 失败续行 | 通过 | 通过 | 第二步前注入一次 503，第一步已保存；点击一次继续后完成第二步，未重做第一步 |

最终八项各自只有一个完成回合，原生动作均完成；总计 4 次模拟文本节点请求、2 次模拟图片供应商执行。重开八项画布后再次只读核对，无新增生成。助手自身的模拟决策请求单独记录，不计入节点调用上限。

验收脚本按实际保存状态推进，并在版本变化时使用 `read_canvas` 补读；保留产品原有的旧版本拒绝保护。图片完成依据原任务编号、真实任务记录及结果节点，不假设生成节点存在统一的 `status=succeeded` 字段。

前期调试发现测试分镜样例缺少必填的任务、列、起止时间字段，以及模拟器对文本/图片结果识别不准确；均修正测试材料，未据此修改产品。早期材料保留在 `output/creative-flows-20261017/` 和 `output/creative-flows-20261017-final/`，不计入最终通过结果。最终材料在 `output/creative-flows-20261017-verified/`，包含 `verified.json`、`browser-reopened.json`、八项重开截图和中断截图。调试单镜案例已退出最终案例清单，历史证据保留。

## 如何重复验收

在项目根目录执行，`--workspace` 必须指定不存在的新目录：

```powershell
python\python.exe tools\verify-creative-flows.py --workspace output\creative-flows-repeat --port 3063
```

按新目录 `cases.json` 中的地址依次打开八项画布，展开创作助手，选择并勾选本地模拟平台的 `flow-text` 和 `flow-image`。发送该案例的 `message`：

- 文本整理：等待任务完成。
- 故事分析：任务面板授权一次节点运行。
- 单镜配图：任务面板授权两次节点运行。
- 失败恢复：确认第一步保留，打开任务面板，点击一次“继续创作”。

完成后分别在新标签重开画布，核对正文、分镜、连线与图片；最后另开终端执行：

```powershell
python\python.exe tools\verify-creative-flows.py --workspace output\creative-flows-repeat --port 3063 --verify
```

核对器检查八项案例、原回合完成状态、原生动作、授权次数、模型结果证明、图片任务、实际图片请求输入及执行次数；未完成时返回非零，不写成功证据。通过后将结果写入该验收目录的 `verified.json`。服务终端按 Ctrl+C 停止，原目录保留作为验收材料。

`tests/test_creative_flow_regression.py` 将两画布文本保存、中断续行及分镜样例与真实前端格式的兼容性纳入核心检查。这里的 HTTP 回归不代替上述八项浏览器操作。

## 自动检查

`.github/workflows/core-checks.yml` 在 `main`、`codex/**` 分支推送、拉取请求及手动触发时运行：Windows、Python 3.10、Node.js 22；安装锁定依赖后运行 `tools/check-core.py`、发布预检和 `git diff --check`。仓库权限只读，同分支新任务取消旧任务，超时 45 分钟。没有发布或密钥配置步骤。

本地日常检查仍可双击根目录 `检查核心流程.bat`，或运行：

```powershell
python\python.exe tools\check-core.py
python\python.exe tools\prepare-release.py --preflight
```
