# 阶段 9：画布任务错误规则试拆（2026-10-04）

## 范围

普通画布的 `normalizeCanvasTaskError` 只做错误文本判断：空文本使用调用方默认文案；后端重启、画布图片任务记录缺失和网络连接异常统一使用“后端重启/任务状态丢失”提示；其他错误原样保留。

这段逻辑没有 DOM、配置、画布节点、浏览器存储或网络依赖，适合先拆成纯规则模块 `static/js/canvas-task-error-rules.js`。页面保留同名兼容入口，继续由 `canvas.js` 提供本地化文案和级联状态上下文。

## 改动

- `static/js/canvas-task-error-rules.js` 暴露 `CanvasTaskErrorRules.normalizeErrorMessage(error, options)`，可在 Node 环境独立测试。
- `static/canvas.html` 在 `canvas.js` 前加载规则模块。
- `static/js/canvas.js` 删除原内联正则判断，改为调用规则模块；外部调用名称与错误提示行为保持不变。
- `tests/canvas_task_error_rules.test.cjs` 覆盖空错误、重启文本、404 任务缺失、网络错误、普通供应商错误和真实脚本加载顺序。

## 验证

使用 `node --check static/js/canvas-task-error-rules.js`、`node --check static/js/canvas.js` 及 `node tests/canvas_task_error_rules.test.cjs` 验证。真实供应商、真实任务和私人画布数据不在本次范围内。

## 后续候选

智能画布的任务状态轮询仍与节点状态、恢复信号和供应商差异紧密耦合；在没有统一状态协议测试前不继续抽取，避免把独有行为误合并。
