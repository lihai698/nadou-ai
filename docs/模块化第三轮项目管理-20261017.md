## 分工与清理

| 位置 | 当前职责 |
| --- | --- |
| `backend/project_store.py` | 项目文件加载、原子保存、默认初始化、新建和更新；注入路径、共享锁、时钟及 ID 工厂 |
| `backend/project_records.py` | 摘要、排序及 `project_list_records` 纯汇总；只计入调用方传来的有效画布，不修改输入 |
| `backend/project_service.py` | `delete_project` 在共享锁内协调预读、画布归属迁移和项目索引保存；不直接读取画布文件 |
| `main.py` | HTTP 路由、依赖注入、错误转换；保留画布读取验证适配器与既有画布写入入口 |

主程序的旧重命名、排序更新、计数和删除协调算法已经迁出，原 `project_sort_key` 专用导入清除。`load_projects`、`save_projects` 两个包装经全局搜索确认无调用者后删除；`ensure_default_project`、`new_project` 仍分别供原列表和创建入口使用。

项目操作错误统一由 `ProjectOperationError` 表达，原 `ProjectReadError` 保留为子类；主程序仍转换为原有 HTTP 状态与说明，不在模块里引入 FastAPI。

## 删除行为保持原样

1. 默认项目不可删除；不存在项目维持 404。
2. 先完整读取并验证画布目录所有 JSON，包括回收站中的画布。任意坏文件、未来格式或文件名/ID 不一致先阻止迁移。
3. 把仍属于目标项目的画布逐个改归默认项目，保留节点、日志、连线、删除标记和原更新时间。
4. 全部画布写入完成后，才保存删除目标项目后的索引。

如果第二幅画布写入失败，已迁移的第一幅画布保留，目标项目仍存在；重试只处理剩余画布。如果最后项目索引写入失败，原项目索引保留，重试可以完成删除。这是原有可重试流程，不是新增加的跨文件原子事务。

`_project_canvases_for_move` 继续使用原有画布格式验证和原始文件扫描。没有复用会跳过坏文件、清理过期回收站的 `iter_canvas_records`，避免改变删除保护。
