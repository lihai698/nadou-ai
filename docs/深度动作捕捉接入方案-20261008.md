# 视频“深度动作捕捉”接入方案与实现记录

日期：2026-10-08。范围已按用户确认更新为“同时导出独立骨骼参考”；不包含后续付费模型的视频生成。

## 用户最终会看到什么

1. 普通画布的视频素材卡片、视频生成结果，以及智能画布的视频媒体卡片都有“编辑”入口。点击后打开沿用各自画布配色、图标、按钮和间距的视频编辑面板。现有图片编辑器保持原样。
2. 面板顶部先有“预览”和“深度动作捕捉”。视频区有原视频播放器和时间轴；处理页解释输入限制、运行设备、首次下载量、缓存状态及结果含义。用户尚未要求的视频剪辑和画面裁切不出现在本轮工具栏。
3. 点击“创建深度参考”后，源节点旁立即出现关联的结果占位节点。节点展示检查组件、下载、加载模型、分析、编码、保存等真实状态和进度，提供取消。失败保留原因和重试入口；关闭面板或重开画布后继续查询任务。
4. 成功后，源节点旁生成两个独立结果节点：灰度相对深度视频（近处偏白、远处偏黑）和骨骼姿态参考视频；另外保存逐帧 33 关节点 JSON。灰度深度视频不会画骨骼线，原视频保留。
5. 两路结果均可播放、下载和继续连接。JSON 使用 MediaPipe Pose 33 点格式，包含归一化坐标、深度坐标、可见度和时间戳；它不是 BVH/FBX。

## 如果目标是“模仿原视频”：深度与骨骼如何合用

可以从同一原视频同时提取两路信息，并用同一时间轴对齐：

```text
原视频 ──→ 灰度深度视频（人物、物体、空间及镜头变化）
      └──→ 人体姿态轨迹（关节位置、朝向和动作节奏）
                         ↓
          支持双路控制的视频生成模型 → 新视频
```

若用户已有独立骨骼数据，需先确认格式、骨架定义、帧率和起止时间，再与原视频对齐。骨骼数据应作为单独的结构化输入或姿态控制视频保存，不能直接画进灰度深度视频：画上关节线会改变原有深度值，普通视频模型也不会因此自动理解关节含义。

这种组合在**人体动作模仿**上可能比单独深度更精确；深度仍负责身体前后关系、场景空间和镜头变化。但改善效果取决于下游生成模型是否明确支持两种控制，并需要用实际样片比较，不能预先保证。若目标模型只接受普通参考视频，优先直接使用原视频做视频生视频。

当前项目的 `CanvasVideoRequest` 与普通、智能画布请求只有 `images`、`videos`、`audios` 等媒体输入。本轮只产出两路参考素材，不把它们自动塞入生成请求，也不宣称任意付费模型会自动使用双路控制。用户后续手动选择模型，并按模型的真实输入合同上传所需文件。

2026-10-08 现场核对：项目内没有已接入的 OpenPose/DWPose/深度双路视频生成工作流，默认 ComfyUI 端口 `8188` 当前未监听。现有视频节点能传普通参考视频，但这不等于所选模型会把灰度深度和骨骼当作控制条件。面向“复制视频”的下一步应先用一段 2～5 秒隔离样片确认目标是“换人物且保留动作”还是“连镜头和场景一起模仿”，再选与之匹配、能在 RTX 4090 24 GB 上运行的本地视频生成工作流，并核对其真实输入字段和许可证。只有端到端样片证明双路有效后，才把骨骼输入和一键生成接入正式画布。

简化界面结构：

```text
视频节点 [编辑] → ┌ 编辑视频 ── [预览] [深度动作捕捉] ── 关闭 ┐
                 │ 原视频播放器 / 处理后播放器（成功后可对照） │
                 │ 时长、分辨率、设备、下载与缓存说明           │
                 │ 阶段、进度、错误与恢复说明                 │
                 └ 取消任务 / 关闭 / 创建深度参考或重新生成 ┘
                      ↓
                 原视频节点 ──→ 灰度深度节点 + 骨骼节点 + 关节 JSON
```

## 设备策略

当前借用电脑：GTX 1070，8 GB 显存，CUDA 计算能力 6.1；i7-6820HK，16 GB 内存。目标电脑：RTX 4090，24 GB 显存，64 GB 内存。当前机器的新版 CUDA 运行包兼容性未验证；不应仅检测到 NVIDIA 就先下载约 3.45 GB。当前机优先 CPU 并实测 2 秒、15 秒样片的耗时和内存。目标机先用已校验组件执行真实 Small 模型 CUDA 探针，通过后使用 GPU；设备故障才允许同一任务回退 CPU 一次，素材损坏和取消不得触发回退。

Windows CPU 组件约 818 MiB、Small 权重约 111 MiB；CUDA 组件约 3.45 GiB，解压和临时文件需要更多空间。下载、校验、安装只在第一次或缓存损坏/版本更换时发生；每个新视频仍会重新推理。缓存可迁移到目标电脑，但必须重新校验哈希和运行兼容性，不默认认为复制后即可用。

## 实施与验收顺序

1. 先固定视频素材、生成结果、普通/智能节点、保存、复制导入的真实数据入口，建立隔离样例画布，不改用户当前画布。
2. 完成本地运行组件的可信下载、缓存、取消、探测、任务持久化和结果验证；失败时保留原视频与可读错误。
3. 接入两种画布的视频编辑入口、顶部工具栏、任务占位与结果节点。普通画布的视频生成节点与视频结果节点都能通过结果卡片进入。
4. 用模拟运行组件验证下载中断、哈希错误、取消、失败、重试、刷新重开、复制导入和重复事件；再用短样片做本机真实 CPU 推理和横竖屏播放检查。真实 CUDA 效果须在 4090 机器上验证。
5. 提供真实界面截图及使用路径。用户手动确认成功后，按项目约定仅提交本功能源码、测试和说明，再同步个人 GitHub。

本地隔离样片已验证：深度 MP4、骨骼 MP4、33 点 JSON 的帧数和时长一致；普通画布和智能画布入口、占位节点、刷新恢复已实际检查。真实 CUDA 效果仍需在 RTX 4090 上验证；用户确认功能成功后才按项目约定提交和同步源码。
