# 阶段 11：生成与媒体任务状态边界审计

日期：2026-10-04  
范围：初始部分只读检查 `main.py` 中画布图片、ComfyUI、视频任务，以及普通画布和智能画布的提交、查询与展示；后续实施结果在文末单独记录。未读取私人配置或画布数据，未调用供应商。本文件是实施依据，**不代表阶段 11 已完成**。

## 已确认的现状

| 路径 | 后端状态与记录 | 两画布展示、重试和重启 |
| --- | --- | --- |
| 画布图片 `POST/GET /api/canvas-image-tasks` | `CANVAS_TASKS` 进程内缓存加 `data/canvas_tasks/canvas_img_*.json` 原子记录，初始 `queued`，工作协程改为 `running`，结果为 `succeeded` 或 `failed`；即梦另有 `jimeng_pending`。记录本地编号、类型、时间、供应商、模型、追踪号及结果/错误；失败时可有 `upstream_task_id`。持久记录只保存状态、结果和输入长度摘要，不保存原始提示词或引用正文；目前没有过期清理或取消接口。 | 两画布均保存已取得的本地任务编号。查询遇 408、429、5xx 或断线，最多再试 3 次原编号；持续失败保留编号和“查询暂停”，允许手动查询。明确失败不再当作查询故障；有上游编号时可走 `/api/image-task-query` 恢复查询。服务重启后读取旧的 `queued/running` 记录会返回 `unknown`，不自动重新提交；普通画布保留失效卡片，智能画布显示任务失效提示。 |
| ComfyUI `POST/GET /api/canvas-comfy-tasks` | 同一 `CANVAS_TASKS` 缓存加 `data/canvas_tasks/canvas_comfy_*.json` 原子记录，`queued → running → succeeded/failed`。工作协程在后台线程调用 `generate`；持久记录保存状态、结果/错误和工作流长度摘要，不保存工作流正文。`generate` 另维护旧的 `QUEUE`/`/api/queue_status` 排位，这不是同一任务状态表。无取消接口。 | 两画布对临时查询失败只重试原编号，服务重启后 `unknown` 和明确失败终止查询，不会重新 POST 工作流。普通画布保留不可重试的失效卡片，智能画布保留“任务已失效”提示。 |
| 视频 `POST /api/canvas-video` | 接口在同一个请求内调用供应商并等待结果；有远端编号时在请求内轮询，成功后返回 `videos`、`task_id`。没有本地视频任务表、提交后查询路由或本地取消接口。上游失败/取消/超时状态在供应商适配层主要归为请求错误，未形成统一的任务 `cancelled` 状态。即梦可返回待查询信号，由智能画布保存 `submitId` 并查询 `/api/jimeng/query-media`。 | 普通画布用临时 `_pending` 展示同步请求，错误后清除；智能画布在 POST 前保存“可能已受理、再次提交可能重复计费”警告，网络异常、408、5xx 或空结果时保留，明确拒绝或取得视频后清除。警告可在刷新后看见，但没有远端编号时无法查回视频结果。 |

图片与 ComfyUI 已有同一格式的本地任务记录，但视频仍只有稳定编号和受理记录，尚未统一到这套查询协议。服务重启后图片与 ComfyUI 的 `queued/running` 记录会明确变成 `unknown`，不会伪装成成功或自动重提。视频即使远端已受理，只要同步 HTTP 响应中断，也可能没有可恢复的本地编号。上游结果字段还使用 `SUCCESS`、`FAILED`、`CANCELLED` 等各平台写法；本地图片/ComfyUI 对外只返回小写状态，即梦额外返回 `jimeng_pending`。

## 取消、重试和“状态未知”的含义

| 操作或故障 | 当前能确认的行为 | 不能据此声称 |
| --- | --- | --- |
| 普通画布“停止一键运行” | `AbortController` 中止该页面的请求/等待，后续链路停止；已取得编号的图片任务可保留待查询卡片。 | 后端协程或远端供应商任务已取消。 |
| 智能画布“停止运行” | 设置 `stopRequested`，当前任务完成后不启动下一轮；并行轮次停止领取新任务。 | 当前已提交的远端任务已取消。 |
| 查询暂时失败 | 图片和 ComfyUI 只重查原编号；图片可保留待查询记录。 | 生成失败，或重试 POST 一定安全。 |
| 提交响应丢失 | 图片批次将未拿到编号的请求标为“可能已受理”；智能视频预先保存未知状态警告。 | 远端明确拒绝或可以无成本重提。 |
| 本地任务 404 | 两画布将本地编号失效解释为重启/过期边界，图片不会自动重新提交。 | 远端一定停止，或一定还在运行。 |

`main.py` 的两个本地任务路由目前只有 POST 创建和 GET 查询，没有 DELETE/取消路由；页面的“停止”因此只是停止本地链路或等待。后续若增加 `cancelled`，必须由能确认的后端或供应商事件产生，不能由浏览器中止请求直接赋值。

## 最小且可独立验证的实施候选

先从两个本地后台任务的**状态流转规则**入手：新增无 I/O 的 `backend/task_states.py`，只接收当前状态、事件、结果或错误，返回更新字段；由 `run_canvas_image_task`、`run_canvas_comfy_task` 的真实入口调用，删除原先两套重复的 `queued/running/succeeded/failed` 字段更新。规则只允许 `queued → running → succeeded/failed`，并显式保留即梦 `jimeng_pending` 作为待远端查询状态；查询故障、浏览器停止与未收到提交响应均不得伪装成 `failed` 或 `cancelled`。保留现有 API 字段与追踪号。

用纯规则单元测试和现有图片/ComfyUI 生命周期、重启测试验证：成功与失败不可互相覆盖，结果只在成功状态出现，失败保存原因及可恢复编号，GET 只读不再次提交，404 仍如实解释本地记录丢失。此拆分不需要真实供应商，也不触碰私人数据；通过后再逐步设计持久记录、视频异步编号/查询、确认过的取消能力和并发限制。视频不能仅套用本地状态表就宣称可恢复，须先取得稳定的远端编号和查询协议。

## 2026-10-04 局部实施结果

上述最小拆分已实施：新增 `backend/task_states.py`，纯函数 `task_state_update` 只接受当前记录、目标状态、时间戳和必要结果字段，校验 `queued → running → succeeded/failed/jimeng_pending`；终态不可被后续状态覆盖，浏览器停止不能据此写成 `cancelled`。`main.py` 图片与 ComfyUI 的真实后台 worker 已调用这条规则，原先两套 `running/succeeded/failed` 字段赋值及图片专有的 `jimeng_pending` 赋值已清理。任务创建、GET 接口、字段名、追踪号和即梦远端续查字段保持原样。

验证：`tests/test_task_states.py` 纯规则 3 项、`tests/test_canvas_task_lifecycle.py` 图片真实接口 6 项（新增即梦待查询回归）、`tests/test_canvas_comfy_lifecycle.py` ComfyUI 真实接口 2 项、`tests/test_canvas_restart_boundary.py` 跨进程重启 3 项，均通过；相关 Python 语法检查和差异空白检查通过。测试使用模拟生成，不调用供应商；未检查私人文件内容。视频、前端展示、持久化、取消、远端查询协议和并发限制仍按上文记录为后续工作，阶段 11 不能据此勾选完成。

## 2026-10-04 ComfyUI 编号刷新续查

普通画布的 ComfyUI、MiniMax ComfyUI 和 LTX Director 入口，拿到本地 `task_id` 后把编号写入结果卡片的 `_pending`，先保存画布，再查询结果。保存失败时保留编号，暂停查询并显示“保存并查询”；同浏览器的未保存编号也会沿用现有本地备份。智能画布的普通 ComfyUI、链路/循环和 MiniMax ComfyUI 入口把编号放进节点 `pendingTasks`，先保存再查询；保存失败保留当前页面的编号和手动查询入口。刷新后两个编辑器都只向 `/api/canvas-comfy-tasks/{task_id}` 发 GET，不重新 POST 工作流。

短时 408、429、5xx 或断线仍限次重查原编号；持续故障保留任务和查询按钮。404 解释为**本地任务记录已失效，可能服务重启或任务过期；远端状态未知**，不声称远端取消，也不自动重提。普通画布保留不可再查的失效卡片，智能画布保留原有“任务已失效”提示。停止页面等待只停止本地链路，已保存的编号仍可查询。正常成功路径继续使用原结果处理和节点显示；刷新续查的 ComfyUI 结果写回原结果节点，智能 MiniMax 写回原片段。

验证：新增 `tests/canvas_comfy_resume.test.cjs` 7 项，覆盖两画布受理编号落盘、刷新同编号 GET、404、保存失败和普通画布停止等待；连同原有 ComfyUI 与图片任务回归共 43 项 JavaScript 通过。`tests/test_canvas_comfy_lifecycle.py` 真实路由模拟 2 项和 `tests/test_canvas_restart_boundary.py` 跨进程 3 项通过；两份画布脚本语法及差异空白检查通过。3023 公开文件隔离预览加载两份更新脚本；自制普通、智能画布各保存一个不存在的本地 ComfyUI 编号，页面实际 GET 后分别显示“本地任务记录已失效”和“任务已失效”，普通画布刷新后提示仍在，两页控制台无错误。测试未连接真实 ComfyUI。智能画布在服务器保存失败、浏览器也立即关闭时仍缺本地编号备份；进程重启后后端任务表丢失，404 无法恢复远端结果。普通画布“增强后再放大”的两步工作流若恰好在步骤间刷新，续查可取回已完成步骤的结果，但不会自动补发第二步。阶段 11 仍未完成。

## 2026-10-04 图片与 ComfyUI 任务记录补强

新增 `backend/task_records.py`，集中处理任务编号路径校验、原子 JSON 读写和进程重启边界。图片与 ComfyUI 提交时先写入 `data/canvas_tasks`，记录失败会返回 503，且不会启动上游 worker；worker 的运行、成功、即梦待查询和失败状态会持续更新同一记录。任务记录只保留结果、错误、追踪号和 `prompt_length`/`workflow_length` 等摘要，不保存原始提示词、工作流正文或进程编号以外的提交参数。内存缓存丢失时 GET 会从记录恢复；其他进程留下的 `queued/running` 会原子标记为 `unknown`，对外提示“远端状态未知，请勿直接重复提交”。损坏记录返回受控 500，不把 JSON 内容回显给客户端。

普通画布和智能画布的图片、ComfyUI 查询都识别 `unknown`：停止轮询、保留任务失效提示并禁止自动再次提交。临时 408、429、5xx 和断线仍只重查原编号，且保留原有暂停恢复路径。隔离验证覆盖 10 项任务记录规则、8 项图片生命周期、2 项 ComfyUI 生命周期、3 项跨进程重启边界，以及 51 项相关 JavaScript 轮询回归；未连接真实供应商，未实现远端查询、取消、过期清理或多进程协调。阶段 11 仍未完成。
