# 阶段 14：长期维护检查表

## 每次修改后

在项目解释器中运行：

```powershell
python\python.exe tools\check-core.py
python\python.exe tools\prepare-release.py --preflight
python\python.exe tools\check-environment.py --config-root . --min-free-bytes 1073741824
python\python.exe -m compileall -q main.py backend tests
git diff --check
```

这些命令只检查源码、临时测试数据和发布清单；环境检查不会打印密钥值。`--min-free-bytes` 可以按部署空间调整，设为 `0` 时关闭磁盘门禁。

## 涉及数据前

1. 停止服务和后台任务，确认浏览器没有未保存编辑。
2. 使用 `tools/backup-restore.py create` 创建到私有备份盘的新目录。
3. 运行 `verify`，再用 `tools/check-data-formats.py --root <恢复副本> --all-json` 检查格式和原子临时文件。
4. 只在新的恢复目录和独立端口验证升级；确认页面、项目、画布、素材索引和任务状态后再切换。
5. 保留旧代码恢复点和旧快照，确认新程序没有把未来版本数据降级写回。

如需在不触碰正式目录的情况下复核程序更新边界，可另外准备隔离旧版本目录和候选
更新目录，运行[升级与中断恢复隔离演练](阶段14升级恢复隔离演练-20261004.md)：

```powershell
python\python.exe tools\verify-upgrade-recovery.py `
  --source <隔离旧版本目录> `
  --candidate <隔离更新目录> `
  --workspace <不存在的验收工作目录> `
  --expected-version <候选版本>
```

该命令只在新工作目录写入，验证私人文件保留、升级前快照回退和一次模拟中断恢复；
它不能代替真实用户数据、断电和跨平台升级验收。

## 发布前

- `prepare-release.py --preflight` 通过后再生成发布目录；发布目录必须含 `RELEASE_FILES.json`，不包含 `data/`、`assets/`、`.env` 和历史内容。
- 保持发布目录原样，用 `tools/verify-release-startup.py <release-dir> --python <已装依赖的项目Python>` 在临时沙盒启动根页和 `static/index.html`；另从 ZIP 隔离解压并运行 `安装依赖.bat` 验证首次安装。不要在发布目录安装依赖，否则会产生清单外文件。
- 当前版本更新模式是 `full_install`；上游更新必须先比较并验证，不自动覆盖本地二次开发。

## 任务记录维护

图片和 ComfyUI 任务记录默认不会在启动时自动删除。需要清理时先生成只读计划，
确认编号和数量后，再显式应用同一份计划：

```powershell
python\python.exe tools\cleanup-task-records.py `
  --write-plan output\task-cleanup-plan.json
python\python.exe tools\cleanup-task-records.py `
  --apply-plan output\task-cleanup-plan.json
```

计划只包含已确认结束且超过保留期的记录；排队中、运行中、远端状态未知、即梦
待查询和视频任务不会进入候选。应用时会重新核对文件指纹，记录发生变化就停止，
删除过程中出现故障会使用临时恢复副本回滚。计划文件包含任务编号和文件指纹，
应在清理完成后按需删除，不要提交到公开仓库。

## 已知未验证项

真实供应商联调、macOS 实机安装、旧版本二进制跨版本运行、长时间高负载、磁盘写满后的现场恢复、多个服务进程的全局队列、自动后台清理和外部 CLI 登录会话仍需独立维护窗口验证。它们不能由本地单元测试或公开包预检替代。
