# 任务记录与图片执行模块迁移验收

2026-10-18。继续完整职责迁移主线。本轮将共享画布任务记录策略和图片任务执行生命周期移入 `backend/canvas_task_service.py`，不重新实现底层任务文件库或并发闸门。

## 归属与迁出结果

| 模块 | 职责 |
| --- | --- |
| task_records（已有） | 任务JSON校验、目录锁、原子读写、格式及错误合同 |
| task_states（已有） | 状态转换的纯规则 |
| task_concurrency（已有） | 当前进程的并发限制及计数 |
| comfy_task_service（已有） | ComfyUI worker原有执行流程 |
| canvas_task_service（新增） | 持久字段白名单/结果筛选、写失败策略、同进程缓存恢复、启动失败、重启unknown、公开字段筛选、上游编号批次跟踪、图片任务门控和worker完整状态流程 |
| main | HTTP请求/响应、助手提交前校验、供应商生成实现、共享缓存和锁的装配；通过明确回调连接新服务 |

新模块有14个函数、380行。main.py 本轮23,318→23,016行，净减少302行。迁出的业务算法及两份字段白名单已删除旧副本；6个纯规则通过导入别名服务既有调用方，8个适配函数只负责传入缓存、锁、进程编号、生成和读写回调。

不复制运行缓存或新建第二个队列。CANVAS_TASKS 仍由应用持有、传给服务；提交路由构造初始任务，服务处理本轮迁出的恢复/执行/记录规则。主程序 `_read_canvas_task_record` 保留既有HTTP异常转换。没有反向导入main、读取应用私有全局变量或引入新依赖。

## 保持的行为

- 原记录字段白名单、结果字段筛选和用量整理保持，不把提示词/工作流正文新增到磁盘。
- required写失败仍抛TaskRecordError，普通写失败仍记录诊断并返回False；错误不回显任务正文。
- worker缺缓存时只恢复同进程记录，其他进程的未完成记录仍通过查询入口保守转unknown。
- 运行态必须先落盘才能调用生成；生成成功后最终记录写失败不能把内存成功状态改成失败。
- 上游任务编号必须立即保存，失败异常保留原编号及接受状态标记；批量一部分已受理时进入unknown，不重提整批。
- 图片的ContextVar回调在成功和异常路径都恢复；即梦排队、普通失败与批量未知状态分支保持。
- 音频和ComfyUI继续原执行策略，仅通过已有适配函数使用迁出的共享记录策略。
