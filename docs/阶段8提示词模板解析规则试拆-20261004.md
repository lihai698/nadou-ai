# 阶段 8：提示词模板解析规则试拆

日期：2026-10-04

## 目标与范围

把内置提示词模板 Markdown 的分类、区块提取和字段解析规则从 `main.py` 移到
`backend/prompt_templates.py`，保留智能画布提示词模板接口的字段、筛选和错误
回退行为。本次只拆无状态解析规则，不改变模板文件内容、提示词库保存格式或
前端调用协议。

## 职责与数据归属

| 模块 | 负责 | 不负责 | 数据所有权 |
| --- | --- | --- | --- |
| `backend/prompt_templates.py` | 解析调用方传入的 Markdown、提取模板区块、分类、应用调用方传入的英文翻译映射 | 定位/读取模板文件、修改模板、访问配置、FastAPI 响应和提示词库写入 | 不拥有持久数据，只返回新建的 Python 字典 |
| `main.py` | 选择模板路径、读取文件、传入 `PROMPT_TEMPLATE_EN`、公开 `builtin_prompt_templates` 和 HTTP 路由 | 不再实现 Markdown 正则解析规则 | 拥有静态模板路径、翻译映射和路由错误回退 |

模块不会反向导入 `main.py`，也不读取其他模块的私有状态。入口通过显式参数传递
翻译映射；`main.py` 中保留的 `parse_prompt_template_markdown` 只是兼容旧调用方
的薄包装，实际解析由后端模块完成。

## 允许依赖与入口

- `backend/prompt_templates.py` 仅依赖 Python 标准库 `re` 和 `typing`。
- `main.py` 的 `builtin_prompt_templates()` 和
  `GET /api/smart-canvas/prompt-templates` 是真实入口。
- 模板路径、文件读取、诊断日志和 HTTP 错误边界仍由 `main.py` 组织；解析模块不
  进行文件或网络操作。

## 验证

- `tests/test_prompt_templates.py`：5 项通过，覆盖分类、代码围栏、参数解析、缺少
  正向提示词过滤、翻译映射、无 `main.py` 依赖，以及真实智能画布 HTTP 路由。
- `python\\python.exe -m py_compile backend/prompt_templates.py main.py` 通过。
- 使用仓库内静态模板读取验证，解析出 10 条内置模板；未读取私人配置、对话、画布
  或素材，未调用供应商。
- `git diff --check` 通过。

## 恢复与限制

恢复时删除新模块和专项测试、文档，并恢复 `main.py` 中原解析函数体及其导入；本次
没有改动用户数据。阶段 8 仍只完成局部拆分，提示词库持久化、画布保存、任务调度
等职责边界仍需后续按路线继续验证。
