# 创作助手引入方案

**项目：** Infinite-Canvas（`D:\daxiong`）
**参考项目：** BeefTV（`D:\beeftv`）
**方案日期：** 2026-10-08
**方案状态：** 阶段 B 已完成并获用户验收确认，开始阶段 C 画布操作
**适用范围：** 普通画布、智能画布

## 1. 结论

BeefTV 的“创作助手”值得引入。它的主要价值不是右侧聊天面板，而是把自然语言、画布结构修改、生成提议、用户确认、任务执行和撤销串成了一个完整流程。

本项目不能直接复制 BeefTV 的 React、Go 或 Agent Host。当前项目是原生 HTML、JavaScript、FastAPI，普通画布和智能画布的数据结构也不同。正确做法是：

1. 保留参考项目的业务规则；
2. 使用当前项目的节点、保存、模型和任务入口；
3. 普通画布和智能画布分别适配；
4. 界面沿用当前画布的主题、按钮、面板和交互习惯；
5. 生成任务仍然必须由用户确认后提交。

第一版建议实现完整的画布助手闭环：对话、选中节点、素材引用、创建节点、修改提示词、连线、生成提议、用户确认、整轮撤销、历史恢复和错误恢复。

创作首页转入画布、跨画布搜索、复杂分镜表、角色卡、插件宿主和自动付费生成列为后续阶段，不与第一版混合。

## 2. 参考项目的真实功能

### 2.1 界面功能

参考项目右侧面板包含：

- “创作助手”标题和当前画布名称；
- 新建对话；
- 历史对话；
- 关闭助手；
- 当前画布标签；
- 已选节点数量；
- `@` 引用素材；
- 对话流式回复；
- 停止当前回合；
- 助手改动摘要；
- “在画布上查看”；
- “撤销这一轮”；
- 图片或视频生成提议；
- “生成”和“先不用”；
- 助手模型选择器。

侧栏本身不直接修改节点。它只显示状态，真正的修改由后端受控操作层完成。

### 2.2 一轮对话的运行顺序

```text
用户输入要求
  ↓
冻结当前画布、选中节点和引用素材
  ↓
后端验证用户、画布和素材归属
  ↓
助手读取画布并决定操作
  ↓
受控操作层执行创建、修改和连线
  ↓
记录操作回执和回合变更摘要
  ↓
返回文本回复和可选的生成提议
  ↓
用户确认生成
  ↓
再次核对画布、模型、提示词和素材
  ↓
调用画布原有生成流程
```

只有收到完整的 `turn_end` 事件，参考项目才把这一轮视为结束。断流、损坏的流式 JSON 或只有半段回复，都不能当成成功。

### 2.3 受控画布操作

参考项目给助手暴露的核心操作包括：

| 操作 | 作用 | 是否修改画布 |
|---|---|---:|
| `canvas.get` | 读取画布、节点和连线 | 否 |
| `canvas.search` | 搜索工作区画布 | 否，第一版暂缓跨画布使用 |
| `asset.get` | 读取已授权素材 | 否 |
| `task.get` | 查询与当前画布有关的任务 | 否 |
| `canvas.nodes.create` | 批量创建节点 | 是 |
| `canvas.node.update` | 局部修改标题、正文或可编辑提示词 | 是 |
| `canvas.edge.create` | 创建节点连线 | 是 |
| `canvas.generation.propose` | 提出图片或视频生成方案 | 否，不生成、不扣费 |
| `canvas.task.bind` | 将已完成任务绑定回节点 | 是，第一版优先复用现有前端任务回填 |

每个写操作都带画布版本检查和操作编号。重复调用同一操作编号时返回原结果，避免模型重试造成重复节点或重复连线。

### 2.4 回合变更摘要

每个助手回合记录：

- `revisionBefore`；
- `revisionAfter`；
- `createdNodeIds`；
- `updatedNodeIds`；
- `createdEdgeIds`；
- `operationIds`；
- 回合前的画布快照；
- 用户消息、选中节点和引用素材。

界面将它转换成用户能看懂的文字，例如：

```text
新建 3 个节点，修改 1 个节点，连了 2 条线
```

### 2.5 生成提议和费用确认

参考项目把“规划生成”和“真正生成”分开：

第一步，助手可以创建节点、写入提示词和连线，并提出生成提议。
第二步，用户点击“生成”后，页面才提交图片或视频任务。

提议卡片会显示：

- 生成类型；
- 节点数量；
- 用户当前选择的模型；
- 可能的价格信息；
- “确认后开始，按所选渠道计费”。

助手不能自行声称已经生成、已经扣费或已经得到结果。

### 2.6 整轮撤销

参考项目不是简单减少版本号，而是：

1. 保存本轮前的画布快照；
2. 用户点击撤销时检查画布是否被其他操作修改；
3. 用新的版本写回本轮前内容；
4. 标记该回合已撤销；
5. 保留回合身份和历史记录。

如果画布在助手回合之后又被修改，撤销必须拒绝，并提示“这之后画布又改过，不能直接撤销”。

## 4. 采用的总体架构

第一版不引入 BeefTV 的 Node Agent Host，也不复制 Go 后端。采用当前项目的 Python 和原生 JavaScript：

```text
右侧助手面板
  ↓
canvas-assistant 前端状态模块
  ↓
FastAPI 助手会话接口
  ↓
当前 /api/canvas-llm
  ↓
结构化助手操作解析与校验
  ↓
普通画布适配器 / 智能画布适配器
  ↓
现有画布保存和任务接口
```

模型返回的内容先解析成受限操作，再由后端校验和执行。模型不能直接提交整份画布 JSON，也不能自行扩大素材、任务或跨画布访问范围。

## 5. 首版功能范围

### 5.1 对话与会话

首版包括：

- 新建对话；
- 当前画布历史对话；
- 刷新页面后恢复历史；
- 当前画布绑定；
- 发送时冻结画布 ID；
- 发送时冻结选中的节点；
- 停止当前助手回合；
- 回合失败后的重试；
- 切换画布后旧回调不能写入新画布。

首版不支持助手直接修改其他画布。

### 5.2 选中节点和素材引用

发送消息时附带：

```json
{
  "canvasId": "当前画布 ID",
  "message": "用户要求",
  "selectedNodeIds": ["选中的节点 ID"],
  "references": [
    {"kind": "asset", "id": "已验证的素材 ID"}
  ],
  "sessionId": "当前对话 ID"
}
```

后端重新验证所有引用的归属。用户在文字中提到某个素材，不等于模型自动获得该素材的权限。

### 5.3 普通画布适配

普通画布建议使用以下原生节点组合：

| 用户意图 | 创建或修改的节点 | 关系 |
|---|---|---|
| 生成图片 | `prompt` + `generator` | `prompt → generator` |
| 图片继续生成视频 | `prompt` + `generator` + `video` | `prompt → generator → video` |
| 使用已有图片做参考 | `image` 或已有素材节点 + `generator` | 图片节点连接到生成节点 |
| 修改已有提示词 | 当前 `prompt` 节点 | 只修改 `text` |

参考项目可能只显示“两个节点、一条线”，但普通画布需要提示词节点才能让现有生成器真正读取提示词。因此本项目优先保证真实可运行的数据关系，摘要数量按照实际节点计算。

### 5.4 智能画布适配

智能画布建议使用以下原生节点组合：

| 用户意图 | 创建或修改的节点 | 必须同步的字段 |
|---|---|---|
| 图片创作 | `smart-prompt` + `smart-loop` | `showPrompt`、`inputNodeIds`、`connections` |
| 参考图创作 | `smart-image` + `smart-loop` | 图片输入关系、连接类型、提示词草稿 |
| 视频创作 | `smart-prompt` + 当前适配的视频工作节点 | `runSettings`、视频模型、时长、比例、素材输入 |
| 生成结果 | 用户确认后创建 `smart-image` 输出节点 | 任务状态、运行提示词、结果引用 |

助手不能假定所有视频模型都使用同一个节点。模型和供应商仍由本项目配置及用户当前选择决定。


`chat` 使用 NDJSON 响应。即使当前模型渠道不支持真正逐字流，也要保持完整协议：

```text

```

没有 `turn_end` 时，前端必须显示“回复没有完整结束”，不能把半段内容当作成功。

## 7. 受控操作协议

### 7.1 操作参数

每个操作至少包含：

```json
{
  "operationId": "本轮唯一操作 ID",
  "canvasId": "当前画布 ID",
  "expectedUpdatedAt": 0,
  "params": {}
}
```

当前项目使用 `updated_at` 和已有保存冲突保护，因此第一版可以把它作为画布版本依据，同时保存规范化文档哈希。后续如果画布版本字段统一，再迁移到显式整数 revision。

### 7.2 节点创建

节点创建只接受有限字段：

```text
title
type
prompt 或 content
```

具体默认字段由普通画布和智能画布适配器补齐。模型不能提交任意运行状态、任务状态、结果 URL 或未知元数据。

### 7.3 节点修改

第一版允许修改：

- 节点标题；
- 普通文本节点正文；
- 普通提示词节点文本；
- 智能提示词节点草稿；
- 图片或视频节点的下一次生成提示词。

已经提交的任务提示词、结果 URL、任务编号和恢复字段不能由助手随意覆盖。

### 7.4 连线

连线操作必须校验：

- 两个节点存在；
- 两个节点属于当前画布；
- 节点类型允许连接；
- 不能连接自身；
- 重复连接幂等返回；
- 智能画布同步 `inputNodeIds` 和连接类型。

## 8. 生成提议和用户确认

助手可以调用 `canvas.generation.propose`，但该操作只返回提议：

```json
{
  "proposalId": "唯一提议 ID",
  "kind": "image 或 video",
  "nodeIds": ["目标节点"],
  "model": "显示名称",
  "modelKey": "实际模型 ID",
  "source": {
    "canvasId": "画布 ID",
    "canvasUpdatedAt": 0,
    "canvasContentHash": "内容哈希",
    "modelConfigHash": "模型配置哈希"
  }
}
```

用户点击“生成”时，必须重新读取当前保存内容并核对：

1. 画布 ID 没有变化；
2. 画布更新时间和内容哈希仍匹配；
3. 模型配置仍匹配；
4. 目标节点仍存在；
5. 提示词仍是用户确认的版本；
6. 素材仍存在；
7. 提议没有被处理过；
8. 当前页面仍拥有该画布。

任何一项不匹配，都提示“画布内容或生成设置已变化，请保存修改后重新提出生成方案”。

生成按钮只调用当前画布已有的生成函数。助手模型不会覆盖用户已经选择的图片、视频、供应商或模型配置。

## 9. 回合存储和撤销

首版使用当前项目的原子 JSON、目录锁和原有画布保存锁，不新增数据库。每个回合保存：

```text
turnId
userId
canvasId
sessionId
userText
selectedNodeIds
referencedAssetIds
createdAt
state
revisionBefore 或 updatedAtBefore
documentBefore
change
undone
```

### 撤销条件

- 只允许撤销已经结束的助手回合；
- 回合没有画布改动时不显示撤销按钮；
- 当前画布仍与回合结束状态匹配时允许撤销；
- 画布之后被修改时拒绝撤销；
- 撤销用新保存版本写回旧内容，不倒退时间戳；
- 撤销后保留回合记录和“已撤销”标记。

### 生成后的处理

助手生成提议和真正生成分开，因此正常情况下撤销发生在生成之前。如果任务已经提交：

- 不自动取消供应商任务；
- 不擅自删除任务结果；
- 不把“无法撤销任务”伪装成“整轮已撤销”；
- 提示用户任务仍可在任务和结果区域查看。

## 10. 错误和恢复

需要覆盖以下状态：

| 状态 | 用户提示 | 处理规则 |
|---|---|---|
| 助手未配置 | 创作助手暂时不可用 | 提供模型配置入口 |
| 模型调用失败 | 这一轮没有完成 | 保留已落地画布改动 |
| 流式回复中断 | 回复没有完整结束 | 不当作成功，可重试 |
| 写入版本冲突 | 画布刚刚被修改 | 重新读取后再继续 |
| 目标节点被删除 | 提议中的节点已变化 | 拒绝提交，重新提出 |
| 提议重复点击 | 已提交或正在提交 | 不重复发任务 |
| 任务编号未知 | 可能已经受理 | 禁止直接重新提交，优先查询原编号 |
| 保存失败 | 任务已受理但画布未保存 | 保留任务编号并提供保存/查询恢复 |
| 切换画布 | 画布或账号已切换 | 旧回调不能写入新画布 |
| 助手回合撤销冲突 | 这之后画布又改过 | 拒绝覆盖当前内容 |

这些规则与当前已有任务恢复、保存冲突和切换画布保护结合，不能重新建立另一套任务状态。

## 11. 界面方案

### 11.1 按钮位置

普通画布和智能画布都把“创作助手”按钮放在现有右上角快捷工具栏的固定区域，位于“日志”右侧：

```text
工作流   资产库   日志   创作助手
```

按钮使用：

- 现有 `.tool-btn` 样式；
- 现有主题变量；
- `sparkles` Lucide 图标；
- 现有圆角、边框、阴影和悬停状态；
- 窄屏时沿用工具栏已有的隐藏文字规则。

### 11.2 右侧助手面板

根据用户后续要求，采用小型悬浮窗口，替代固定停靠侧栏和窄屏覆盖抽屉：

- 位置沿用已展示的设置，不另行改为小地图上方；预览初始位于右下角。
- 默认约 300×360 像素，窄屏宽度自动限制在可用区域内。
- 拖住标题栏可自由移动，位置限制在可见画布区域内。
- 窗口保持可读尺寸，不随画布缩放一起变小。
- 可收起为小型助手按钮，再次点击恢复展开；双击标题栏回到原位置。
- 仅保留底部边缘拖动调节高度，最小 300 像素，最大不超过可用画布范围；用户明确不需要顶部铺满按钮，已从预览中删除该按钮及对应逻辑。
- 实际接入阶段验证与小地图及其他悬浮工具的遮挡关系，不擅自调整现有小地图位置。

面板不引入 BeefTV 的另一套设计系统，沿用当前画布的浅色、深色、字体、间距和按钮。

### 11.3 预览顺序

开始编码前，先根据当前普通画布和智能画布真实截图制作按钮、右侧面板和窄屏状态预览图。预览确认后再进入业务实现。
