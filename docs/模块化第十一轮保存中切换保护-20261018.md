# 第十一轮：保存中切换保护

2026-10-18。在普通画布已有 openCanvas 入口补齐切换前保存保护，复用既有 saveCanvas、Session、Scheduler 和草稿机制；不创建第二套保存流程。未改服务器接口、智能画布固定 URL 加载或原生返回工作台逻辑。

## 问题与修复

普通画布返回工作台已有等待保存逻辑，但同文档 openCanvas 原先直接开始加载另一画布。新增测试证明：dirty、保存中、计划保存或排队状态下都会直接发目标 GET，保存失败也不能阻止切换。当前工作台使用独立页面导航，这仍是同文档入口边界，不能夸大为已证明正常工作台点击一定丢数据。

现在：

- 有未保存状态时，先调用现有 saveCanvas；成功且没有剩余编辑才开始目标加载。等待时保留原画布和同步状态。
- 保存失败或仍有新编辑时提示并留在原画布。多个目标先后发起时，仍按第十轮的打开编号只接受最新目标。
- 目标 GET/touch 等待期间原画布仍可被编辑，因此应用目标前再次检查保存。此时失败会恢复原画布同步轮询。
- 重开同 ID 时，若等待期间已经自动保存成功，当前画布对象已被保存回包替换，即使 dirty 已清除，也重新读取目标；若第二次检查又执行保存，同样重新读取。避免把保存之前取到的旧快照重新显示为当前内容。

保留原有“保存成功会替换 canvas 对象”的契约。没有仅按时间戳不断重试，以免服务器旧版本恢复或时间戳差异导致无休止重取。

## 实际页面验收

临时服务仅复制公开代码并使用自制 A/B 画布。临时 HTML 中明确标注的按钮调用真实 openCanvas，生产页面无这些按钮。

1. A 输入第一份文字，让其 PUT 在服务端等待，确认磁盘仍为基线。
2. 请求打开 B，页面继续显示 A；等待期间再输入新文字。
3. 放行 PUT 后，最新文字先保存到 A，再显示 B。重开 A 和磁盘检查均确认最新文字，B 基线未变。
4. 让 A 保存返回 503，再输入文字并请求 B：页面仍为 A，显示保存失败和本机备份提示；磁盘没有这次失败文字。
5. 解除故障，再请求 B，保存成功后切换。移除临时按钮并刷新重开 A，文字完整保留；B 仍未被写入 A 内容。

证据在 `output/canvas-switch-save-20261018/`：`waiting-keeps-a.png`、`failed-save-keeps-a.png`、`a-reopened.png` 和 `result.json`。同 ID 与浏览器缓存分支使用自动测试覆盖，未作真实浏览器缓存命中声明。
