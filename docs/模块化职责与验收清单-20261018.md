## 本次第一项：画布存储完整边界

采用已有 ProjectStore 模式，路径、共享可重入锁、时钟、ID 工厂和原子写入器由 main 注入；不增加框架、不修改外部 HTTP 协议或数据格式。模块不得导入 main 或 FastAPI。

迁移：路径清理、格式保护、基础写入/带时间保存、新建、活动/含回收站读取、过期回收站清理、列表记录枚举、项目移动前画布校验、元数据读取/更新、touch、内容保存与版本冲突、软删除/恢复/永久删除。

保留边界：清空/日志删除的媒体协调、素材引用扫描、素材索引的旧宽松读取、备份恢复工具不并入本次存储类。这些是独立职责，不以本轮完成宣称所有目录读取已统一。素材索引目前与正式画布读取的格式校验不同，不能为迁移悄悄改变行为。

main 的兼容函数如 load_canvas/save_canvas 仍供大量现有调用方使用，但只委托新存储类并转换领域错误。移走的读写算法不得保留两份。待各应用服务调用方迁移后可移除兼容入口；本次不为追求删除名称而改遍无关调用方。

## 验收与停止条件

- 存储合同：ID处理、旧/当前/未来格式、回收站可见性、字段保留、时间单调、写入失败不破坏文件。
- 业务合同：元数据不改变 updated_at，title/icon 的 meta_revision 规则不变；内容保存的两类409与视口/日志规则不变。
- 真实路由委托检查和既有并发测试；测试故障注入点随迁移调整，原断言不删。
- 两类画布新建、保存/重开、标题、归属、回收站/恢复按风险在自制数据验证。
- 完整核心、发布预检、知识来源摘要、重复实现搜索和独立审查。
