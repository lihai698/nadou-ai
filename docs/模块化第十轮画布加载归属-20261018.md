# 第十轮：普通画布加载请求归属

2026-10-18，继续第九轮的异步生命周期核对。本轮只修复普通画布 openCanvas 的重复调用竞态，未新建模块、改写合并算法或引入依赖；此前未提交修改完整保留。

## 复现范围

在同一个编辑器文档内先 openCanvas(A)、再 openCanvas(B)，控制响应顺序：旧实现会让晚到的 A 覆盖 B；A 的晚到失败还会使 B 跳回列表。旧 touch、草稿准备和素材检查续体也可能更新当前状态。最初 10 项测试中，9 项复现失败，最新请求的正常错误处理 1 项通过。

当前工作台选画布已经位于独立页面，普通编辑器经 URL 的 id 加载。上述结果证明同文档加载入口的竞态，不等于已经证明正常工作台双击就会丢失数据。保留的列表打开入口及其他重复调用仍应遵循“最后一次打开有效”。

## 修复

- 每次打开增加请求编号。GET、JSON 解码、touch、草稿准备、素材检查结束后，以及错误处理前，均检查是否仍是当前请求。
- 获取的数据先保存在本次调用中，touch 返回并确认有效后再赋给当前画布，防止旧 touch 修改新画布时间戳或触发旧智能画布跳转。
- pagehide 使未完成请求失效；如果浏览器以 persisted=true 恢复一个尚未完成的打开流程，重新打开记录的目标。
- 删除正在打开的目标时取消该次加载，避免回包后又把它打开；删除其他画布不取消最新目标。
- 素材检查绑定启动时的画布对象和打开编号，旧结果不能加入新画布的缺失素材集合。
- 独立审查发现真实 touchCanvasOpened 内部仍会先更新列表。补充真实 helper 回归测试，观察失败后把有效性判断移到列表更新之前。正常 touch 更新列表仍保留。

正在进行的网络请求不强制中止，过期回包失去修改当前编辑器的资格。已经发送的 touch 仍可能在服务端记录该画布被打开，不回滚这一服务器操作。草稿的存储和合并规则未改动。

## 页面验收

使用公开代码和自制 A/B 画布的隔离服务。在临时 HTML 中增加两个明确标注的验收按钮，调用真实 openCanvas；生产 HTML 没有这些按钮。服务端只让 A 的 GET 等待，确认请求确实进入等待后打开 B，随后放行 A。

实际结果：A 回包后页面仍显示 B；编辑 B 后，隔离磁盘确认只有 B 内容变化，A 原内容保持；移除临时验收控件后，通过原生返回工作台和卡片打开 B，保存文字仍在。
