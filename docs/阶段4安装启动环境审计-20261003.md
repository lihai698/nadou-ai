## 启动与数据边界

- Windows 正式入口是 `run.bat`，执行 `main.py`，默认端口 3000。2026-10-04 已将 `main.py` 默认绑定地址收紧为 `127.0.0.1`；只有显式设置 `NADOU_BIND_HOST` 才会监听其他地址。局域网访问仍缺完整鉴权，端口占用提示按现有启动检查处理。
- `run.bat` 在服务启动前安排 3 秒后打开浏览器，没有检查 Python 缺失、依赖缺失或端口是否已经占用。当前也没有独立的环境检查入口或停止脚本；正常停止提示为 Ctrl+C。
- `main.py` 导入时会创建数据、素材、输出等目录；启动生命周期还会同步静态 HTML 版本并执行素材整理迁移。因此后续启动验收应继续使用独立目录和端口，不能在当前用户数据目录随意演练失败场景。
- `.gitignore` 排除多数私人目录，但 `git ls-files` 显示 `API/.env` 和 `data/asset_library.json` 仍被 Git 跟踪。忽略规则不能保护已跟踪文件；程序文件与用户文件分离、升级不覆盖私人数据的验收尚未完成。本记录不读取或展示密钥内容。
- `mac-安装依赖.sh` 也依赖同一个离线包目录，但目前只有 Windows wheel；macOS 的离线安装未验证。仓库中的 `mac-启动服务.sh` 文件模式为 `100644`，直接执行需要额外赋予执行权限，故安装脚本提示使用 `bash` 运行。macOS 在线安装和启动未在本机验证。
