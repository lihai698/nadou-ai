# 阶段 13/14：干净发布包启动检查（2026-10-04）

## 发现的缺口

公开预检 `tools/prepare-release.py` 能确认哪些文件可以进入发布包，但原流程在导出后仍依赖人工启动，无法证明发布包在没有项目数据的目录中能加载页面。启动时会创建 `data/`、`assets/` 等运行目录；直接在导出目录启动会把验收产生的文件混入待发布内容，也可能继承当前终端的密钥环境变量。

## 本轮补充

新增 `tools/verify-release-startup.py`，作为发布包生成后的自动门禁：

1. 读取 `RELEASE_FILES.json`，校验清单路径安全、`VERSION` 一致、每个公开文件 SHA256 一致，并拒绝清单外文件和符号链接。
2. 拒绝 `API/.env`、`data/`、`assets/`、`output/`、`history.json` 和 `global_config.json` 等私人数据路径。
3. 找到导出包自带的 `python/python.exe`（macOS 可使用 `python/python`），先确认 `uvicorn`、`fastapi`、`httpx` 和 `PIL` 等运行依赖已经安装，再只复制启动所需公开文件到临时目录；不会复制 `python/`、测试、文档、工具目录，也不会修改导出目录。依赖未安装时直接失败并提示先运行安装依赖脚本。
4. 清理子进程环境中的常见密钥、令牌和密码变量，固定监听 `127.0.0.1`，选择临时端口，访问 `/` 与 `/static/index.html` 并要求 HTTP 200 和 HTML 内容。
5. 无论成功或失败都停止临时服务，超时后强制回收进程并删除临时目录。

新增 `tests/test_verify_release_startup.py` 覆盖清单哈希、版本、私人路径、清单外文件、运行沙盒写入隔离和环境变量过滤。

## 使用与证据

在 `prepare-release.py --build` 生成的目录执行：

```text
python\python.exe tools\verify-release-startup.py .
```

本轮使用当前源码在临时导出目录生成公开包，并用已经完成依赖安装的项目 Python 通过 `--python` 覆盖路径完成启动检查：根页和静态页均返回 HTTP 200，服务退出后临时目录自动清理，导出目录文件哈希未变化；直接使用尚未安装依赖的包内 Python 会按预期失败，不会误报通过。专项测试 6 项通过。

## 范围限制

该工具只验证无私人数据时的本地进程启动、清单完整性和两个基础页面；不替代正式安装目录的人工页面验收、真实供应商请求、macOS 实机安装或跨版本用户数据升级。磁盘不足仍需要正式安装目录的故障演练。

## 2026-10-04：启动前磁盘空间门禁

`tools/check-environment.py` 新增可选参数 `--min-free-bytes`。传入正整数后，检查配置根目录所在磁盘的可用空间；配置根目录尚未创建时使用最近的已有父目录查询，不读取目录内文件，也不输出私人路径内容。可用空间不足或无法查询时返回启动检查失败；默认值为 `0`，保持原有启动检查行为。

隔离测试在 `tests/test_check_environment.py` 中覆盖低空间、缺失目录和关闭门禁，共 8 项通过；本机用 1 字节门槛运行检查通过。该门禁用于发布前和长期维护窗口的快速预检，不能替代真正写满磁盘、恢复空间后重试及跨平台实机测试。
