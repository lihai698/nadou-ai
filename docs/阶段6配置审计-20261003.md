# 阶段 6：配置边界与启动前校验（2026-10-03）

本轮先处理配置边界中可以在不接触真实供应商的情况下验证的部分：公开默认值、个人配置、密钥文件和发布包入口。没有展示现有 `API/.env`、`global_config.json` 的私人值，也没有访问真实外部服务。

## 已交付

- [API/.env.example](../API/.env.example) 只包含空密钥字段和本地 ComfyUI 默认地址。复制它为 `API/.env` 后再填写本机配置；不填写任何供应商密钥也可以启动本地画布。
- `tools/check-environment.py` 在启动前检查 `.env` 的参数名、重复项、引号、数字和 URL 格式；同时检查 `data/api_providers.json` 的 JSON 类型、平台 id、地址和版本字段。错误只包含配置文件、行号或键名，不输出配置值、密钥或完整原行。
- 检查器新增 `--config-root`，可以把 API、data、assets 和 JSON 配置指向隔离目录。真实工作区的私人目录仍使用默认根目录，检查器不会为了验收复制或改写私人值。
- `tools/prepare-release.py` 只放行精确路径 `API/.env.example`，继续排除 `API/.env`、`API/custom.env` 和其他私人配置；完整发布包测试覆盖了这个边界。

## 2026-10-03 配置读写边界试拆

`main.py` 原先同时负责决定配置路径、创建运行目录、解析 `.env`、读取单个值和重写文件。现已将不含业务规则的文件读写移入 `backend/local_env.py`：

- `ensure_runtime_files(env_path, data_dir)` 只创建调用方指定的目录和空配置文件。
- `load_env_file(path, environ)` 只把文件中尚未存在于进程环境的键加载进去，保留原有环境变量优先级。
- `read_env_value(path, key)` 和 `update_env_values(path, updates, environ)` 保留原注释、空行和未涉及配置，并对包含空格、`#` 或引号的值使用 `.env` 引号。

依赖方向为 `main.py -> backend.local_env`；模块不读取默认路径、不拥有密钥、不导入 `main.py` 或其他业务模块。`tests/test_local_env.py` 覆盖独立读写规则，`tests/test_local_env_entry.py` 在临时公开副本中通过 API 设置保存、进程重启加载和现有配置保留验证。真实 `API/.env`、用户数据和外部供应商均未读取或调用。

## 2026-10-04 配置保存中断保护

`update_env_values` 现在把完整新内容写到同目录临时文件，`flush`/`fsync` 后用 `os.replace` 替换 `.env`；只有替换成功才更新进程环境。失败时旧文件和旧进程值保持原状，临时文件尽力清理。模块内锁保证同一进程的两个保存不会互相覆盖；不同进程仍没有跨进程协调，部署时应只运行一个写入实例。

隔离测试验证了替换失败回退和同进程并发保存两个键，`tests/test_local_env.py` 共 5 项通过；临时公开副本中的真实 API 设置保存及重启加载 1 项通过。未读取现有私人 `.env`。

## 2026-10-04 旧 Token 配置回退与来源检查

`GET /api/config/token` 仍优先读取当前 ModelScope 环境配置，仅在其缺失时读取旧版 `global_config.json` 的字符串字段 `modelscope_token`。旧文件缺失时返回空字符串；JSON 损坏、编码错误、字段类型错误或读取失败时，返回空字符串，并将固定错误类别、异常类型和请求追踪标识写入受控诊断日志。日志不写配置路径、异常文本或 Token 值。没有迁移、修改或读取项目中的真实旧配置文件。

该接口仍返回完整 Token，供旧版页面或兼容调用使用；新版 `angle.html` 与 `zimage.html` 已改用只返回配置状态的 `/api/config/token/status`，生成请求由后端使用服务端 Token。两个接口带 `Origin` 的请求须与服务的 ASGI 协议、Host 和端口同源，否则返回 403；无 `Origin` 的旧版直接请求继续兼容。代码不直接相信客户端传来的 `X-Forwarded-*`，部署在 HTTPS 反向代理后时，需由可信代理配置正确的 ASGI 协议。隔离 HTTP 测试覆盖同源、跨站、伪造转发协议、环境配置优先、旧文件回退及错误诊断脱敏。

同源 `Origin` 检查只阻止普通跨站浏览器 `fetch`，不能代替鉴权。无 `Origin` 的直接请求仍可读取 Token；DNS 重绑定时，恶意域名可能同时出现在 `Host` 和 `Origin` 中，本检查也无法识别。兼容现有局域网或自定义域名部署所需的 Host 白名单尚未定义，因此没有擅自限制 Host。这些属于阶段 13 的访问控制工作，当前不能认定 Token 接口已全面安全。

2026-10-06 补充：Token 响应增加 `Cache-Control: no-store`、`Pragma: no-cache`、`Expires: 0` 和 `Vary: Origin`，避免浏览器或代理缓存完整凭据。两个旧页面仍通过同源接口读取 Token，后续若改为后端代理或短期内存注入，仍应保留这些缓存禁止头。
