2026-10-18。在第八轮已接入的 CanvasRemoteSync 内修复旧任务失效边界，保留前八轮未提交成果。本轮没有继续拆分节点合并算法，没有新增依赖或改变服务端接口。

## 复现与修改

延迟请求测试确认：控制器在画布 ID 变化后，仍可能调用 apply、触发另一个画布的完整 GET、执行旧延迟回调；普通画布旧请求失败还会显示错误。普通编辑器原有 apply/merge 的 ID 检查能挡住部分错误数据应用，因此不能把控制器测试直接描述为已经证明真实页面跨画布数据丢失。智能画布当前 ID 来自固定 URL，本轮同时为其离开/恢复页面建立明确边界。

- 控制器内部记录当前生命周期编号。stop 使编号变化，回包必须仍属于当前编号和画布 ID 才能应用或继续调度；同 ID 关闭重开也能拒绝旧回包。
- stop 清除延迟和轮询计时器，并使已经排入事件队列的旧回调失效。停止期间消息和直接同步调用不产生新请求。
- 每个延迟任务有独立编号，已被替换的旧延迟回调不会重复请求。
- 普通轮询的忙碌标记由本次请求拥有。旧请求结束不能清掉新请求的标记；重复 start 期间已有请求仍保持串行。
- 两种画布开始加载前 stop；普通画布成功删除当前画布时 stop；页面 pagehide 时 stop。pageshow.persisted 表示浏览器从页面缓存恢复，此时重新启动并同步一次。
- 两个 HTML 更新脚本版本，知识索引同步更新文件摘要。

不强行取消已发出的 HTTP 请求；请求可能在网络层继续完成，但过期结果不能影响编辑器。保存队列、草稿、原生合并和保存失败阻止返回的流程不变。
