# 阶段 11：视频任务远端刷新与两画布入口（2026-10-04）

## 本轮范围

本轮在已有 `POST/GET /api/canvas-video-tasks` 的基础上补齐已受理视频任务的显式单次查询，并把查询入口接到普通画布和智能画布的恢复卡片。仍不调用真实或收费供应商，也不把浏览器停止等待解释为远端取消。

## 已实现

- `POST /api/canvas-video-tasks/{task_id}/refresh` 只读取本地任务记录中的远端编号，按落盘的查询模式调用一次远端查询；不会重新提交视频。当前支持 RunningHub OpenAPI、即梦 CLI 的 `query_result`，以及已经由画布视频适配器使用 GET 长轮询的通用 OpenAI/APIMart/火山类接口、土豆和 Agnes 查询模式。
- RunningHub 返回完成时下载本地视频并把任务改为 `succeeded`；明确失败改为 `failed`；处理中、网络错误、超时和下载失败继续保留 `unknown` 及原远端编号。
- 适配器得到上游编号后立即写入任务记录，再进入长轮询；服务重启或同步响应中断后仍可用该编号尝试刷新。即梦 CLI 也在进入 `jimeng_store_outputs` 前写入 `submit_id`，查询模式只保存固定标识，不保存查询地址、密钥或原始回包。
- 普通画布和智能画布遇到带可查询远端编号的 `unknown` 记录时显示“刷新远端结果”，成功后写回原输出节点/媒体节点；没有远端编号时继续显示不可重提提示。
- 智能画布在视频查询暂时失败、远端状态仍未知或刷新不可用时保留原分支节点和视频任务编号，恢复卡片不会被外层运行错误清理；明确完成后才清理旧编号，避免下一次生成重复提交。
- 任务公开响应对旧记录的 `input_summary` 也执行固定字段白名单，避免提示词、参考地址和 `raw` 随兼容读取返回。

## 验证

使用临时任务目录和模拟 HTTP 响应验证：

- `tests/test_canvas_video_remote_query.py` 覆盖受理编号落盘、通用 GET/RunningHub 完成与处理中刷新、无编号冲突、状态映射、输出下载和旧记录字段白名单；`tests/test_canvas_video_jimeng_query.py` 覆盖即梦 CLI 受理回调、单次查询和排队保留编号；
- 两个画布的视频生命周期、未知状态恢复卡片和新增刷新按钮 JavaScript 回归（含智能画布分支保留）；
- `node --check static/js/canvas.js`、`node --check static/js/smart-canvas.js`、`python\\python.exe -m py_compile main.py` 和差异空白检查。

## 尚未完成

其它未列出的供应商也不会因为协议文字相似而自动启用查询。即梦 CLI 的单次查询依赖本机 CLI 登录会话，CLI 不可用时只保留 `unknown` 和原编号，不自动重提。远端取消、跨进程协调、任务过期清理、真实供应商联调和长时间运行压力仍未验证，因此阶段 11 整体不勾选完成。
