# RunningHub 媒体出入模块化验收（2026-10-21）

本批将 `main.py` 中五个完整业务主体归入三个已有模块：`provider_media_transfer` 拥有 `runninghub_local_asset_path`；`runninghub_protocol` 拥有 `runninghub_output_ext`、`rewrite_runninghub_file_url`、`runninghub_extract_outputs`；`generation_output_service` 拥有 `runninghub_store_remote_output`。原公开函数签名保留，只连接每次调用的当前依赖。RunningHubAppService、标准接口适配器、图片与视频查询、在线图片保存、媒体读取及下载的真实调用方继续使用这些适配入口，旧业务主体已清除。

模块只使用传入数据和依赖；不读取配置、不持有任务状态、不导入 main 或其他 backend 模块。协议模块只处理数据；供应商媒体模块管理 RunningHub 特有路径策略；生成结果模块下载并写入文件。文件名、存储路径和 URL 映射仍由既有存储端口负责，任务状态及历史仍由相应任务与历史模块负责。

保留 RunningHub 与通用媒体路径解析的差异：先判断原始前缀再解码；`/assets/input/`、`/input/`、`/assets/output/` 使用原目录策略；其他 `/assets/` 与 `/output/` 走原映射；commonpath 的 ValueError 继续透传。输出扩展名仍先看 URL，再按原 Content-Type 顺序回退。解析保持四个数组键和五个 URL 字段的优先级、首个空数组与根 URL 回退、列表真假值、重复项和顺序。远程写入保持重写、协议判断、请求、非成功回退、扩展名、UUID、路径、写入和 URL 返回顺序；读取或 URL 构造失败后的文件残留合同不变。
