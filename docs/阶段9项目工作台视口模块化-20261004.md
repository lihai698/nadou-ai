# 阶段 9：项目工作台视口模块化（2026-10-04）

## 目标与范围

把项目工作台 `canvas-list.js` 中与项目数据无关的画布板视口职责拆成可独立维护的前端模块。范围包括：

- 视口状态 `x`、`y`、`scale`；
- 屏幕坐标与画布世界坐标换算；
- 根据卡片边界重置视图；
- 鼠标背景平移、滚轮缩放；
- 监听器的幂等注册与显式清理。

卡片数据加载、项目/回收站状态、卡片拖动、创建和导出仍由工作台入口负责。本次不改普通画布或智能画布核心逻辑，也不改变后端接口和数据格式。

## 模块职责与允许依赖

`static/js/canvas-list-viewport.js` 只拥有注入的 `board`、`boardWorld` DOM 引用和自身视口状态，不读取项目数组、画布 JSON 或服务接口。它只通过 `beforePanStart` 回调通知入口关闭已有卡片菜单，不反向导入 `canvas-list.js`。

工作台入口通过 `CanvasListViewport.createCanvasListViewport({ board, boardWorld, beforePanStart })` 获取控制器，并通过公开的 `state`、`screenToWorld`、`boardCenterWorld`、`reset`、`apply`、`bind` 和 `destroy` 接口交互。模块内部不写项目数据；卡片拖动仍使用公开坐标换算接口。

## 前端状态、样式和事件隔离

- 视口状态只在模块内部创建，并以只读约定的公开对象供卡片拖动读取。
- 模块只写 `boardWorld` 的 transform 和 `board` 的背景定位/尺寸，并切换 `panning` 类；卡片样式由工作台入口和 CSS 管理。
- `bind()` 重复调用不会增加监听器；`destroy()` 移除 board 和 document 监听器并结束当前平移，便于页面重开或测试时清理。
- 点击卡片、创建卡片、按钮和表单控件不会触发背景平移；滚轮缩放保持光标下的世界坐标不变。

## 实际接入与旧实现清理

- `static/canvas-list.html` 在 `canvas-list.js` 前加载 `canvas-list-viewport.js`。
- `static/js/canvas-list.js` 删除原内联视口计算、平移和缩放监听器，改用控制器接口。
- 搜索确认 `canvas-list.js` 不再保留 `onBoardPan*`、`onBoardWheel`、`applyViewport` 或旧的视口边界常量；页面只有一套视口入口。

## 兼容性、风险与恢复

视口状态不写入画布 JSON，旧画布数据无需迁移。模块若缺失会在工作台入口明确报错，避免静默退回第二套实现。恢复时还原 `static/canvas-list.html`、`static/js/canvas-list.js` 并删除 `static/js/canvas-list-viewport.js` 与对应测试/文档即可；不触碰用户画布、素材和配置。
