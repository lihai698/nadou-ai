# 阶段 10：画布、项目格式版本与隔离恢复

## 已接入的真实写入口

- `data/canvases/<id>.json` 和 `data/projects.json` 的旧文件没有版本字段，按格式 0 读取；读取本身不改文件。
- 首次保存时在原 JSON 对象增加整数 `format_version: 1`，原有画布字段、节点、连接和项目数组保持原形状。画布普通保存、轻量元数据保存和删除项目时的画布迁移均走同一版本规则与原子替换。项目创建、更新、删除及默认项目创建也写版本 1。
- 版本为负数、布尔值或非整数时拒绝；高于 1 的未来版本返回 409，损坏或不符合基本容器形状的项目文件返回 500。旧项目文件读取失败时不会再当作空项目文件覆盖。画布列表会跳过无法识别的文件，直接打开及写入仍明确报错，原文件保留。
- `history.json` 是顶层数组，`storage_settings.json` 是扁平路径对象。改变它们的容器会破坏旧程序，因此本次保持格式 0；只读工具可检查这两种形状。

`backend/data_formats.py` 只负责纯格式规则；`main.py` 负责读取、锁、HTTP 错误和原子落盘。`tools/check-data-formats.py` 检查指定副本中的这四类 JSON，输出版本计数；带 `--snapshot` 时比较相对路径和 SHA256。它还会扫描副本根目录及 `data/` 下的所有 `.json.*.tmp` 原子写入残留，因此对话、素材索引、平台设置和任务记录等新增 JSON 入口不会被恢复检查漏掉。工具不输出数据内容，也不修改文件；它不覆盖素材、生成结果、密钥或浏览器本地数据的备份检查。

## 旧代码回退兼容性

对基线提交 `53168d8e6b7be6174f2d3eccae9375ce4d44cd3e` 的 `main.py`，在临时目录内提取并执行原始 `load_canvas`、`save_canvas`、`load_projects`、`save_projects` 函数，输入自制版本 1 文件，结果如下：

| 文件 | 基线读取版本 1 | 基线再次保存 |
| --- | --- | --- |
| 画布 | 可读，原字段保留 | 保留 `format_version: 1` |
| 项目 | 可读，项目内容保留 | 旧写法去掉顶层版本标记，成为可读的格式 0；项目内容仍在 |

这证明的是上述旧读写函数对当前**只增加版本字段的格式 1**的兼容性，不代表基线程序的所有界面、任务或插件均已回归。未来若引入实际字段迁移，必须另测代码回退；旧程序没有未来版本保护，不能用旧代码修改未来版本文件。

## 失败恢复演练与操作方法

`tests/test_data_format_migration.py` 只用临时自制画布、项目、存储设置和历史数据：先复制为独立备份，确认 4 个 JSON 的哈希一致；模拟根目录和 `data/` 子目录中的任意 JSON 原子写入残留 `.tmp` 文件，以及损坏工作副本的项目文件，校验工具均返回失败；把原备份复制到另一个新目录后，校验恢复副本与备份 4 个文件的路径和哈希一致，原备份字节不变。HTTP 专项还验证旧画布/项目首次保存变为版本 1、未来版本拒绝读写且字节不变、项目删除的画布迁移成功，以及项目文件写入失败后保留原项目并能重试完成。

### 2026-10-04 跨进程原子替换回归

`tests/test_atomic_json.py` 新增两个隔离进程同时写同一自制 JSON 的回归。每个进程只写完整对象，测试确认最终文件始终可解析、临时文件已清理；该规则明确为“最后一次成功原子替换生效”，不承诺跨进程读改写合并，业务层仍需在部署上避免同一记录的并发修改。

### 2026-10-04 全部本地 JSON 的可选恢复审计

`tools/check-data-formats.py` 新增 `--all-json`。启用后在原有画布、项目、存储设置和历史检查之外，继续审计根目录兼容 JSON 以及 `data/` 下的对话、任务、素材索引、平台配置和其他本地 JSON：只确认 UTF-8 JSON 可解析，并在 `--snapshot` 下比较相对路径与 SHA256。未知业务容器暂不强行标版本，统一记为 v0，避免恢复工具伪造迁移规则；输出仍只包含类型、数量和哈希差异，不输出记录正文。

`tests/test_data_format_migration.py` 新增隔离回归，确认自制对话和兼容配置被纳入快照比对，内容变化只报告相对路径和“内容哈希不同”，不会泄露自制的敏感文本。真实用户数据和正式备份没有被读取；跨进程写入、不同磁盘备份和完整启动恢复仍需独立演练。

实际升级前应先停止生成和保存，按《备份恢复说明》制作包含画布、项目、素材和配置的私有一致性备份，并保留原目录。可先对**备份副本**运行：

```powershell
python\python.exe tools\check-data-formats.py --root D:\隔离副本 --snapshot D:\原始备份\snapshot
```

故障时停止服务，保留故障现场；把验证过的备份复制到新的空目录，在该目录运行校验与实际读取接口，再决定从恢复目录运行。不要直接覆盖原始备份。代码退回基线时，本格式 1 的画布和项目可以读取；旧程序保存项目会丢失版本标记，重新运行当前代码的首次项目写入会补回版本 1。若遇到未知未来版本，应升级到能识别它的程序，或同时恢复与旧代码匹配的数据备份。

## 验证与限制

- 格式/HTTP/恢复专项 8 项通过；现有画布基线 6 项、项目记录 4 项通过；`py_compile` 通过。最终全量核心检查应在并行修改汇合后执行。
- 项目删除涉及多个画布及一个项目文件，仍不是跨文件事务；失败前已迁移的画布会保留在默认项目，项目文件保持旧内容，重试会迁移剩余画布并删除项目。不同进程同时写同一文件仍无协调。
- 只用公开代码与自制临时数据演练；没有读取、迁移或覆盖真实用户文件，也没有覆盖原始备份。本次尚未给历史和存储设置增加版本，阶段 10 整体仍未完成。
