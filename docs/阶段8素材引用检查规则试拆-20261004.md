# 阶段 8：素材引用检查规则试拆

日期：2026-10-04  
范围：把素材删除前用到的本地 URL 收集与 JSON 递归引用匹配规则移到 `backend/media_reference_rules.py`。本次只拆纯判断边界，不移动引用文件扫描、锁、删除和索引写入。

## 职责、数据和依赖

| 模块 | 负责 | 不负责 | 数据所有权 |
| --- | --- | --- | --- |
| `backend/media_reference_rules.py` | 从调用方提供的 JSON 值收集本地媒体 URL；通过显式路径解析器判断是否命中目标文件 | 不打开文件、不扫描目录、不解析默认 URL 配置、不获取锁、不删除文件 | 不拥有持久数据；只返回新列表或布尔结果 |
| `main.py` | `local_media_path_from_url` 的目录/URL映射和文件存在性检查；历史、画布、对话、素材索引的扫描、锁序、引用保护和删除事务 | 不再重复实现 JSON 递归和本地 URL 前缀收集 | 仍拥有各持久文件、锁和删除流程 |

允许依赖方向为 `main.py -> backend.media_reference_rules`。规则模块只依赖 Python 标准库；`resolve_local_path` 是入口显式传入的函数，不反向导入 `main.py`，也不能让新模块取得持久化路径或锁的所有权。`main.py` 保留 `json_references_media_path` 兼容适配器，以便现有删除/清理调用和测试继续经过同一入口解析器。

## 兼容边界

- 本地 URL 前缀仍为 `/assets/`、`/output/`、`/api/storage-files/`；递归顺序、重复值和字符串两端空白处理保持原行为。
- 引用匹配仍使用目标路径和解析结果的 `normcase(realpath(...))` 比较；解析器异常按“本次无法确认”返回 `False`，调用方在文件无法读取时继续保留文件。
- 规则模块支持字典、列表、元组和嵌套值；数字、布尔值、`None` 等非容器值不视为引用。
- 画布/历史/对话/素材索引文件扫描、损坏文件保护、四类锁顺序和 `os.remove` 都保留在 `main.py`，没有改变删除 API 或数据格式。

## 验证

`tests/test_media_reference_rules.py` 3 项通过，覆盖本地 URL 收集顺序、显式解析器、路径规范化、解析异常和 `main.py` 兼容适配器。素材删除相关回归 `tests/test_canvas_log_cleanup.py` 16 项、`tests/test_storage_file_delete_references.py` 3 项、`tests/test_asset_library_cleanup.py` 5 项均通过；`py_compile` 和 `git diff --check` 通过。`rg` 确认旧递归实现已删除，仅保留新模块和一个调用应用解析器的兼容适配器。

专项测试只使用自制 JSON 值、URL 和临时路径，没有读取或写入真实 `data/`、`assets/`、历史、画布、素材索引或 API 配置，也没有调用供应商。

## 限制与恢复

本次不解决外部进程同时修改引用文件、跨文件事务或删除失败恢复；这些仍是阶段 8/10 的后续边界。若需恢复，删除该模块和专项测试，把 `collect_local_media_urls` 与递归匹配逻辑恢复到 `main.py`，再移除适配器导入；持久数据格式无需迁移。
