# 阶段 11：视频同编号跨进程协调（2026-10-04）

本次只处理画布视频任务的本地 `client_task_id` 幂等和状态写回。测试使用临时任务目录与假供应商，没有读取真实画布、配置或素材，也没有向真实供应商提交。

## 行为

- `POST /api/canvas-video-tasks` 在同编号文件锁内读取旧记录、写入 `queued` 并安排 worker。另一进程使用相同编号时只返回已有任务，不启动第二次供应商提交。文件锁只覆盖短暂的本地读改写；供应商请求和远端刷新期间不持锁。
- 后台 worker 的 `queued → running`、远端受理编号和最终结果都在同编号锁内检查当前记录后写回。任务记录或锁在提交前不可用时，不调用供应商；本进程对外显示本地启动失败。
- 另一进程看到 `queued/running` 时可返回保守的 `unknown` 视图，但不据此把磁盘记录写成 `unknown`。进程编号不同不能证明原 worker 已退出；原 worker 因此仍可保存结果。
- 远端刷新在请求返回后重新读取磁盘。若编号变化则拒绝旧查询结果；若 owner 已写入终态则返回该终态。对仍在运行的记录，只有远端明确成功并取得本地输出，或明确失败，才能写入终态；未知、排队和传输故障不能覆盖活跃 worker。

## 验证

- `tests/test_canvas_video_cross_process.py`：6 项通过，包括两个进程同编号同时 POST 只触发一次假供应商、第三进程 GET 不覆盖活跃 owner、刷新期间 owner 写入的终态优先、未知刷新不覆盖运行态、提交入口和 worker 锁失败均不触发供应商，以及磁盘结果暂时缺失时 volatile 完成缓存也阻止重复提交。
- `test_canvas_video*.py`：32 项通过；`main.py` 和新增测试的 `py_compile` 通过；`git diff --check` 无差异空白错误。
- `tools/check-core.py`：Python 355 项、JavaScript 163 项及中英文词条检查通过。

## 后续边界

本次没有实现跨进程存活证明或心跳。因此外进程对活跃任务也会看到保守的 `unknown` 视图，磁盘保留原 `running`，直到 owner 完成或后续获得可确认的远端结果。worker 在已保存 `queued` 后遇到持久锁故障，本进程显示失败，磁盘仍保留 `queued`；重启后按未知状态处理，不能据此重新提交。远端取消、跨进程远端查询去重、过期记录应用清理和真实供应商联调仍未完成，阶段 11 不勾选完成。
