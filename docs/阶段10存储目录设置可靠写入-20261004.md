# 阶段 10：存储目录设置可靠写入

## 范围与入口

`main.py` 的 `GET/PATCH /api/storage-settings` 仍使用 `load_storage_settings`、`save_storage_settings` 和 `apply_storage_settings`。设置文件仍是 `data/storage_settings.json`，内容仍为 `upload`、`generated`、`local` 三个扁平字段；相对路径仍按程序目录解析，空字符串仍重置对应默认目录。现有完整三字段提交行为不变。部分字段提交现在保留未提交字段，符合 PATCH 的更新范围。

## 保存与并发

写入改用 `backend.atomic_json.write_json_atomic`：在同目录写临时文件、同步磁盘后替换目标。替换前失败时，旧文件字节保持原样，临时文件尽力清理，异常继续交给现有 HTTP 错误路径；只有替换成功后才更新进程内三个生效目录。保存前会严格读取已有文件；只有文件不存在时才使用默认值。现有 JSON 损坏、类型错误或读取失败时，PATCH 报错且不覆盖原文件。GET 继续按原行为回退默认目录，诊断仅记录异常类型，不输出私人路径。

`STORAGE_SETTINGS_LOCK` 覆盖同一进程中的读取、部分字段合并、创建目标目录、保存及更新生效目录；`backend.process_lock.interprocess_file_lock` 另外锁定同名 `.lock` 文件，把同一读改写区间扩展到不同进程。两个线程或进程分别修改不同目录时，后进入者会在锁内重新读取前一个提交，再合并自己的字段，避免丢失更新。目标目录的创建发生在文件替换前；若随后写入失败，新建的空目录可能留下，但旧设置仍生效。锁等待超过 30 秒会失败并沿用现有保存错误边界。

## 隔离验证与恢复

`tests/test_storage_settings_atomic.py` 在临时目录中通过真实 GET/PATCH 路由验证相对路径、旧扁平格式、成功回读、部分字段保留、损坏或读失败时拒绝覆盖，以及替换失败时旧字节及内存目录不变；另用两个线程验证写入期间第二次更新被串行化，最终两项字段都保留。新增 `tests/test_process_lock.py` 使用两个隔离 Python 进程确认第二个进程必须等第一个释放同一锁文件后才能进入。专项 3 项、跨进程锁 1 项、Python 语法和差异空白检查通过。测试没有修改真实 `data/storage_settings.json`。

磁盘或权限故障排除后，重新保存目录设置即可。现有 JSON 已损坏时，GET 仍回退默认目录；需从备份恢复原文件或人工修复 JSON 后才能再次保存。本次不自动覆盖损坏文件、不搬迁素材，也未覆盖跨文件事务、备份迁移和真实多实例部署演练。阶段 10 整体仍未完成。
