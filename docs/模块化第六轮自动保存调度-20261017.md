## 当前职责

`CanvasSaveScheduler` 为每个编辑器创建独立调度器，拥有计时器句柄和有效票据。只暴露 pending、schedule(delay)、cancel()。宿主提供 save 与 getCanvasId；调度器不保存节点、草稿或任务编号，不操作 DOM 或网络。

- Scheduler 管待执行计时器及取消。
- Session 管正在保存、后续保存标记和等待者。
- Transport 管 HTTP 保存和冲突版本取回。
- Recovery 管持久草稿和跨页合并。
- 编辑器仍负责数据快照、节点合并、界面、草稿宿主及原有错误反馈。

原 saveTimer 全部读写已迁移，包括防抖、直接保存、重试、清空、任务执行前保存、后续保存和远端同步保护。旧变量和旧测试辅助函数名称已搜索清理，无重复计时器状态。

## 已复现的行为修正

普通画布旧计时器执行或取消后，saveTimer 仍是 truthy 的旧句柄。新增回归实际观察到：自动保存已完成且画布干净，再返回列表仍发送第二次 PUT（期望 1、实际 2）。

新 pending 只表示真正尚未执行的计时任务；回调执行前清除它。dirty、Session.isSaving 和 Session.queued 仍独立保护未保存内容，因此没有用“无计时器”代替“内容已保存”。

取消/替换使旧票据失效，即使旧回调已经排入队列也不执行。回调在调度时记住画布 ID，执行时若当前 ID 不同则丢弃，不保存新打开的另一幅画布。计时器返回句柄 0 也可正确管理。

普通 500ms、智能 450ms 防抖和 0ms/300ms 后续保存间隔保持；草稿备份、撤销记录及请求格式不改变。智能画布返回时原有的主动保存策略保留，不宣称所有编辑器都不再发额外保存。

4. 智能画布创建提示词、编辑中文、返回并重开，内容完整保留。
