## 使用前必须加载新后台

交付时只读核实：`127.0.0.1:3000` 的 OpenAPI 仍没有 `/api/canvas-audio-tasks`，`ApiProviderPayload` 仍没有 `audio_generation_models`，证明当前进程尚未加载新源码。不要在旧后台保存新增音频配置，否则生成列表无法保留。

等当前生成任务结束后，在原服务窗口按 Ctrl+C 停止，再运行根目录 `run.bat`。浏览器 Ctrl+F5 刷新，进入 API 设置，选择平台、拉取并勾选音频模型、应用、保存，然后回到画布手动选择模型。

真实供应商的模型权限、调用效果与协议兼容尚未验证。未知模型可在同一选择窗口手动改用途；不增加自动选模型行为。

## 后续纠正：火山引擎与本地一键包

用户明确未来音频来源为火山引擎或本地一键包，协议入口使用原基本信息区，不增加音频专属配置区域。本轮已移除重复生成高级区，原上方协议控件保持原用途；尚未添加缺乏调用实现的协议选项。

已只读核对当前内置火山平台：ID 为 `volcengine`，协议为 `volcengine`，地址为 `https://ark.cn-beijing.volces.com/api/v3`。本机该平台所有五类模型列表均为空。没有读取或回显密钥。

现有新增音频清单与真实接口适配需区分：

- 音频模型清单已接入选择、保存与两画布同步。
- `backend/canvas_audio.py` 的转写明确只接受 OpenAI 兼容协议。
- 当前生成通过 `audio_generation_protocol` 调用 OpenAI 或原有 MiniMax 音频端点，尚无火山原生语音处理；直接把方舟地址用于默认语音请求会形成不正确的路径，不能宣称火山音频可用。
- 现有方舟模型拉取不能保证返回独立火山语音服务的模型。未拉到的模型仍可使用原列表的添加入口，但登记模型并不等于完成服务接入。

后续应在现有火山平台内部按媒体类型路由，音频使用具体语音服务的地址、鉴权和请求格式，保持方舟图片、视频、文本行为。实际新增的音频协议放原协议入口；不新增独立平台页面、音频高级面板或素材节点模型设置。本地一键包需确定具体软件和服务接口，兼容 OpenAI 时复用已有调用，不兼容时增加对应适配。
