### C03-01：一次查询 503 导致丢失任务跟踪（已复现，待修复）

- 注入方式：只对第一个任务 GET 查询返回 503，模拟生成在 1 秒后正常成功；后续 GET 恢复正常。属于 HTTP 查询暂时不可用，不是物理断网测试。
- 实际：页面立即弹出失败提示，将 pending 删除并保存失败日志。后台实际状态为 succeeded，调用次数为 1，但画布输出为空；刷新后仍无法找回该结果。
- 根因定位：普通画布 `pollCanvasImageTask` 对非成功 HTTP 响应直接进入 `failCanvasImageTask`；没有上游恢复 ID 时后者删除 pending。查询失败与生成失败未区分，导致丢失已受理任务的跟踪入口。
- 影响：短暂查询故障后，用户可能误以为必须再次生成；本次没有自动重复提交，也没有真实扣费。此项不通过，不能把之前“明确生成失败后的手动重试通过”扩大解释为自动恢复通过。
- 建议最小修复范围：短暂网络/可重试 HTTP 故障只重试查询同一 task_id；设置有限退避，耗尽后保留任务标识和清楚的恢复入口。404、确定的任务失败与临时查询故障分别处理。禁止重新 POST 生成。实现前补故障恢复、持续故障、刷新续查和不重复提交测试，同时评估智能画布的同类路径。
- 证据：[后台成功但画布失败](evidence/20260930/transient-query-failure.json)、[失败弹窗](evidence/20260930/transient-query-failure.png)。
