## 使用方法

1. 现有运行任务结束后，停止原服务窗口，再双击根目录 `run.bat`；打开 `http://127.0.0.1:3000/`，画布按 `Ctrl+F5` 刷新。现场检查发现旧服务启动于 2026-10-09，`/openapi.json` 尚无音频任务路由，所以仅刷新页面不足以启用新接口。
2. 原上传入口可直接上传或拖入音频。素材节点仅包含文件、波形、播放器、下载、存入原素材库、拖出功能，不含模型。
3. 把音频连接现有 API 生成节点，自动显示音频参数；手动选择自己的平台和识别模型，点击运行。识别参数不出现音色、格式或语速。
4. API 连接现有 LLM，识别文字进入原输入链路；手动运行 LLM，或使用原一键运行链路处理文字。
5. 生成配音时，文本连接 API，从原模型列表选择已配置的音频生成模型，设置音色、格式、语速等协议支持的参数，手动运行。结果可播放、下载、存库、拖出再连接。
6. 没有上游音频时，可以在音频模型下拉选择“返回原图片模型选择”。原图片模型、尺寸、数量仍保留。状态未知或查询暂停时查询原任务，不重复提交。

平台管理继续复用原 API 设置。识别使用已有“音频识别模型”配置；生成使用新增“音频生成模型”及对应协议配置，不从参考项目导入默认模型。识别当前支持 OpenAI 兼容转写；生成请求适配 OpenAI Speech、MiniMax Speech / Music，实际平台需提供对应能力。

## 关键源码与清理

- `backend/canvas_audio.py`：协议能力、参数、识别输入及音频／文本结果校验。
- `main.py`、`backend/task_records.py`：持久任务入口、供应商请求、原编号查询与写盘失败处理。
- `static/js/canvas-audio.js`：共享素材卡片、参数、波形、拖拽、任务状态与恢复契约。
- `static/js/canvas-audio-host.js`、`static/js/smart-canvas-audio-host.js`：分别接原普通／智能画布；原 API 及 LLM 入口在各自主脚本中分流。
- `static/css/canvas-audio.css`、两份画布 HTML：原主题变量与正式加载入口。
- `static/api-settings.html`、`static/js/api-settings.js`：原平台管理保存和读取音频生成配置。
- `tests/test_canvas_audio*.py`、`tests/canvas_audio_node.test.cjs`：规则、协议、任务、完整应用与前端状态回归。

撤回并清理独立音频生成器、独立转文字预览和 Prompt 转写按钮草稿；源码未保留 `audio-generator`、`smart-audio` 节点入口。保留唯一旧数据兼容读取：普通画布 `image + mediaKind=audio` 读取迁移成音频素材，原 ID 与连线不变；智能画布继续原 `smart-image` 媒体容器。

## 尚未验证及限制

没有实际付费平台生成或识别效果证明；没有全面重测所有图片／视频供应商与协议。音频识别当前只接受一个音频，混入图片、视频或多个音频时明确报错；当前生成协议不接收参考音频，不会悄悄丢弃素材。识别模型与生成模型请分别配置，避免同名模型同时填进两份列表而产生用途歧义。

本地分支有其他任务改动，未全量暂存、提交或推送。接入前快照仍保留，用于选择性回退。用户本次“上传节点能识别音频”确认的是原上传播放，不作为整项 API／LLM 功能验收及源码同步授权触发。
