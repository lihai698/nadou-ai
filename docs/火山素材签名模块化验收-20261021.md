# 火山素材签名模块化验收

日期：2026-10-21。基线 `921b9cfaac4c903fe0d2fd872051672a0f6ec509`；固定产品候选树 `5effb4a5454f6c1ace90d49dfea63af69b0b08db`。最终提交树只追加本文。

## 职责与真实调用

`_volc_hmac` 与 `volcengine_sign_v4_headers` 的完整主体归入现有 `backend/avatar_asset_service.py`，与其唯一业务消费者 Ark 私域素材调用保持同一职责归属。main 保留原函数名、参数、类型标注和默认值的单行适配。服务内部明确接收 service、region、version、host，以及时钟、摘要与签名依赖；不读取配置、不保存凭据、不新增网络调用。

两个完整函数的语法树对比通过，其他 main 和素材协议模块已有语法树不变。新模块内部省去原 main 的返回类型别名，默认参数由 main 原签名提供；归一这两项适配差异后完整函数相同。签名算法、时间格式、查询编码、四级密钥派生、头名称与顺序、错误及原调用顺序均保留。

真实路径仍是素材库注册/审核状态接口 → avatar_asset_service 注册/查询 → main 的 Ark 调用适配 → 原 Ark 请求 → main 签名适配 → avatar_asset_service 签名。主入口只连接当前依赖，未保留第二套签名实现。

## 本次验证

- 15 项新增独立测试。旧树因目标服务缺少签名函数而红灯，候选通过。覆盖已知 HMAC 向量、UTF-8、固定完整签名向量、UTC 时钟只读一次、空体/空白精确哈希、service/region/version/host、查询编码、四级派生顺序、凭据空白不被隐式修剪及原类型错误。
- 固定树专项基线 822、候选 837，各跳过 2。本批额外纳入原素材库与素材协议测试，不能与上批不同范围的 767 直接比较。固定候选 full core：Python 1405 项、JavaScript 1134 项，中英文词条检查通过。
- 29 组签名/调用合同逐值一致，使用虚构凭据及固定 UTC 时钟；精确比较完整签名头、请求 URL、UTF-8 请求体、超时、错误、完整 OpenAPI 与素材库注册记录。实际通过 19 次 loopback TCP POST，覆盖复用/新建分组、提交、缺失 Id、非法 JSON、上游业务错误/503、Active/Failed/Processing、缺失凭据不发请求，以及真实注册/状态路由和持久化。
- 上述本地测试将原请求的 HTTPS URL 在客户端适配处映射到 loopback HTTP，发送前核对原 URL，保留产品生成的全部签名头与请求体。验证的是签名及应用调用合同，不是 TLS 或真实火山服务认证；没有使用真实凭据或真实供应商。
- 131 个后端模块显式导入无 main 反向依赖或环；素材协议模块没有后端依赖边。阻断 main、助手与素材索引模块后，15 项独立测试通过。该静态检查覆盖顶层与嵌套显式导入，不证明动态插件导入无环。
- 既有 103 组 HTTP/图片查询、31 组媒体读取/ZIP、46 组助手原生后端合同全部重新通过，比较后没有归一业务响应。
- 基线和候选真实 Chrome 双画布引用/编号/read_canvas、原生 drop/预览/下载、RunningHub 图片视频及普通 video-proxy/智能 Tudou 图片任务恢复、保存刷新和强杀重启通过。双画布原资源 ZIP 下载按钮均取得 download 事件，落盘条目名/字节一致。普通 clip 原生导出的真实 FFmpeg、文件下载/保存到画布与连线、重复确认不重提、强杀重启恢复也通过；智能画布没有 clip 对应入口。候选相关截图已查看。
