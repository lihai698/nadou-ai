# 阶段 9：图片预览监听器生命周期（2026-10-04）

## 目标与范围

验证生成历史页面的图片放大预览在重复初始化、关闭和重新打开时不会叠加窗口监听器。范围只覆盖 `static/js/image-preview.js` 的预览控制器，不改变图片地址、历史数据、生成请求或画布逻辑。

## 改动与边界

- `StudioImagePreview.attach(container)` 对同一容器默认返回活动实例，避免重复注册 `wheel`、`mousedown`、`dblclick`、`window.mousemove` 和 `window.mouseup` 监听器。
- 返回对象新增 `destroy()` 和 `isDestroyed()`；销毁会移除容器及窗口监听器，并结束当前拖动状态。
- 需要替换图片节点或配置时可显式传入 `{ replace: true }`，旧实例先销毁，再创建新实例。
- 缩放、拖动、双击复位和光标锚定行为保持原有实现；注入样式仍只创建一次。

模块不拥有历史记录或页面状态，不访问后端，不保存用户数据；使用页面调用方传入的容器和图片节点。默认的现有页面调用不需要改变，重复 `attach` 也不会产生第二套活动实现。

## 验证

- `tests/image_preview_lifecycle.test.cjs` 3 项通过：同容器幂等、显式替换前清理旧实例、销毁后监听器计数归零，以及缩放/拖动/双击复位行为。
- `node --check static/js/image-preview.js` 和 `git diff --check` 通过。
- 5 个生成历史页面的 `image-preview.js` 资源查询版本更新为 `2026.10.04.4`，避免浏览器继续使用旧缓存。
- 当前源码隔离页面 `http://127.0.0.1:3028/static/zimage.html` 使用自制历史图片加载成功；点击历史卡片后，预览层可见，`StudioImagePreview.attach` 为函数，图片 transform 初始为 `translate(0px, 0px) scale(1)`。未调用真实供应商，页面只使用临时静态服务和自制 SVG 数据。
