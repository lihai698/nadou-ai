# 阶段 8：实时通知模块试拆

日期：2026-10-03  
范围：把 `main.py` 中的 WebSocket 连接管理和后台事件循环投递边界移入 `backend/realtime.py`。本次只覆盖阶段 8 的一个低风险后端职责，不代表配置、素材、画布、外部连接或任务执行已经完成拆分。

## 职责、数据归属与依赖

| 项目 | 约定 |
| --- | --- |
| 模块 | `backend/realtime.py` |
| 负责 | 维护内存 WebSocket 连接、用户到连接的映射、在线人数统计、统计/图片/画布/素材库/个人通知 JSON，以及后台线程向应用事件循环投递协程 |
| 输入输出 | `ConnectionManager` 保留 `connect`、`disconnect`、`online_count`、`broadcast_count`、`broadcast_new_image`、`broadcast_canvas_updated`、`broadcast_asset_library_updated`、`send_personal_message`；`set_global_loop` 设置循环，`schedule_coroutine` 返回投递 Future 或 `None` |
| 数据归属 | `active_connections`、`user_connections`、`connection_clients` 和 `GLOBAL_LOOP` 只属于实时模块，均为进程内存状态，不写入配置或用户文件 |
| 允许依赖 | Python 标准库 `asyncio`、`json`、`time`、`typing`；不导入 `main.py`、FastAPI、文件系统、网络客户端或其他业务模块 |
| 依赖方向 | `main.py -> backend.realtime`；入口注册 `/ws/stats`，启动时注入当前事件循环，业务推送通过公开调度函数调用 |

## 兼容边界

- `main.py` 继续导出 `ConnectionManager` 和 `manager`，已有业务调用方及 `tests/test_realtime.py` 无需改写。
- `/ws/stats` 路由仍由 `main.py` 注册；`ping` 仍返回 `{"type":"pong"}`，连接建立/断开仍广播 `stats`。
- `canvas_` 开头的客户端仍不计入 `online_count`；同一 `client_id` 的最新连接仍覆盖 `user_connections`。
- 通知 JSON 的类型、字段和失败连接清理行为保持原约定。发送失败的连接从 `active_connections` 移除，其他连接继续发送。
- 应用尚未启动或事件循环已经关闭时，`schedule_coroutine` 会关闭未执行协程并返回 `None`，后台通知不会阻断业务操作。

## 改动文件

- 新增 `backend/realtime.py`。
- `main.py` 删除原 `ConnectionManager` 和 `GLOBAL_LOOP` 实现，保留路由与兼容导入；原来的跨线程 `run_coroutine_threadsafe` 调用统一经过 `schedule_coroutine`。
- `tests/test_realtime.py` 增加入口别名和事件循环调度回归。
