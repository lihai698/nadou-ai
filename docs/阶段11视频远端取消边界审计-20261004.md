# 阶段 11：视频远端取消边界审计（2026-10-04）

## 审计结论

当前不能安全接入视频远端取消接口。本轮没有调用真实或收费供应商，也没有读取真实配置。现有视频适配器有提交和查询代码，但没有在项目中发现可核对的取消 URL、HTTP 方法、请求体、鉴权方式和“已取消”确认回执。`main.py` 的视频任务路由只有创建、读取和单次刷新：

- `POST /api/canvas-video-tasks` 创建本地记录并启动适配器；
- `GET /api/canvas-video-tasks/{task_id}` 读取记录；
- `POST /api/canvas-video-tasks/{task_id}/refresh` 只按原远端编号查询一次，不重新提交。

普通画布的 `AbortController` 和智能画布的 `stopRequested` 只停止本地页面等待或后续链路。它们不会终止后端协程，也没有证据证明远端供应商任务停止，因此不能把这些操作写成 `cancelled`。

## 已核对的安全边界

`backend/remote_task_protocol.py` 已提供两个保守规则：

- `local_stop_decision` 保留 `pending`/`running` 和原远端编号，明确提示“远端状态未被取消”；
- `cancel_remote_task` 只有在适配器合同声明 `supports_cancel=True`，并收到明确的 `cancelled`/`canceled`/`revoked`/`aborted` 状态回执时才返回 `cancelled`。未声明能力、网络错误、404 或 2xx 但没有明确取消状态，都保持 `unknown`。

当前源码中 RunningHub、即梦 CLI、通用 GET 查询、土豆、Agnes、灵境和玉玉等视频路径均没有取消适配器；协议合同对当前视频供应商保持 `supports_cancel=False`。本轮新增 `tests/test_canvas_video_cancel_boundary.py`，以隔离内存回包核对当前供应商集合：即使回包模拟为 `cancelled`，也不会越过能力声明；另验证了本地停止和未来显式启用合同的纯规则。

## 不能据此推断的内容

本地规则测试不能证明任何供应商实际支持取消，也不能推断取消是否收费、是否幂等、取消请求超时后任务是否仍在运行，或查询 404 是否代表供应商已经删除任务。没有供应商协议和独立模拟服务器之前，不应新增通用 `DELETE`、`/cancel` 或“取消成功”按钮。

## 后续接入条件

若以后要接入某一家供应商，必须先取得并记录该供应商的：

1. 取消端点、HTTP 方法、鉴权和请求字段；
2. 远端编号与取消幂等规则；
3. 明确的取消确认状态或查询对账规则；
4. 取消请求超时、404、429、5xx 和已完成任务的处理语义；
5. 不连接真实账户的本地模拟回包测试，再进行用户明确授权的单家联调。

接入时应为该供应商单独增加取消适配器和能力合同，先保存“取消请求已发出但未确认”的 `unknown`，只有确认回执才写 `cancelled`。本轮不勾选阶段 11 的远端取消验收。
