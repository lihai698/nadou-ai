# 创作助手第二阶段：原文、LLM分析与分镜表

日期：2026-10-13。状态：最小流程本地实现及隔离模拟验证通过；真实模型效果、用户验收与源码上传尚未完成。

## 已落实的流程

1. 助手读取或保存已有原文节点。
2. 调用 `create_story_analysis` 创建原生分析节点，绑定用户已选文本平台和模型，不要求图片模型。
3. 原文通过真实输入线接入分析节点。普通画布是 `prompt → llm`；智能画布是原文 `smart-prompt → 开启LLM的smart-prompt`。
4. 使用现有原生运行方案；用户确认后调用 `/api/canvas-llm`，保留原文，记录实际使用的模型与输入。
5. 运行完成后点击“继续创作”，助手调用 `import_story_analysis` 读取已保存的真实JSON输出，校验后创建原生分镜表。
6. 原文变更后可以重新确认运行，再导入更新同一张未手改的分镜表；重复导入不重复建表。

这不是全画布一键自动执行。分析到表的线表示结果归属，结构转换由助手导入工具完成；单纯连线不会执行模型。每次分析调用仍需要明确运行，编辑原文本身不会提交任务。

## 已处理的问题

- 旧故事工具只保存助手写好的结果，却容易被误认为可执行流程：保留能力，修改指引和展示名称为“保存故事分镜结果图”，默认可执行需求走新分析工具。
- 普通画布会在保存时清理 `running`，智能画布会补齐空 `images`：新节点按对应画布的原生保存格式创建，避免确认前出现无意义快照变化；没有移除确认检查。
- 普通模型请求期间切换模型可能导致结果归属错误：在实际请求解析平台、模型时捕获快照，用该快照记录结果。
- 原文、模型、输出或输入连接改变后，旧结果不能直接导入。
- 失败时保留已有输出，清除本次无效的导入证明，不用假分镜代替错误。
- 已手改或已创建配图链的分镜表不自动覆盖，提示保留当前结果并另建流程。

## 启动与使用

正常项目使用现有 `run.bat` 启动；后端已有运行实例需要重启以加载本轮Python改动，再刷新普通或智能画布。无需安装新依赖。

1. 保存原文到提示词节点。
2. 在助手“模型”中选择并勾选文本模型。
3. 对助手说：“将这个原文接入LLM分析，生成分镜表；保留原文。”
4. 查看分析节点与所选模型，确认运行。
5. 完成后点击“继续创作”导入分镜。
6. 修改原文后要求“重新运行分析并更新分镜”；已有手动编辑时先保留该表，按提示另建流程。

旧回合保存了改造前的规则快照时，先停止旧回合并新建对话。3036页面仅供隔离验收，不是另一套产品入口。
