# 双画布编辑器桥接职责

本批基于已推送的 `dfd2f04`，将普通画布剪辑、双画布视频拆解的完整桥接主体与嵌套回调接入 `static/js/canvas-editor-bridges.js`。原函数名作为调用入口保留，实际业务由对应 `CanvasEditorBridges.create(host)` 实例负责。

| 数据或操作 | 负责方与边界 |
| --- | --- |
| 剪辑候选素材去重、命名和来源身份 | 桥接模块，保留画布素材优先和原排序 |
| 视频时长探测 Promise 缓存、临时 video 与超时清理 | 普通桥接闭包，每个实例独立 |
| 拆解 generation、旧请求和切画布边界 | 各自桥接闭包，继续检查原画布和原结果身份 |
| 分镜链、抽帧分组、镜头整理及所有嵌套操作 | 桥接模块调用现有 Host/Model 和原生节点操作，不另起供应商执行流程 |
| 指针关闭事件 | 模块登记并持有处理器；重复初始化不重复绑定，`suspend/resume/dispose` 管理释放与恢复 |
| 画布、节点、连接、选择、视口与配置 | 原画布宿主所有；显式 getter/setter 实时访问，避免把切换前的节点数组捕获成旧副本 |
| 持久化、任务、导出与媒体模型 | 继续调用既有模块及宿主公开能力，不在桥接内建立第二份存储或任务表 |

真实页面在入口之前加载模块；普通和智能页面的隐藏/持久恢复事件调用各自实例。智能画布没有普通剪辑时间线，保留其原生分组整理、保存重试和生成入口，不为形式对称增加剪辑功能。

独立回归覆盖：模块缺失、重复初始化、监听器释放与恢复、独立时长缓存、加载/错误/超时资源清理、上传验证与 multipart 请求、素材优先级、实时宿主替换、原结果身份、generation 与切画布后的生成停止、抽帧去重、保存重试和终止释放。

旧页面片段测试改为加载真实模块和宿主；原行为断言保留，原本针对入口文本的桥接结构断言改为检查实际模块。AST 审计逐一比较四个完整主体和全部嵌套回调，除明确增加的监听器生命周期外，其余入口 AST 保持一致。

本批精确候选、红灯/专项/完整核心、契约、双画布页面、强制重启和导出证据存于本地 `.git/modularization/canvas-editor-bridges-20261021/`，均须核对 `candidate.json` 的同一树后才能提交。公开包预检仅用于本地验收，不表示发布。混合工作区和其他聊天的样式、启动脚本及文档不属于候选；整个原三文件模块化仍在继续。
