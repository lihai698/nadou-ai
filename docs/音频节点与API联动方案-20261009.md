# 音频节点与 API 联动方案

日期：2026-10-09；修订：2026-10-10。状态：已批准并完成本地接入与隔离验证，待真实平台手动验收；仅音频连接 API 生成节点时自动识别，其余操作手动，沿用已有上下游逻辑。

## 最终结构

**音频节点负责素材，现有 API 节点负责生成。现有 API 图片生成逻辑完整保留。**

自动识别只切换 API 的音频处理状态，不自动选平台／模型、不自动提交、不自动转写、不自动创建或运行下游。平台、模型、参数和运行仍由用户操作。现有级联的触发方式与执行顺序不变，只让音频输入／输出加入原媒体链路；本次不建立全局多模态自动路由。

| 位置 | 负责的内容 |
| --- | --- |
| 音频素材节点 | 文件名、格式、时长、大小、波形、播放、进度、音量、下载、存入现有素材库、输出连线 |
| API 图片模式 | 当前图片平台、模型、分辨率、比例、质量、数量及全部执行逻辑 |
| API 自动音频分支 | 音频连接自动识别；模型、能力允许的参数与音频任务仍在现有 API 内 |
| 现有 LLM 节点 | 接在 API 后，沿用原输入、Run LLM、输出与下游逻辑，输出文本 |
| 原生输出节点 | 承载音频，播放、下载、素材库、下游引用；拖出后创建音频素材节点 |
| 智能画布 API 面板 | 沿用现有面板和胶囊控件，自动适配音频参数；素材卡片不含模型 |

不创建独立音频生成节点，不建立第二个素材库，不搬用参考项目的设计系统。

## API 节点布局与原逻辑保护

参照用户截图，保留标题栏、关闭按钮、连线口、平台与模型的双下拉、设置框和 API生成按钮。**不增加图片／音频切换按钮。** 输入预览统一称为“输入内容”，文本、图片、视频和音频分别标注类型，不能把全部输入叫图片。

原图片处理继续显示分辨率、比例、质量和数量。音频连接触发独立音频处理，在同一区域显示所选模型支持的参数。原图片平台、模型和参数独立保留，不被音频参数覆盖。模型仅来自当前 API 配置，不自动添加外来模型，不自动执行生成。

### 自动识别规则

| 连接内容／操作 | 自动行为 |
| --- | --- |
| 音频或音频＋文本 | 自动进入音频处理状态，显示音频引用及对应参数，不需要点击模式按钮 |
| 图片或图片＋文本 | 沿用当前图片处理逻辑与参数 |
| 只有文本 | 默认沿用原图片行为；用户手动选已配置的音频模型时显示对应参数，不根据文本猜测用途 |
| 视频输入 | 识别并展示为视频，保留当前目标入口的处理规则，不把视频当图片或擅自迁移视频业务 |
| 图片、视频、音频混合 | 音频连接触发 API 音频状态，预览保留实际类型、来源和顺序；兼容模型由用户手动选择，沿用目标原有输入规则，不重新设计混合输入路由 |
| 自动进入音频处理，但当前平台没有兼容模型 | 提示配置或选择兼容模型，不自动换平台，不创建外来模型 |
| 断开最后一条音频连接 | 撤销仅由连线触发的音频适配，恢复原图片配置；用户随后主动选择的模型仍保留 |
| 正在生成时输入变化 | 当前已提交请求保持不变，变化仅用于下一次生成，不能重提、改写或取消原任务 |

自动识别的是输入素材类型，最终生成类型由所选模型能力决定。模型选择仍在原 API 下拉中；无须另设图片、文本、视频、音频四个模式按钮。自动适配音频分支不会让普通 TTS 获得原本不支持的参考音频或声音克隆能力。

| 当前行为 | 接入要求 |
| --- | --- |
| `runGenerator` 图片执行分支 | 只在入口增加音频分流，原图片分支完整保留 |
| 图片平台、模型解析 | 沿用原方法；音频字段独立保存 |
| 图片输入筛选 `imageRefsOnly` | 规则不变，不插入音频校验改变图片运行 |
| 尺寸、比例、质量、数量 | 默认值、限制和交互不变 |
| 批量提交、并发 | 原逻辑和图片任务路径不变 |
| 轮询、恢复、错误、重试 | 原逻辑和接口不变 |
| 输出、日志、级联、模板 | 复用既有体系，扩展音频媒体类型 |
| 输入预览 | 增加音频图标和文件信息，避免把音频加载为图片 |

## 音频素材节点

直接拖入现有支持的 MP3、WAV、M4A、AAC、OGG、FLAC 等文件后，创建音频素材节点。

- 外观、选中描边、字体与连线口沿用相应画布。
- 名称、时长、格式、大小来自真实文件，波形来自实际解码；无法解码时不伪造波形。
- 播放、暂停、进度、音量和预览倍速只改变播放，不修改素材或生成参数。
- 下载原文件；存入素材库复用现有分类、去重和保存入口。
- 导入音频和生成结果拖出的音频使用同一种节点，保留来源。
- 节点拖动、播放器、文件拖出与连线拖动各自命中，避免抢事件。
- 不放平台、模型和生成参数；素材节点保留输出口，替换文件通过导入／拖入完成。

## 上下游数据链路

生成链路：`提示词／文本 → 现有 API（所选音频模型自动适配参数）→ 原生输出（音频）→ 拖出音频素材 → 后续节点`。

引用链路：`音频素材 → 现有 API／视频／工作流输入区 → 目标入口的原生音频字段`。

识别输出文本链路：`音频素材 → 现有 API 生成节点（手动选音频识别模型）→ 现有 LLM 节点 → 文本输出／原下游`。仅音频连接 API 时自动识别音频模式；选择模型、点击 API生成及运行 LLM 均沿用手动操作和原级联规则。

不新增转为文本节点，不给 Prompt 增加音频输入口、来源行或“转为文字”按钮。识别与生成共用 API 音频处理分支，模型来自现有 API 配置并由用户手动选择。识别模型显示自身支持的参数，不显示语音生成的音色、MP3 或语速。音频识别结果是文本，应作为 API 的有效结果传给 LLM 的原 Input；不能伪装成音频文件，不能把原音频 URL 当作识别文字。

源码核对：现有 LLM 已有 Input、Output、Run LLM 和级联入口，但当前音频草稿及真实 API→LLM 的文本结果桥接尚未完成。接入时仅扩展 API 音频识别结果的数据传递，复用原 LLM 执行与输出；不能因预览连线存在就宣称当前已可运行。现有 `backend/canvas_video_speech.py` 的镜头表转写要求时间戳，普通识别按所选模型实际能力校验，不改变镜头表业务。

连接后显示音频文件图标、名称、时长、输入顺序和来源。识别音频类型不代表图片模型能理解声音：图片分支仍按原来的图片输入规则执行；已经支持音频的视频／MiniMax／工作流入口沿用原来的音频上传、数量限制和字段映射。

新增音频生成分支按协议校验参考素材。普通 TTS 不能自动当成声音克隆；协议不支持参考音频时，在音频分支明确说明。`@` 沿用现有引用体系，只列真实可解析素材，不另设一套候选库。输出、组内音频和独立素材共享媒体引用契约。

现有剪辑节点拒绝独立音频，本次不改变剪辑业务，也不展示已支持混音的假入口。

## 参数能力

| 类型 | API 音频模式的参数 |
| --- | --- |
| OpenAI 兼容语音 | 协议允许的音色、格式、速度 |
| 支持声音指令的语音模型 | 当前配置明确开启后，展开语气与表达方式 |
| MiniMax 原生语音 | 协议支持的音色、格式、速度及扩展参数；验证后启用 |
| 音频识别模型 | 所选模型实际支持的识别参数，结果作为文本进入现有 LLM 输入，不套用语音生成参数 |
| 音乐模型 | 实际支持的描述、歌词、格式，不套用语音音色和语速 |
| 视频／工作流引用音频 | 现有引用、上传和字段映射 |

音调、音量和参考音频不是所有模型通用参数。界面可选项与最终请求字段必须一致。转写与生成复用现有 API 配置，各自校验适用模型，不能把生成模型当转写模型。

## 两个参考项目的对应关系

| 来源和源码入口 | 参考行为 | 本项目归属 |
| --- | --- | --- |
| BeefTV `canvas-audio-player.tsx` | 音频播放、进度、媒体操作 | 原生音频素材卡片 |
| BeefTV `canvas-audio-settings-popover.tsx`、`audio-settings-panel.tsx` | 常用／展开参数、关闭和事件清理 | API 音频设置区域 |
| BeefTV `web/src/lib/audio-generation.ts` | 能力归一化与实际请求 | 自主实现协议适配，模型来自本项目配置 |
| Nomi `runner/audioActions.ts`、`catalogTaskActions` | 音频任务、结果归一化、生成／转写分流 | 新音频任务分支与错误边界 |
| Nomi `generationNodeExecutor.ts`、`NodeGenerationComposer.tsx` | 引用解析、状态、能力驱动参数 | 当前输入、保存、任务和引用体系 |

BeefTV 的 OpenAI 能力标记 `showPitch/showVolume` 为 false，不能从字段存在就推断参数生效。Nomi 转写输出文本，不能标成音频结果。参考行为与处理逻辑，代码按本项目结构自主实现，不复制 Nomi 的 AGPL 源码。

## 保存、恢复与清理

音频任务提交前保存本地编号，后端持久记录后再向供应商提交。排队、运行、明确失败、查询暂停和结果未确认分别展示；查询原任务不会再次生成，响应丢失或重启不自动新建任务。

复制节点不复用运行中任务编号。素材信息、位置、来源和连线保存到现有画布。旧 `image + mediaKind=audio` 只在读取时迁移，保留 ID 与原连线。新路径验证后清理被替代的创建／预览分支，再搜索残留和验证；保留唯一兼容读取边界。

## 本地接入与当前真实状态（2026-10-10）

用户已批准正式接入。普通与智能画布均加载音频共用组件和各自适配层，原上传入口识别音频后显示播放器、波形、下载、原素材库与拖出操作。音频连接 API 自动适配，平台和模型手动选择；识别结果通过现有 LLM 输入链路传递。纯文字配音从原模型列表选择音频生成模型；音频模型列表可返回原图片选择，无额外模式按钮。

已验证持久任务、幂等、保存失败、响应丢失、重启未知状态、原编号恢复、复制编号隔离、实际页面操作与原图片分支。当前协议的识别仅支持单音频，生成协议不接受参考音频，混合或不支持的输入会明确报错。旧独立生成器和 Prompt 转写草稿已撤回，源码无这些入口。

验收结果和真实截图见[音频节点本地接入验收-20261010.md](音频节点本地接入验收-20261010.md)。实际供应商效果尚未验证；用户整项手动确认前不提交、不上传、不发布。当前本机旧服务尚未载入新增路由，使用前在现有任务结束后重新运行 `run.bat`，再强制刷新画布。
