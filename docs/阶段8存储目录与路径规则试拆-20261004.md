# 阶段 8：存储目录与本地路径规则试拆

日期：2026-10-04  
范围：把存储目录值规范化、存储类型映射和本地媒体 URL 路径解析等无状态规则移到 `backend/storage_paths.py`。本次不移动存储设置文件的锁、JSON 读写、目录创建或 HTTP 路由，不表示阶段 8 整体完成。

## 职责、数据和依赖

| 模块 | 负责 | 不负责 | 数据所有权 |
| --- | --- | --- | --- |
| `backend/storage_paths.py` | 相对目录展开、三类存储目录解析、输出 URL 选择、存储类型映射、相对文件路径越界检查 | 文件读写、目录创建/删除、锁、FastAPI 错误、配置文件和用户数据 | 不拥有持久数据；只处理调用方传入的值 |
| `main.py` | `storage_settings.json` 的读取/原子保存、`STORAGE_SETTINGS_LOCK`、三个生效目录全局变量、路由和 HTTP 错误转换 | 不再重复实现路径规则 | 仍拥有配置文件和运行时目录映射 |

允许依赖方向为 `main.py -> backend.storage_paths`。新模块只依赖 Python 标准库 `os`、`urllib.parse` 和类型定义，不导入 `main.py`、FastAPI、网络客户端或其他业务模块。`main.py` 保留 `_storage_abs_path`、`output_storage`、`output_url_for`、`output_path_for`、`storage_kind_dir`、`storage_file_path` 和 `output_file_from_url` 兼容入口；包装层只提供当前全局目录并把纯规则异常转换为原有 HTTP 状态。

## 兼容边界

- 空目录值仍回退到默认目录；相对值相对 `BASE_DIR`，并继续展开环境变量和用户目录。
- `upload`、`generated`、`local` 三种存储类型和未知类型的 404 行为保持不变。
- 位于 `assets` 内的产物继续生成 `/assets/...`；配置到项目外的目录继续生成 `/api/storage-files/{kind}/...`。
- `/output/` 仍先查当前生成目录，再回退旧的根目录；URL 查询参数、中文/空格编码和路径穿越检查保持兼容。
- 设置文件仍为扁平 JSON `{upload, generated, local}`；原子写入、损坏文件拒绝覆盖、同进程锁和成功保存后才切换生效目录继续由 `main.py` 负责。

## 验证

`tests/test_storage_paths.py` 共 5 项通过，覆盖目录展开和默认回退、类型映射、Windows 路径及 `..` 越界、文件存在性、项目内/外 URL、查询参数和旧 `/output/` 回退。存储设置原子写入 3 项、存储文件引用保护 3 项、素材库删除回归 5 项通过；`py_compile` 覆盖新模块、`main.py` 和专项测试。

所有测试只使用临时目录和自制字节，没有读取或修改真实 `data/`、`assets/`、`API/.env`，没有调用真实供应商。

## 限制与恢复

该模块仍是单进程内的路径规则层，外部进程同时修改目录或文件的协调、目录迁移、素材索引及跨文件事务仍属于后续阶段。若需恢复，只需删除新模块和专项测试，恢复 `main.py` 中对应规则实现并移除导入；存储 JSON 和媒体数据格式无需迁移。
