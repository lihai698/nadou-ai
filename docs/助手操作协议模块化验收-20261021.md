# 助手操作协议模块化验收（2026-10-21）

本批将有限操作的输入模型、解析器和原有协议说明迁入 `backend/canvas_assistant_operation_schema.py`，使工具协议校验不再加载操作执行编排器。主入口媒体导出的一处忙碌判断也改为直接导入公共节点规则。操作格式、严格校验和执行行为不变，整体模块化尚未完成。

## 职责与调用

- 协议模块拥有 9 个操作/计划模型、`parse_plan` 及既有 `OPERATION_GUIDE` 的唯一实现，不执行画布操作、不访问持久化或供应商。通用创建模型及严格操作基类继续复用公共节点规则。
- operations 仍负责候选文档、操作编排、回执编号及差异汇总，导入实际分发需要的操作类型；旧模型、解析器、协议说明和仅用于它们的导入均已移除，没有重复定义或包装转发。
- tools 直接使用协议模块校验操作列表和旧格式回复；会话入口直接使用协议模型，删除其未使用的旧解析器导入；所有相关测试和真实流程 fixture 已迁移。全局剩余 operations 导入只使用 `prepare_operations` 或 `receipt_key`。
- main 的 `control_canvas_assistant_media_export` 直接使用 node_rules.is_busy，函数体及检查顺序不变。这是前两批公共职责迁移的一处遗漏引用，本批补齐。
- 协议层仍复用故事、分析及逐镜领域模块中的数据模型，本批没有进一步拆分这些领域文件，也不宣称消除助手系统所有层间依赖。前端状态、样式、事件、持锁写入及任务服务归属保持原样。
- 知识索引仅更新 main 的两处源码摘要，没有用混合工作区刷新其他来源。
