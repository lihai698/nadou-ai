## 当前分工

| 模块 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| `canvas-save-transport.js` | 保存 PUT、JSON 回包解析、冲突版本检查、智能画布必要的 GET 补读 | 不操作 DOM，不存草稿，不合并节点，不创建任务，不自动重提 PUT |
| `canvas.js` | 普通画布快照、排队、冲突合并、保存状态、已受理任务编号清理 | 不再重复实现本轮迁出的网络分支 |
| `smart-canvas.js` | 智能画布存储归一化、排队、合并、撤销状态、草稿和结果应用 | 不再重复实现本轮迁出的网络分支 |
| `canvas-save-recovery.js` | 原有公共合并、IndexedDB 草稿、跨页恢复和离开保护 | 本轮未改该模块 |

新模块挂在 `globalThis.CanvasSaveTransport`，提供 `saveClassic` 和 `saveSmart` 两个接口。两个 HTML 在主编辑器脚本前加载它，并更新脚本缓存版本。请求正文仍由原编辑器按自身数据字段构造。

## 有意保留的协议差异

- 普通画布成功回包必须有 nodes；409 可读取 detail.canvas 或顶层 canvas，不补读 GET。
- 智能画布成功回包保持原样供编辑器处理；409 缺少完整较新版本时补读 GET，仍不可用则失败。
- 普通画布沿用未编码的原 ID URL，智能画布沿用 encodeURIComponent；不借本轮改变接口行为。
- 普通冲突读取响应处理时的当前版本；智能在冲突 JSON 解析后捕获一次基准版本。
- 智能画布收到 409 时立即调用 onConflict 清除旧排队标记，早于异步 JSON/GET；等待期间的新编辑可重新排队，不被后续取回覆盖。
- 智能 GET 的动态画布 ID 读取时机保持原实现。切页与旧响应隔离仍属于编辑器状态层，本轮没有新增这方面的保证。

两种策略没有强行合成同一规则。失败继续进入原 catch/finally，原保存错误提示、草稿备份、排队和任务编号保留机制继续生效。

## 界面验收

隔离服务使用公开代码和自制空画布，没有私人配置或真实模型调用：

1. 普通画布从节点菜单新建提示词，输入中文，点击返回管理页；列表显示 1 节点。
2. 从列表重新打开，中文全文保留。
3. 智能画布通过节点菜单新建提示词，输入另一段中文，返回列表；同样显示 1 节点。
4. 重开智能画布，中文全文保留；另只读核对两份磁盘 JSON。

截图：`classic-reopened.png`、`smart-reopened.png`。没有重新执行浏览器断网、双页面同时修改同字段或收费任务；这些相关合同仍依赖现有自动回归，本轮不能宣称所有真实环境已验收。
