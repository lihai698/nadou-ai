## 职责与入口

`backend/canvas_assistant_native_service.py` 接管助手与现有原生后端之间的五个完整应用职责：`query_canvas_assistant_native_task`、`control_canvas_assistant_native_task`、`canvas_assistant_workflow_fields`、`prepare_canvas_assistant_media_export`、`control_canvas_assistant_media_export`。原生动作合同与预检继续归既有 native 模块；任务创建、执行、持久化仍使用原来的任务管理器。

main 保留原签名单行适配，将当前目录、读取器、提交入口和运行依赖显式传给新服务。五个完整主体及内部 `usable`、两个 `probe` 嵌套函数的语法树与基线相同，其他 main 语法树不变。新服务没有顶层导入，不持有助手会话，也不直接调用供应商。显式后端依赖仅为 media_export、clip、native、node_rules 四个既有模块。

真实入口仍为 main 注册的助手路由 → 原生动作预检/确认/查询 → main 适配 → 新服务 → 既有原任务。工作流字段按原优先级合并，错误、只读/忙碌/快照门禁与提交顺序保持原样。
