# 阶段 9：文生图历史分页控制器试拆（2026-10-04）

## 范围

本次只整理 `static/zimage.html` 的历史画廊分页状态。生成请求、WebSocket 消息、卡片 HTML、灯箱、删除请求、国际化和页面样式仍由文生图页面入口负责；没有改后端接口、历史 JSON 或用户文件。

## 职责边界

- `static/js/history-page-controller.js` 只管理内存中的历史数组、页大小、当前偏移、加载锁和是否还有下一页。
- 控制器通过 `loadItems()` 接收页面提供的历史读取函数，返回本页条目；不读取 DOM、不调用固定 API、不生成卡片。
- `prepend()` 为 WebSocket 新结果提供去重和偏移调整，`remove()` 在删除卡片后同步内存索引，`invalidate()` 可使正在等待的异步结果失效。
- `static/zimage.html` 继续负责请求错误提示、清空/追加画廊、滚动观察器和卡片结果展示；页面只通过控制器状态判断是否正在加载和是否还有下一页。

控制器在首次加载时读取完整历史并按 15 条切页，后续点击或滚动只切片内存数据，保留原页面追加 400ms 的视觉节奏。重复触发不会并发请求；加载失败会结束加载锁并保留错误，页面可再次执行重置加载。新结果插入已加载列表时会增加偏移，避免下一页重复显示旧卡片。

## 入口与清理

`static/zimage.html` 在页面内联入口之前加载唯一的 `history-page-controller.js`。原来的 `allHistory`、`currentIndex`、`isLoading` 及分页切片实现已删除，`loadHistory()` 只保留页面状态与控制器之间的适配；WebSocket 与 IntersectionObserver 也改为读取控制器状态。

## 验证

- `node --test tests/history_page_controller.test.cjs`：4 项通过，覆盖单次读取和分页停止、重复插入与偏移、并发加载和失败重试、真实 HTML 入口及旧状态清理。
- `node --check static/js/history-page-controller.js`：通过。
- 测试只使用自制内存条目和替身加载函数，未触碰历史文件、私人配置或真实供应商。
