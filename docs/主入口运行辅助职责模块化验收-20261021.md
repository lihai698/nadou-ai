## 失败追踪与修正

首次候选 `c0f985706e0264635475876274de13aba1ffd73b` 的核心检查与助手合同失败，未提交。候选生成器在 Windows 写入 6343 处 CRLF 后按原字节计算 `main.py` 摘要，而生产 `ProjectKnowledge._digest` 会先将 CRLF 转 LF，因而触发“知识来源已变化”的写入保护。

修正仅针对验收候选生成器：源码先统一为 LF，再计算摘要并写入候选 Git blob；没有改变生产知识校验、放宽断言或关闭失败测试。随后对新候选重新执行上述门禁并全部通过。旧失败日志及根因记录保留在本地证据中，不与新候选成功结果混称。

静态同步合同会实际原子写入 HTML，文件修改时间属于缓存版本输入。fixture 在真实写入后固定测试文件 mtime，再比较完整响应/文件字节；不修改业务逻辑，也不归一输出。loopback 端口每次随机，先断言返回地址确属该次配置，再记录配置索引和完整请求顺序。
