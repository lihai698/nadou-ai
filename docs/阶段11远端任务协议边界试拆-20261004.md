# 阶段 11：远端任务提交、查询与取消协议边界试拆

日期：2026-10-04  
范围：图片、视频和 ComfyUI 任务的供应商适配边界。只使用本地纯规则和测试内存模拟，不连接真实或收费供应商。

## 本轮做了什么

新增 `backend/remote_task_protocol.py`，把各适配器共同需要的判断集中为低依赖纯规则：

- `normalize_remote_status` 将 `SUCCESS`、`COMPLETED`、`PROCESSING`、`CANCELLED` 等常见文字归一为 `succeeded`、`running`、`cancelled`；未知文字和缺失状态归为 `unknown`。
- `observe_remote_task` 区分提交、查询和取消。查询端点的 404、408、429、5xx、网络中断只产生 `unknown`，不会伪装成失败；提交收到明确 4xx 才产生已确认的 `failed`。
- `remote_task_decision` 永远不建议自动重新提交，并保留原远端编号。已确认终态不会因一次后续查询故障被覆盖。
- `local_stop_decision` 明确表示浏览器停止只停止本地等待，不代表远端取消。
- `provider_task_contract` 给出保守能力声明：OpenAI 兼容、APIMart、火山等已有查询适配器的图片/视频任务可查询；RunningHub 使用适配器自己的 POST 查询；即梦使用专用适配器；ComfyUI 的本地记录不冒充远端查询。所有内置供应商默认 `supports_cancel=False`。
- `submission_summary` 只保存供应商、类型、远端编号和能力摘要，不保存原始提示词、工作流或原始回包。

## 为什么先做纯协议层

现有视频适配器仍把提交和同步轮询绑在同一请求中，图片适配器也有多套供应商状态字段。直接给界面增加“取消”按钮会把浏览器中止误报为远端取消。先用统一观察结果约束每个适配器，可以逐家拆出“提交 → 取得编号 → 查询”，并且在没有供应商确认时保留 `unknown` 边界。

本模块不发网络请求，也不改变现有 `main.py` 路由，因此不会自动声称现有供应商已经支持取消或重启后远端续查。后续接入某一供应商时，适配器必须显式提供查询方法、编号提取和取消确认响应，再把结果转换为这里的观察对象。

## 验证

`tests/test_remote_task_protocol.py` 共 9 项通过，覆盖：

1. 图片、视频、ComfyUI 共用的状态归一化；
2. 提交编号提取和最小受理摘要；
3. 网络中断、查询 404、5xx 的未知状态及禁止自动重提；
4. 提交明确拒绝与提交超时的区别；
5. 已确认终态不被后续查询故障覆盖；
6. 本机内存模拟的提交 → 查询 → 完成闭环；
7. 各供应商查询能力和 ComfyUI 本地边界；
8. 本地停止等待的语义；
9. 只有显式取消响应才允许得到 `cancelled`。

运行命令：

```powershell
python\python.exe -m unittest discover -s tests -p 'test_remote_task_protocol.py' -v
python\python.exe -m py_compile backend/remote_task_protocol.py
git diff --check
```

## 尚未完成的边界

- 内置供应商没有被声明为支持远端取消；只有以后获得明确接口和回执后才能设置 `supports_cancel=True`。
