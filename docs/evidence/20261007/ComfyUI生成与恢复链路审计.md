# ComfyUI 生成与恢复链路审计（2026-10-07）

## 结论

普通画布和智能画布的 ComfyUI 任务入口、任务编号保存、查询重试、页面刷新恢复、服务重启后的未知状态和结果回填均已有本地回归覆盖。本轮发现并修复了一个保存边界：生成已经成功但最终任务记录写入函数抛出异常时，worker 不再把 `succeeded` 非法转换成 `failed`；本进程继续保留可回填结果，重启后仍按磁盘中的运行记录保守显示 `unknown`。

## 本轮修改

- 将 ComfyUI 任务 worker 生命周期移到 `backend/comfy_task_service.py`；`main.py` 保留兼容包装和路由，后续入口可以复用同一任务服务边界。
- `main.py::_run_canvas_comfy_task` 将生成异常和成功结果写回分开处理。
- 失败记录再次写盘失败时只记录脱敏诊断，不让 worker 因二次写盘异常崩溃。
- 成功结果写盘失败时保留内存中的成功结果，不执行 `succeeded -> failed` 的非法状态转换。
- 未改变 `/api/canvas-comfy-tasks` 路径、任务记录字段、旧画布格式或 ComfyUI 工作流协议。

## 验证结果

- Python ComfyUI/画布任务专项：16 项通过。
- JavaScript 普通画布、智能画布 ComfyUI 轮询与恢复：31 项通过。
- 覆盖成功、明确失败、超时、连接中断、查询重试、持续查询故障、页面刷新、服务重启、保存失败、缓存丢失和重复查询不重复生成。
- `py_compile` 与 `git diff --check` 通过。

## 当前边界

- 当前使用模拟 `generate`，没有连接真实 ComfyUI，也没有把模拟结果当成真实服务验收。
- 记录写盘持续失败并在服务重启后，任务会保守显示 `unknown`；这是为了避免把未持久化的结果误报为已保存成功，后续需要在真实 ComfyUI 可用时再验证结果文件与任务记录的恢复策略。
- 长期压力、磁盘写满、macOS 和真实用户目录升级按计划放到最后。
