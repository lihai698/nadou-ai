# 图片批量查询汇总规则拆分（2026-10-07）

## 范围与职责

- `backend/task_states.py::image_batch_outcome` 只根据已记录的上游状态和是否已有图片，返回 `succeeded`、`partial`、`failed` 或 `unknown`；不查询供应商、不读写任务记录，也不修改传入列表。
- `main.py` 的图片查询入口继续负责供应商请求、结果合并、错误摘要和持久化；它只把最终状态列表交给纯规则，再按结果写入原有任务记录。
- `partial` 仍使用本地任务的 `succeeded` 状态并保留成功图片，同时保留“部分上游编号失败”的提示；存在未确认编号时保持 `unknown`，不自动重提。

## 保持的行为

全部成功返回成功；全部失败且没有图片返回失败；已有图片而其余编号全部进入终态时保留已有图片并返回部分成功；只要仍有 `running`、`queued` 或 `unknown`，就继续保持未知状态。空状态列表也不会被误判为成功。

- `tests/test_canvas_image_remote_query.py` 覆盖真实查询入口的双编号成功、部分失败保留图片、配置变化和重复查询边界。

## 后续边界

供应商响应解析和页面轮询仍由 `main.py` 组织。本次只固定批量汇总规则；下一步先审计一个供应商状态组装入口的输入、输出和未知状态处理，再决定是否抽取，避免把供应商协议误合并进本地任务状态模块。

真实供应商、macOS、长期压力和磁盘不足场景不属于本轮验证结论。
