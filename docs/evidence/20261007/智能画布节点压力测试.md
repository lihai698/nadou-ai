# 智能画布节点压力测试（2026-10-07）

在 `output/node-stress-20261007/app` 的隔离副本、`127.0.0.1:3017` 上测试；未修改 3000 端口的用户画布。每组 100、300、500 个节点，提示词与图片节点各半，每两节点一条连线；图片重复引用一张自制 320×240 PNG。浏览器视口为 1110×808。未调用生成供应商。

| 节点 / 连线 | 页面出现全部节点的观察时间 | 优化前完整重绘 | 优化后完整重绘（三次） |
| --- | ---: | ---: | ---: |
| 100 / 50 | 约 0.93 秒 | 134 毫秒（一次） | 91、87、93 毫秒 |
| 300 / 150 | 约 1.44 秒 | 396、286、286 毫秒 | 260、254、251 毫秒 |
| 500 / 250 | 约 1.85 秒 | 586 毫秒（一次） | 459、420、437 毫秒 |

“页面出现全部节点”是导航后观察到节点的上界，包含自动化调用延迟，不等于精确可交互时间。重绘是在真实页面直接调用现有 `render()` 测得，浏览器进程和缓存未重置，因此这些数值用于判断量级，不当作严格的版本对照或性能承诺。

优化后各进行一次真实指针拖动，在约 1.6 秒的采样窗口里，100 / 300 / 500 节点分别有 4 / 11 / 10 个帧间隔超过 33 毫秒，最大间隔分别为 67 / 133 / 167 毫秒。500 节点页面保存耗时 412 毫秒；刷新后仍有 500 个节点、250 条连线和修改后的中文提示词。直接 HTTP 保存 500 节点的三次耗时为 478、139、108 毫秒。分组测试确认两条指向同组成员的连线仍合并成一条，组内连线仍隐藏。核心回归检查通过：Python 462 项、JavaScript 208 项。

本次只消除了重绘和连线计算中的重复全量查找，没有改动节点格式、保存协议或生成流程。100 节点基本可用，但单次拖动仍可能有短暂停顿；300 节点以上存在明显卡顿风险，500 节点尚不能宣称流畅。大量不同高清图片、视频节点、并发生成和长时间运行没有覆盖。若实际创作经常达到 300 节点以上，需要单独设计可见区域渲染与连线更新；不应以这次局部优化冒充完整解决。
