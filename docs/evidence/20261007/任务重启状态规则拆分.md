# 任务重启状态规则拆分（2026-10-07）

## 范围与职责

- `backend/task_states.py::interrupted_task_update` 是纯规则：接收已校验的记录、当前进程编号、时间和提示，返回需更新的字段；不读文件、不取系统时间、不提交或查询任务。
- `backend/task_records.py::mark_interrupted_task` 保留既有兼容入口，负责校验、提供默认时间、复制旧记录并应用规则。原内联状态判断已删除，不保留第二套实现。
- 真实入口继续为 `main.py::_interrupted_canvas_task` → `mark_interrupted_task` → `interrupted_task_update`；发生变化后仍由入口负责持久化。没有更改 HTTP 接口、锁、记录格式或视频所有者协调。
- 依赖方向为入口 → 记录适配 → 纯状态规则，无反向导入 `main.py`。

## 保持的行为

异进程或缺少进程编号的 queued/running 记录变为 unknown；同进程记录、succeeded、failed、jimeng_pending 和已有 unknown 保持不变。原输入不变，旧字段、单个/多个远端编号及部分结果保留。错误文字为空时使用既有提示，最长仍为 600 字。

重启转换不复用运行中失败转换：后者可能清空 result，重启判断必须保留部分结果。纯规则不负责证明其他进程死亡，继续沿用既有单实例前提。

## 使用及回退

工作目录仍双击 `run.bat`，已运行的服务需正常退出后重新启动以加载代码。本轮不对外发布，也不重建现有 ZIP；旧 ZIP 保持上一轮版本，尚不含此次内部重构。回退只需恢复此次两个后端文件改动，不需要迁移任务数据。既有未提交修改必须保留。

真实供应商、macOS、长期压力和磁盘不足场景不属于本轮验证结论；界面没有改动。
