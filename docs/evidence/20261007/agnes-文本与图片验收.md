## 视频最小请求（2026-10-07 补验）

使用当前 API 设置中的第一个视频模型 `agnes-video-2.5`，通过持久任务入口 `POST /api/canvas-video-tasks` 提交一次 5 秒、16:9、480p 的纯文字请求。任务先进入 `queued`，随后上游返回 HTTP 400：`invalid_request`、`width is a forbidden field`。本地记录最终为 `failed`，没有远端任务编号、视频结果或可刷新编号。请求已被明确拒绝，因此没有使用原编号重提，也没有尝试第二个模型。

这证明现有 Agnes 视频请求体至少有一个字段不符合供应商协议，不能把它归因为模型不可用。当前实现的 `generate_agnes_video` 向 `/v1/videos` 发送 `width`、`height`、`num_frames`、`frame_rate`；这些字段来自旧实现，仓库内没有可核对的 Agnes 视频请求规范。公开 `/docs`、`/openapi.json` 入口也没有返回可用规范。在获得供应商的请求示例前，不按猜测改字段或再次真实提交。视频结果尚未通过验收，页面应以本地失败状态为准。

其它 Agnes 文本和图片模型未逐个尝试，模型可用性仍须逐项验证。

## Agnes 视频协议公开入口复查（2026-10-07）

使用本机已配置令牌但不输出令牌值复查供应商入口：`GET /v1/models` 返回三个视频模型（`agnes-video-2.5-flash`、`agnes-video-2.5`、`agnes-video-v2.0`），它们都标记 `supported_endpoint_types: ["openai"]`；`/docs` 和 `/openapi.json` 仍返回 HTTP 403。对 `/v1/videos` 使用无效模型做字段探测只返回 `model_not_found`，没有返回请求体 schema，也没有提交真实任务。因此仍不能据此推断 `size`、`seconds` 或其它字段，视频实现保持当前明确失败边界。

## 空回复状态修复

画布文本、普通对话、Agent 文本、流式对话和素材图片说明原先会把上游空内容保存或返回为“接口返回了空回复。”的成功结果。现在非流式入口返回 HTTP 502；流式入口发送错误事件并停止，不写入假的助手消息。`content: null` 也视为空回复；正常文本及 APIMart 包装的回复继续可用。用户已输入的对话消息保留，便于重试。CLI 分支和上游错误摘要规则没有改动。

`tests/test_chat_empty_response.py` 使用模拟上游覆盖上述失败、正常文本兼容、对话落盘、流式事件及真实 ASGI 路由，共 5 项通过。完整核心检查在新增 HTTP 路由用例前通过 Python 431 项、JavaScript 176 项；补充用例单独通过。重启本地 3032 测试服务后，Agnes `agnes-3.0-flash` 再次返回 HTTP 200 与非空文本，普通画布和聊天页面均返回 HTTP 200。真实 Agnes 空回复没有发生，因此该故障行为由模拟测试验证。

发布验收命令补验：在干净发布目录直接使用包内 Python 运行 `verify-release-startup.py`，按预期报告缺少已安装依赖；保持发布目录原样，改用已安装依赖的项目 Python 加 `--python` 验证同一目录则通过，根页和静态页均返回 HTTP 200。原文档要求在发布目录安装依赖后再验证，但安装会产生清单外文件，现已改为“干净目录清单与启动检查”加“隔离解压 ZIP 首次安装检查”两步。

继续检查上传失败路径：角度控制和细节增强页在替换图片时原先保留旧 `uploadedPath`，新图上传失败后可能用旧图生成；图片编辑页则把失败上传的原文件名误当成 ComfyUI 已接收的文件名。本轮均改为提交前清除旧上传名、检查 HTTP 状态和返回字段，并忽略较慢的旧上传结果。细节增强失败会清掉预览；图片编辑本地模式在参考图上传未完成或失败时停止生成，云端模式仍可使用已读取的原图。`tests/simple_upload_pages.test.cjs` 5 项和 `tests/klein_upload_state.test.cjs` 3 项通过；完整核心检查 Python 432 项、JavaScript 187 项通过。三个页面在本地 3032 服务均返回 HTTP 200；没有向真实 ComfyUI 提交生成任务，实际 UI 点击流程仍待人工页验。

## 外部素材工具默认端口修正

审计发现 Photoshop 资产面板和 Chrome 本地素材扩展仍把 `127.0.0.1:8767` 写成默认地址，而当前 nadou ai 后端默认监听 `127.0.0.1:3000`。这会让用户按默认值连接失败。本轮已统一默认值、README 启动命令和端口示例；`tests/connector_default_port.test.cjs` 通过，两个工具脚本语法检查通过。

同时修正了新手教程中与当前访问控制不一致的局域网说明：默认服务只监听本机；局域网访问必须显式配置 `NADOU_BIND_HOST` 与 `NADOU_ACCESS_TOKEN`。两个外部素材工具目前只保证本机未启用令牌时可用，文档已明确这一限制，避免误以为它们已支持远程令牌登录。

另发现 macOS 启动脚本默认打开局域网 IP，但默认绑定实际是本机地址，已改为按 `NADOU_BIND_HOST` 选择本机或局域网地址；默认启动会打开 `127.0.0.1:3000`。本机没有 macOS 环境，脚本仅完成静态检查，未宣称实机验收。

新增启动脚本回归后，核心检查夹具同步纳入公开的 `run.bat` 和 `mac-启动服务.sh`；完整核心检查现为 Python 434 项、JavaScript 198 项通过。
