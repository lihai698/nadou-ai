# 视频任务完整链路审计（2026-10-07）

## 结论

当前普通画布和智能画布的视频任务链路已经有可验证的本地保护：同一客户端编号只提交一次；上游受理编号会在长轮询前落盘；断线、服务重启或查询失败不会自动重新提交；显式远端失败才会落盘为 `failed`；刷新结果保存失败会保留原编号和 `unknown` 状态，后续仍可按原编号查询。

本次没有发现需要立即修改生产逻辑的可复现缺口，因此没有为了缩短 `main.py` 的 `canvas_video` 入口而重写流程。真实视频供应商协议、真实 ComfyUI、macOS、长期压力和磁盘写满仍未验收，不能把本地模拟结果当成这些环境已通过。

## 已核对的链路

1. 普通画布和智能画布都先保存任务编号，再开始查询。
2. 后端 `/api/canvas-video-tasks` 以客户端编号作为幂等依据，重复 POST 返回已有记录。
3. 供应商回调取得远端编号后先写入 `remote.task_id` 和 `upstream_task_id`。
4. 查询入口只使用原远端编号，不调用新的提交入口。
5. 外进程运行中的任务只给查询方保守的 `unknown` 视图，不覆盖运行方的磁盘记录。
6. 明确失败、查询未知、任务记录不存在和保存失败分别保留不同提示，页面保留查询/恢复操作。
7. 任务公开结果经过白名单过滤，不回显 prompt、原始供应商回包或密钥字段。
