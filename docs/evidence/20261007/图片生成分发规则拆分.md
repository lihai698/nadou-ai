# 图片生成分发规则拆分（2026-10-07）

## 目的

固定 `generate_ai_image` 的供应商分支优先级，为后续新增供应商提供唯一的分发入口。此次只处理路由判断，不移动供应商 HTTP 请求、远端轮询、结果下载或文件保存。

## 当前规则

分发顺序保持原行为：

1. ModelScope
2. Codex
3. Gemini CLI
4. 即梦
5. RunningHub
6. Gemini 协议
7. 方舟/Volcengine
8. 土豆异步图片
9. 土豆 Grok 图片
10. 通用 OpenAI 图片接口

土豆模型名仍在进入分发前按原规则规范化。供应商适配函数和错误语义没有移动，也没有新增真实供应商请求。

## 修改

- 新增 `backend/image_generation_dispatch.py`，只依赖传入的供应商能力判断，不反向导入 `main.py`。
- `main.py::generate_ai_image` 保留原入口和参数，负责组装旧辅助函数与适配器，分发结果仍调用原供应商函数。
- 新增 `tests/test_image_generation_dispatch.py`，覆盖专用供应商优先级、协议回退顺序、土豆分支顺序、短路判断和通用分支。

完整核心检查仍需在当前改动集合上执行；真实供应商和真实 ComfyUI 仍按计划由用户在可用环境中手动验收。

## 后续边界

下一步只有在新增供应商或现有分支修改确实受阻时，才继续拆“远端图片任务状态解析”或“结果保存”完整边界。暂不拆通用 HTTP 请求，也不重写 `generate_ai_image`。
