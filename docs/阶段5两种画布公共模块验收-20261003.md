# 阶段 5：两种画布共用保存与读取验收

结论：在 `3021` 隔离服务中，普通画布和智能画布均通过真实页面编辑、自动保存、刷新重开。两种页面共用 `main.py` 的 `/api/canvases/{id}` 保存与读取路由；本次没有发现该共用路径引起的数据串写或素材丢失。原始字段和哈希见[证据](evidence/20261003/stage5-shared-canvas-ui.json)。

| 页面 | 打开前 | 页面修改 | 刷新后页面与磁盘 |
| --- | --- | --- | --- |
| 普通画布 | 4 节点、3 连线，中文提示词，参考图 | 提示词改为“阶段五普通画布：共享接口保存中文提示词。”，分辨率选 2K，比例选 3:2 | 4 节点、3 连线及图片仍可见；提示词、2K、3:2 保留；API 回读与磁盘 JSON 一致 |
| 智能画布 | 3 节点、1 连线，中文提示词，参考图，循环次数 3 | 提示词改为“阶段五智能画布：共享接口保存中文提示词。”，循环次数选 4 | 3 节点、1 连线及图片仍可见；提示词和次数 4 保留；API 回读与磁盘 JSON 一致 |

两页引用同一张自制 32×24 PNG；刷新后浏览器均解码出 32×24 像素，HTTP 返回文件与隔离源文件逐字节一致。两份画布的节点 ID 和连接端点均与各自打开前相同，画布列表同时包含两份记录。界面截图已目视检查，未另存文件。

隔离目录为 `output/acceptance-20261003/stage5-shared-data`，端口 `3021`；未使用私人素材或真实生成服务。准备和复核脚本留在同一隔离目录的上级，运行 `python\python.exe output\acceptance-20261003\stage5_shared_prepare.py` 创建全新样例，启动隔离服务后运行 `python\python.exe output\acceptance-20261003\stage5_shared_verify.py`。准备脚本会拒绝覆盖已有样例。

此项覆盖共用保存与读取入口对两种画布的当前影响，以及两种编辑器各自的一个参数组合。真实供应商、旧版本画布、其他节点类型、删除保护和任务故障分别由阶段 5 其他验收项负责；本项未修改业务代码，也没有替换旧实现。
