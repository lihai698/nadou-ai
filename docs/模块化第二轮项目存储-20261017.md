## 职责与接口

| 位置 | 拥有的职责 | 保留边界 |
| --- | --- | --- |
| `backend/project_store.py` | 项目文件业务读写、格式验证、原子保存、默认初始化、新建项目 | 不读取画布，不处理 HTTP，不持有主程序全局状态 |
| `backend/project_records.py` | 项目公开摘要、排序键和下一个排序值 | 继续作为纯规则模块，无文件操作 |
| `main.py` | 注入当前 PROJECTS_PATH、同一把 CANVAS_LOCK、时钟和 ID 工厂；把读取失败转换为原 HTTP 状态 | 列表计数、项目更新业务规则、项目删除时的画布迁移仍在原入口 |

公开存储接口为 `ProjectStore.load/save/ensure_default/create`。路径和可重入锁由入口提供；每次构造不缓存项目记录，因此更换存储路径、测试隔离和重读磁盘不会留下旧副本。

四个旧函数 `load_projects`、`save_projects`、`ensure_default_project`、`new_project` 保留为薄兼容入口，因为现有路由和测试仍使用它们。它们不再包含 JSON 读写、默认项目构造或新项目算法；待调用方统一迁移到明确的应用服务入口后才考虑移除包装。

原 `projects_and_version` 和 `next_project_order` 在主程序中的专用导入已清理。新模块没有反向导入 `main.py`。项目文件的正常业务写入只存在于 ProjectStore，备份恢复工具仍按其独立维护职责处理文件。

## 保持的行为

- 缺文件只读时返回空列表，不创建文件；需要默认项目时才初始化。
- 兼容旧顶层数组与当前带版本对象；记录内部未知字段保留，无有效 ID 项仍按旧规则过滤。
- 坏文件返回原 500 说明，未来版本返回原 409 说明，并拒绝覆盖。
- 默认项目名称、名称截断、排序递增、ID、时间戳和公开响应字段不变。
- 锁内读改写、嵌套默认初始化和可靠写入继续使用现有可重入锁与 atomic_json。
- 原子替换失败时，已有有效项目文件不变，不返回新建成功。
- 项目删除时画布迁移与项目索引写入的先后顺序保持；失败后仍可以按原入口重试。

这不是新增跨文件事务：如果原先没有默认项目，新建流程会先保存默认项目，之后新项目保存失败时默认初始化可能已经完成。顶层未知字段保存时不保留、跨进程读改写未统一，也是原有边界。本轮不改变这些行为。

## 界面验收

隔离服务仅含公开代码与自制画布：

1. 从工作台新建“二轮验收 中文项目”。
2. 重命名为“二轮验收 保存重开”。
3. 在新项目创建“项目归属验收画布”，项目计数变为 1。
4. 刷新后项目名称、计数、画布和归属均保留；默认项目的两种原有画布仍在。
5. 停止并重启同一隔离服务，以真实项目/画布接口核对，项目名称、画布归属和计数仍一致，默认项目没有重复创建。
