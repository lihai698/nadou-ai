## 职责与依赖

| 位置 | 职责及数据归属 |
| --- | --- |
| `static/js/canvas-remote-sync.js` | 通知过滤、版本轮询、完整画布请求、同步延迟；各控制器独立拥有计时器和轮询状态 |
| `canvas.js`、`smart-canvas.js` | 提供当前编辑状态，执行原生节点合并、冲突副本、界面更新及任务续查 |
| 两种画布 HTML | 在编辑器入口前加载公共模块 |

模块通过宿主注入的 `getState/request/apply` 等函数协作，不读取编辑器私有全局变量，不直接写节点、草稿或磁盘。普通画布与智能画布分别使用 `createClassic/createSmart`，保留不同的保存保护、交互保护、轮询周期、URL 编码和错误提示方式。

旧五个计时/忙碌全局变量以及旧私有 check/stop/schedule 函数已移除；搜索 static 和 tests 未发现残留引用。助手、iframe 和加载流程使用的 sync/start/handleMessage 薄入口仍保留，职责只有委托，不保留第二份同步实现。

## 双页面验收

使用仅复制公开代码的临时服务、独立端口和自制中文提示词节点，不使用私人画布或真实模型。

两种画布均执行：

1. 两页打开同一画布，编辑与保存可传播到另一页。
2. 测试服务仅让页面 B 的 PUT 返回 503，页面 B 输入未保存中文文字。
3. 页面 A 修改同一节点并成功保存；页面 B 收到远端更新后，两份文字同时存在，本地文字保留为冲突副本。
4. 直接检查隔离磁盘记录，确认此时 B 的文字尚未写入服务器，排除“其实已保存”的误判。
5. 解除测试故障，点击 B 的“重试保存”，检查两份文字均写入磁盘。
6. 刷新重开，页面仍显示两份文字，保存失败提示消失。

普通画布还实际触发了并发保存 409，并保留两份编辑。测试服务的页面标识记录和单页故障注入仅位于 `.git/modularization/preview.py`，不属于产品代码。

截图和结果位于 `output/canvas-remote-sync-20261018/`：`classic-reopened.png`、`smart-unsaved-preserved.png`、`smart-reopened.png`、`result.json`。验收服务在结束后停止。
