# 两种画布的框选、分组与工作流工具栏方案

日期：2026-10-21。状态：已接入两种正式画布，隔离页面验证通过，等待用户验收。

## 目标与现有功能结合

普通画布与智能画布使用同一套操作规则。继续使用各自的节点、模型配置、任务恢复、撤销与画布保存能力。ComfyUI、RunningHub 等已经配置好的工作流仍是原生执行节点，分组不改写它们的配置。

需要调整的现有行为：

- 普通画布 `canvas-interaction.js:finishSelection` 在 Ctrl 框选结束后直接调用打组，无法停在临时选区状态。改为只框选，点击按钮或 Ctrl+G 才正式打组。
- 普通画布 `canvas-group-edit.js` 对素材分组会把成员的输入连接转接到组节点。新正式框组不转接连线，保证原制作路线不变。
- 智能画布 `smart-group-edit.js:groupSelectedNodes` 会吸收图片、删除独立图片节点并整理缩略图；这不适合本次要保留原节点、自由编辑的工作组。
- 智能画布 `isSmartGroupCompactMember` 会把组内提示词折成小卡片，`smartGroupScopeId` 会隐藏组内连线。新正式框组保留完整编辑界面和内部连线。
- 保留现有素材卡片分组、历史输出分组与对应专用功能。旧画布打开时不自动拆散、重建或改写旧组。

新工作组复用原生 group / smart-group 节点，使用明确的分组模式区分框组和素材卡片组，记录成员 ID、名称、颜色和边框范围。共用布局、选区工具栏、执行计划和导出内容收集；两边通过各自入口调用原生操作。

三种对象不能混淆：临时选区只是一批当前选中的节点；正式工作组是保留独立成员的画布框组；原有素材分组是带缩略图、预览与宫格拼接等功能的独立节点。原有素材分组的整理、预览、拼接、下载与解散功能不被工作组工具栏替换。

## 两个状态

### 临时框选

Ctrl / Cmd 按住拖动框选；保留 R 框选。松开后选区保留，工具栏在选区上方居中，包含打组、批量下载、布局。点击工具栏与松开修饰键都不清空选区。

在临时框选状态下，拖动选区整体移动节点，点击成员不能误入单个节点编辑。点击真正的画布空白区域才取消框选，之后恢复单节点操作。

### 正式分组

打组时保留原节点尺寸、位置、参数和连线，不自动宫格重排，也不把图片收进缩略图卡片。框上显示组名；组工具栏包含颜色、布局、整组执行、创建工作流、解组。保留批量下载入口，放入组操作菜单，避免组工具栏过长。

拖动组框空白区域或组标题移动整个组；拖动成员的原生拖动区域只移动该成员。提示词可直接编辑，图片、视频、音频及各自工具栏继续正常操作。点击组内节点时保留所属组的上下文，组级操作与节点级操作分开定位。

点击画布空白区域仅取消选中，正式组仍保留。解组只移除框组，成员、素材、结果、配置和连线保留。

正式工作组使用不透明底色，遮住画布网格，默认与整体 UI 协调的中性灰，深色主题用炭灰、浅色主题用浅灰。颜色选择只给底色加入低饱和色调并改变边框与标识，不影响成员原有颜色、图片、视频或连线含义。临时框选保持透明，与正式组一眼可分。

## 总端口与上下游连接

临时选区与正式工作组都在左右两侧中部显示与本项目一致的圆形输入、输出端口。

临时选区右端口拖到现有下游或空白区域新建下游时，先验证完整批量连接，再为各成员建立各自到下游的连线；成功后取消临时选区及工具栏，不创建任何隐藏分组节点。取消拖线、建立节点失败或连接不兼容时保留原选区。左端口反向连接上游时遵循同样的批量规则。一次操作只增加一个撤销记录。

正式工作组右端口连接下游时，保存和显示一条组到下游的连线，工作组和成员保留。运行时按成员顺序汇总文字、图片、视频、音频及生成结果，按照下游原本支持的输入类型传递。相同素材去重，成员内容更新后，下游读取当前成员内容。组内连线和节点原本的独立连线不被替换。

正式工作组左端口接上游时，同样保存一条上游到组的连线，输入依据成员原生类型传递到可接受输入的成员，不能给不支持的节点强塞数据，也不能重复覆盖已有内部依赖。组与组连接使用相同规则，检查自连接、间接循环和重复引用。

正式组解组时，组端口的外部连线展开为成员对应的原生连线，保留有效上下游关系；不能只删除组节点而丢失所有总线连接。输入类型不兼容的操作应在改变状态前明确指出原因，不能悄悄连接一部分并取消选区。

## 快捷键与交互边界

| 操作 | 规则 |
| --- | --- |
| Ctrl/Cmd + 框选 | 临时选区，不自动建立正式组 |
| R + 拖动 | 保留现有框选入口 |
| Ctrl/Cmd + G | 正式打组，与工具栏调用同一入口 |
| Ctrl/Cmd + Shift + G | 解组，两种画布一致 |
| Ctrl/Cmd + Z / Shift + Z | 使用原有撤销与重做 |
| Shift 切线、Alt 拖动复制 | 保留既有功能 |
| 文本输入时的快捷键 | 不抢占输入框、提示词、名称编辑等控件的键盘操作 |

多选包含已有组时，把组当作整体处理，避免组成员被重复移动。连续点击、重复初始化、切换画布后不能重复绑定事件。

## 三种布局

- 水平：全部节点排成一整行，上游在前、下游在后；独立节点按当前阅读顺序排列。
- 垂直：全部节点排成一整列，上游在前、下游在后；独立节点按当前阅读顺序排列。
- 宫格：根据数量和实际节点尺寸计算行列与间距，保持稳定的路线与阅读顺序。

三种布局同时提供给临时框选与正式组，均要对齐节点、避免重叠、统一间距并尽量减少交叉。只改变位置，不改变节点尺寸、图片比例、提示词、生成参数和连线。正式组的布局只整理组内节点，并同步组框范围；临时选区布局不隐式打组。现有按连线自动整理功能保留；三种布局遵守所选方向，在此基础上利用依赖确定合理的先后顺序。

一次布局产生一个撤销记录。布局后保持选中，工具栏不漂移到屏幕外；缩放、平移后仍在合理位置。布局计算使用节点实际尺寸，避免提示词、图片和视频大小不同造成遮挡。

## 整组执行

点击后先检查组内所有可执行节点及依赖，完整检查通过才提交任务。静态素材和普通提示词提供输入，启用 LLM 的提示词节点和各类生成节点使用原生执行入口。ComfyUI 节点继续调用原本配置好的本地工作流。

将所有成员的内部依赖合并成一个执行计划：上游成功后才运行下游；多条独立路线都执行，共用上游只执行一次；不能对每个末端分别追溯重跑，从而重复生成、重复计费。原生循环节点沿用循环语义，不能当作普通静态节点跳过。

仅执行当前组内的生成节点。组外现成素材可以作为输入，组外生成节点不会被无声触发。缺模型、缺输入、循环依赖或原任务仍未结束时明确定位问题节点。失败路线停止向下执行，其他独立路线有各自的状态记录。

工具栏显示整体进度并在运行期间变为停止入口。停止阻止新任务继续提交；已受理任务沿用原有查询和恢复规则。刷新、切换画布或收到旧轮询响应都不能启动下一步或把旧结果冒充新结果。

## 批量下载与创建工作流

批量下载收集选区或组内的图片、视频、音频与文本。文本按节点标题保存 UTF-8 TXT，生成 ZIP 一次下载。重复文件名添加编号；不能读取的素材要明确列出，不伪装成全部成功。不以 HTTP 200 代替真实浏览器下载事件和 ZIP 内容验证。

创建工作流弹出名称与封面选择，保存为本项目的原生节点组合，复用现有 `/api/canvas-workflows/export-to-library` 与素材库索引。封面可从已有图片选择或上传。保存后可在素材库的工作流管理、画布资产库中查看和引用。

模板包含节点、内部连线、必要参数和素材资源；不保存正在执行的任务或后台受理编号。引用时生成新节点 ID 并重映射成员、连线、分镜映射和素材引用，不影响原模板和原组。普通与智能模板继续使用各自的节点类型，类型不匹配时使用现有明确的导入规则，不自动猜测转换。
