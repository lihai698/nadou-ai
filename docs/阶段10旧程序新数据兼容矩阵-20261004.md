# 阶段 10：旧程序与新数据兼容矩阵

## 已确认的规则

当前格式版本为 `1`，没有 `format_version` 的旧画布和项目文件按版本 `0` 读取。当前程序可以读取旧画布、旧项目数组，并在成功写回时补上版本标记；遇到大于 `1` 的版本会拒绝读取和写入，保留原文件字节。

| 数据 | 当前程序读取旧数据 | 旧程序读取版本 1 数据 | 处理方式 |
| --- | --- | --- | --- |
| 画布对象 | 可以，缺少标记按 v0 | 可以，版本字段是附加字段 | 写回时标记 v1；恢复前仍保留备份 |
| 项目文件数组 | 可以，按 v0 | 可以，数组形状不变 | 写回时包装为 `{format_version: 1, projects: [...]}` |
| 当前项目文件包装对象 | 可以 | **不可以**，旧入口只接受顶层数组 | 升级前保留代码恢复点；需要回退时同时恢复数据或使用旧格式副本 |
| 未来版本对象 | 不可以 | 未知 | 返回受控冲突，不覆盖原文件 |

## 验证证据

`tests/test_data_format_migration.py` 的格式规则测试覆盖：

- 旧画布、旧项目数组和当前版本对象可以被当前程序读取；
- 旧程序形状读取器可以读取带附加版本字段的画布；
- 旧程序形状读取器不能读取当前项目包装对象，这个限制被明确记录，不把“当前程序可读旧数据”误称为双向兼容；
- 未来版本、非法版本和损坏 JSON 拒绝读取，原文件字节保持不变；
- 画布和项目真实 HTTP 保存入口从 v0 写回 v1，项目删除的跨文件失败可安全重试；
- `tools/check-data-formats.py` 与目录快照 CLI 的隔离检查可在新目录复核格式和 SHA256。

测试只使用临时目录和自制 JSON，不读取真实画布、历史、素材或 API 配置。旧程序兼容性结论针对仓库中确认的旧容器形状；没有旧版本二进制参与测试时，不宣称完整运行时兼容。

## 回退步骤

1. 停止服务，保留当前目录和诊断日志。
2. 用 `tools/backup-restore.py verify` 校验升级前快照。
3. 从代码恢复点切回旧程序，并用 `restore` 把快照恢复到新的隔离目录；不要让旧程序直接改写当前 v1 项目包装对象。
4. 在独立端口和独立数据目录验证后，再决定是否切换正式目录。
