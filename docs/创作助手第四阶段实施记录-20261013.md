# 第四阶段：简洁交互与后台执行

本轮范围：精简已有助手界面和回复规则，保留后台读取、校验、保存、执行及任务恢复。未改生成权限和供应商协议；第四阶段的执行入口统一与阻断规则评估尚未全部完成。

## 已落实

1. 执行时显示“正在整理素材 / 正在创作 / 正在保存到画布 / 正在检查结果”，内部工具名与详细步骤留在折叠记录中。
2. 进度和停止按钮放在同一行。展开记录时可查看完整步骤，停止仍在详情外。
3. 完成、停止、暂停及失败后的过程区缩为“处理记录”。成果、未完成原因和下一步分别由回复说明，避免重复状态占用空间。
4. 本轮使用的 Skill 记录移入详情，模型、Skill 选择、上下文、复制、放到画布及历史入口保留。
5. 操作确认卡使用简短名称，去掉每次重复的“不调用生成服务”；有服务调用时仍显示模型和调用上限，确认按钮保留。
6. 作品检查中的待改进或未知质量保持可见；同一作品的后续检查可以更新其结论，不同作品的通过结果不会覆盖其他作品的问题。
7. 助手回复规则明确：优先交付作品成果和必要决定，不逐步播报内部检查；失败、待改进和未核验之处必须如实说明。

## 现有入口及本轮处理

| 操作 | 实际入口 | 用户看到什么 | 后台保持的工作 |
| --- | --- | --- | --- |
| 读取画布、知识和素材 | 创作循环调用只读工具 | 简短进度，记录可展开 | 读取真实状态、知识来源及素材引用 |
| 创建、编辑和连线 | `apply_canvas_operations` 及逐镜创建工具 | 保存结果 | 候选画布校验、持锁保存和持久回执 |
| 原生节点操作及模型运行 | `propose_native_action` → 确认 → 原生执行 | 必要确认卡、停止和结果 | 提交边界复核、用户模型和调用范围、保存及来源归属 |
| 查询与恢复生成任务 | 原生任务编号及动作回执 | 等待、错误或继续入口 | 查询原任务，不因刷新或断线重提 |
| 作品检查 | `inspect_result` / `record_result_review` | 有问题时提示，检查记录可展开 | 实际文件、任务及语义评价证据核对 |

没有为了简洁删除后台检查，也没有把工具成功改成质量通过。尚未复现的不必要阻断本轮不盲目移除；知识变化检查缩小范围及原生确认进一步合并仍需具体案例。

- 前端全部 504 项检查通过：[日志](../output/assistant-quiet-js-final.log)。新增检查覆盖简短进度、终态去重、Skill 记录位置、停止位置及不同作品质量提示。

- 实际展开处理记录可查看步骤；普通画布点击停止后保存停止状态，未触发模型请求。
- 智能画布实际视口 390×600、面板宽 300 像素，输入与操作入口可见。普通画布桌面视口的 300 像素面板无横向溢出，进度行约 34.5 像素，停止与进度同排。没有把尝试设置视口但未生效的结果当作窄窗口验收。
- 使用原生浅色主题检查；本轮未重新覆盖全部主题和全部供应商错误组合。真实模型的创作质量与提示词遵循效果尚未实测。
- 代码只读复核未发现阻断问题；项目知识摘要核对为空变化。

## 文件与清理

主要修改 `static/js/canvas-assistant.js`、`static/css/canvas-assistant.css`、`backend/canvas_assistant_agent.py`，同步两画布缓存版本、知识索引及相关测试。删除被替代的重复终态展示、独立 Skill 提示和一条重复 CSS 规则；没有创建另一个助手副本，没有删除用户画布或素材。

## 使用与后续

重启 `run.bat` 后刷新画布。正常使用助手即可看到简短进度和成果；需要核对执行过程时展开“处理记录”。确认、停止、继续、错误与质量提示按真实状态出现。

本轮尚未获得用户手动验收，不自动提交或上传。用户确认可用后按项目约定同步源码。下一步依据实际使用中的阻断案例继续第四阶段，避免为了减少提示而丢失质量检查或任务恢复能力。
