# 模块化第七轮 草稿快照与恢复状态

2026-10-17。复用现有 CanvasSaveRecovery 集中两种画布重复的数据拼装和恢复结果整理；没有新增草稿数据库、管理器或脚本依赖。前六轮保留，未提交上传。

## 改动与边界

新增两个纯函数：

- `draftSnapshot(canvas,nodes,connections)`：接收原生序列化器已经处理的节点，复制连线、保留画布字段。保留原浅拷贝范围，不声称节点或设置全部深拷贝。
- `recoveredState(recovered,viewport)`：没有草稿时返回 null；有草稿时保留当前视口，整理恢复画布、冲突标记和重试提示，不修改输入或宿主。

普通画布仍由原函数清理节点临时运行字段，恢复后赋值节点/连线、标记 dirty、备份后显示提示。冲突副本仍去掉旧 pending/directPending，原节点任务字段不被删除。

智能画布仍刷新当前输入、按原规则序列化和转换旧节点、过滤日志预览节点、克隆设置，显示提示后备份。普通/智能的先后顺序没有强行统一。

classicSaveBase、智能基准 Map/snapshot、IndexedDB、跨页锁、实际合并算法均保持原职责。重复的快照拼装和恢复消息已从编辑器迁入公共模块；编辑器仍负责本地状态应用和 UI。

## 实际失败恢复验收

隔离服务只有公开代码和自制空画布。临时测试标记令对应画布 PUT 返回 503，不修改产品保存接口。

普通与智能画布分别执行：

1. 新建提示词节点，输入中文，页面显示保存失败且已备份本机。
2. 只读核对服务器画布 nodes 仍为空，并确认 503 事件，排除内容已经成功保存的情况。
3. 关闭测试标签并重新打开相同画布；页面显示“已恢复未保存的本机草稿”，中文节点完整保留。
4. 再次确认服务器仍为空，解除隔离故障，点击“重试保存”。
5. 错误提示消失；磁盘记录包含恢复后的完整中文节点。

没有清除浏览器存储、关闭草稿保护或调用真实供应商。故障机制只在本机 `.git/modularization/preview.py`，不进入产品或发布文件。

截图与顺序证据保存在 `output/canvas-draft-state-20261017/`：两种画布各有保存失败、重开恢复和重试成功截图，最终结果与服务器事件记录同目录。

本轮没有新增浏览器存储损坏、配额耗尽、双页面同字段冲突、浏览器进程崩溃或真实用户升级验收。既有相关自动测试仍有效，但不能据局部通过宣称全部恢复场景完成。
