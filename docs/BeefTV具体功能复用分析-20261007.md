| 功能 | 拟放位置 | 回填方式与真实逻辑 |
| --- | --- | --- |
| 运镜 F01 / 摄影参数 F02 | 现有模板库内的创作工具 | 选择并预览描述，默认追加片段；保留原稿与素材引用，不自动运行 |

| 提示词优化 F04 | 模板库内的优化工具 | 读取当前原稿与目标模型，优化结果先预览，用户采用后才替换；保留引用与原稿恢复能力 |

| 灰度 / 边缘图 F05 | 图片工具菜单 | 像素处理、上传、创建结果节点，不属于提示词模板 |

已确认的接入基础：普通画布 `openPromptTemplateModal` → `applyPromptTemplateToPromptNode`，智能画布 `openPromptTemplatePanel` → `applyPromptTemplateToNode`，两者使用 `/api/prompt-libraries` 的共用库。智能画布区分节点与 composer 目标。

关键差异：现有应用模板逻辑直接赋值 `node.text` 或设置 composer 文本，即替换全文。因此新增运镜片段不能原封不动调用现有“应用模板”。拟补充明确的追加与替换模式、原稿与引用快照、目标绑定及过期检查；普通画布回填后同步下游生成输入，智能画布回填后同步对应草稿与保存。复用同一组规则，保留两种画布各自的输入和存储适配。现有负向提示词与平台建议不能未经核实就当作供应商参数提交。

- “直接复用”表示核心逻辑较独立，仍需移除 TypeScript 类型、替换导入及对接输入输出；“适配复用”表示需要处理节点、模型或存储依赖；“较大改造”表示会新增完整创作流程。

## 3. 每项具体如何接入

### F01：视频节点的运镜和分段提示词

**例子：** 用户输入“女孩走进咖啡馆”，选择“背后跟拍”和“10 秒”，自动补充镜头运动及各时间点动作描述，用户编辑后再生成。

- 来源：[cinematic-video-tools.ts](D:/beeftv/web/src/lib/canvas/cinematic-video-tools.ts)，核心是 `CAMERA_MOVE_PRESETS`、`TIME_SEQUENCE_PRESETS`、`appendPromptSnippet`；界面调用在 [canvas-video-prompt-tools.tsx](D:/beeftv/web/src/components/canvas/canvas-video-prompt-tools.tsx)。
- 接入（以入口修订为准）：两种画布的现有模板库内；智能画布沿用 [smart-canvas.js](D:/daxiong/static/js/smart-canvas.js) 的 `setPromptDraftForNode`、`buildPromptRequest` 与 `runApiVideoGeneration`。
- 最小范围：在现有模板库内加入工具区，并复用一个独立提示词规则脚本，不新增供应商协议。时间模板应与当前模型支持的时长相匹配。
- 验收：保留原提示词及媒体引用；仅在用户点击时插入；保存重开不丢失；不自动提交生成。
- 注意：这些文字指导模型创作，不是精确控制摄像机轨迹或强制按秒执行的协议。

### F02：摄影参数组合

- 来源：[camera-prompt-library.ts](D:/beeftv/web/src/lib/canvas/camera-prompt-library.ts)，复用 `CAMERA_PROFILES`、`LENS_PROFILES`、`FOCAL_LENGTHS`、`APERTURES` 与 `buildCameraPrompt`。
- 接入：图片/视频提示词区域中的“摄影”菜单，生成描述后使用现有提示词插入方法。
- 最小范围：先提供焦距与光圈，再扩展相机与镜头风格；直接复用数据，不迁移 React 面板。
- 验收：选择项能形成清晰描述；不改动实际图片尺寸；不把这些描述当成供应商 API 的真实相机参数。

### F03：图片节点的人像质感调整

**例子：** 用户选择“真实肌理 + 自然光影 + 深度融合”，基于当前图片生成新结果，改善塑料肤质和人物贴背景的问题。

- 来源：[canvas-portrait-texture.ts](D:/beeftv/web/src/lib/canvas/canvas-portrait-texture.ts)，核心是 `PORTRAIT_TEXTURE_GROUPS`、`normalizePortraitTextureSettings` 与 `buildPortraitTexturePrompt`；界面在 [canvas-portrait-texture-popover.tsx](D:/beeftv/web/src/components/canvas/canvas-portrait-texture-popover.tsx)。
- 接入：`smartNodeToolbarHtml` 新增“质感”入口，将原图片作为参考输入，调用现有图生图流程。
- 最小范围：五组选项、提示词预览和生成按钮，结果放入新节点并保留源图。
- 验收：选项存储到节点；失败不影响源图；调用支持参考图片的模型；结果可继续编辑。
- 注意：这是通过模型重新生成实现的质感调整，人物一致性要用真实模型样例验收。

### F04：模型适配提示词优化器

- 来源：[prompt-optimizer.ts](D:/beeftv/web/src/lib/plugins/builtin/prompt-optimizer.ts)，可提取 `resolveModelAdaptationProfile`、`buildUserMessage` 及结构化结果约定；面板在 [canvas-prompt-optimizer-drawer.tsx](D:/beeftv/web/src/components/canvas/canvas-prompt-optimizer-drawer.tsx)。
- 提供扩展想法、精修、强化风格、适配模型、结合参考等方式。结果包含正向提示词、规避项、修改说明、假设与备选版本。
- 咱们已有的 `videoEnhancePrompt` 主要提交 `enhance_prompt` 布尔参数；它与可预览、编辑、采用的独立优化面板不同。
- 接入：复用 [main.py](D:/daxiong/main.py) 的 `/api/canvas-llm`，并借用 `runPromptLLMNode` 的供应商/模型选择。需要适配返回结构；流式和取消支持另核接口能力。
- 最小范围：先接图片和视频两类、目标模型规则、结果预览和“采用”。禁止失败时覆盖原内容。
- 验收：优化用文本模型与最终生成模型可不同；保留引用；无效 JSON 明确报错；关闭不回填；点击采用才修改。

### F05：灰度/Canny 媒体转换

- 来源：[local-converter.ts](D:/beeftv/web/src/lib/media-conversion/local-converter.ts)，核心 `convertImageLocally`、`transformPixels`、灰度与 Canny 算法；节点约定见 [contracts.ts](D:/beeftv/web/src/lib/media-conversion/contracts.ts)。
- 接入：第一版在图片工具菜单增加“灰度图”“边缘图”，调用浏览器算法，再沿用现有上传与创建图片节点流程。
- 最小范围：无需 GPU 或模型下载；保留尺寸限制、取消与图片读取错误处理。算法在大图上可能阻塞主线程，需要限制处理尺寸或放入 Worker。
- 验收：透明图片与大图、取消、输出尺寸、保存重开；生成的控制图只有接入支持该条件的 ComfyUI 工作流或模型时才具有约束作用。

### F06：单人脸表情编辑

- 来源：[canvas-emotion.ts](D:/beeftv/web/src/lib/canvas/canvas-emotion.ts)，核心 `resolveEmotionEditPlan`、`buildEmotionImageArtifacts`、`buildEmotionPrompt`、`compositeEmotionImage`；交互在 [canvas-emotion-workspace.tsx](D:/beeftv/web/src/components/canvas/canvas-emotion-workspace.tsx)。
- 特别值得引用：模型只生成脸部裁切图，最终以原图为底，在人脸椭圆区域内羽化融合；渠道不支持蒙版时有局部融合方案。
- 接入：图片工具新增“表情”，第一版手动框选人脸。自动识别依赖 MediaPipe、Worker 和模型资源，后续再引入。
- 验收：多人图只修改选定脸；未选脸不得执行；源图保留；错误和取消不留假成功节点；融合边界与身份保持需实际看图。
- 区别：咱们已有的“六种基础表情胸像”模板是生成整张设定表，本项是编辑已有图片内选定的一张脸。

### F07：AI 打光面板

- 来源：[canvas-node-lighting-dialog.tsx](D:/beeftv/web/src/components/canvas/canvas-node-lighting-dialog.tsx)，包含 `CanvasImageLightingOptions`、`LIGHT_POSITIONS`、`STYLE_PRESETS`、`buildLightingPrompt`。
- 接入：图片工具面板提供方向、亮度、轮廓光、光色与风格选项，把提示词和当前图片传给现有图生图。
- 最小范围：提取纯参数与提示词构造，先做普通控件；球面预览可后续实现。
- 验收：设置可保存；模型不支持图生图时提示；结果另存；光向、颜色是否符合选择需实际生成验证。
- 注意：属于 AI 改图，不是本地物理灯光模拟。预览素材要另查授权，首版可用自己绘制的示意图。

### F08：批量创作表节点

**例子：** 第一列固定人物图，第二列每行放不同服装，第三列放背景，每行可改提示词，分别生成试穿结果。

- 来源：[canvas-batch-table.ts](D:/beeftv/web/src/lib/canvas/canvas-batch-table.ts)，核心 `createBatchRowsFromColumns`、`batchPromptForRow`、`reorderBatchReferenceColumns`、`moveBatchReferenceCell`；界面见 [canvas-batch-table-node.tsx](D:/beeftv/web/src/components/canvas/canvas-batch-table-node.tsx)。
- 接入：在智能画布 `createNodeFromMenu` 增加表格类型；接现有图片任务服务与并发控制。
- 最小范围：行 ID、提示词、参考图列、状态、结果、失败信息。首版可固定两列；后续再做动态列和拖拽交换。
- 保留上游语义：其全局提示词可覆盖行提示词。咱们如果希望“前缀 + 行内容”，应明确新增语义，避免无意改变规则。
- 验收：逐行绑定准确；交换不串图；重开恢复；失败只重试失败项；重复点击不重复提交。表格新增字段需进入保存、导入导出和恢复流程。

### F14：结构化分镜脚本
