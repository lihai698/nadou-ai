## 已确认并修复的问题

1. 源码包中的 `run.bat`、`安装依赖.bat`、`检查核心流程.bat` 使用 LF，违反已有 Windows 启动脚本测试。现统一为 CRLF，并增加 Git 属性约束后续检出。
2. 预览缓存创建使用 `abspath`，删除使用 `realpath`，Windows 短路径会得到不同键。创建 WebP/PNG 和 JPEG 缓存现与删除一致使用 `realpath`。
3. 两项任务记录清理测试通过未规范的字符串路径注入错误，短路径时实际删除路径已经规范化，导致错误未注入。只修正比较方式，保留所有恢复内容、异常和备份断言。
4. 现有云端配置缺少 FFmpeg/FFprobe，曾产生 34 项错误。本轮补充安装和检查步骤，采用已核实存在的 [Chocolatey FFmpeg 8.0.1 包](https://community.chocolatey.org/packages/ffmpeg/8.0.1)。本机没有执行 Chocolatey 安装，继续使用已有媒体工具。

既有短路径键生成的历史预览属于可重建缓存，本轮不批量迁移或删除；原始媒体与用户索引不变。

## 实际界面验收

使用仅包含公开代码和自制空画布的隔离服务，没有连接私人配置或调用模型：

1. 工作台显示普通/智能两种画布。
2. 分别从列表打开两种画布，名称、原有工具栏和页面可见。
3. 回收站显示自制已删除画布和 30 天保留说明。
4. 点击恢复，回收站变空，项目从 2 个画布变成 3 个。
5. 刷新工作台，恢复结果仍在，原两种画布保留。

当前工作台菜单没有置顶按钮，未为验收更改 UI。置顶语义由纯函数及真实列表接口验证，不宣称完成了置顶按钮点击验收。工作台卡片会保留布局位置，因此卡片的空间顺序不等同接口排序顺序。

未执行真实供应商、macOS、长时压力、真实用户跨版本升级或新机器首次依赖安装。云端修改需要用户确认源码后推送并观察新运行，不能用本地通过替代。
