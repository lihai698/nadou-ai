# 阶段 8：供应商协议规则试拆

日期：2026-10-03  
范围：把 `main.py` 中只处理供应商协议和模型展示名的纯逻辑移入 `backend/provider_protocols.py`。本次只覆盖阶段 8 的一小块，不代表配置、素材、画布、外部连接或任务执行已经完成拆分。

## 职责、数据归属与依赖

| 项目 | 约定 |
| --- | --- |
| 模块 | `backend/provider_protocols.py` |
| 负责 | 读取传入字典的基础协议；过滤单模型协议覆盖；规整模型展示名；按平台与模型决定生效协议 |
| 输入输出 | `provider_protocol(provider) -> str`、`normalize_model_protocols(value) -> dict`、`normalize_model_name_map(value) -> dict`、`effective_protocol(provider, model="") -> str`；保持原规则与异常行为 |
| 数据归属 | 不拥有持久化数据或密钥；只接收调用方传入的值并返回新字典或字符串。模块级协议集合只用于规则判断 |
| 允许依赖 | Python 标准库 `re`；不导入 `main.py`、FastAPI、文件系统、网络客户端或其他 `backend` 模块 |
| 依赖方向 | `main.py -> backend.provider_protocols`；与 `backend.versioning`、`backend.tracing`、`backend.diagnostics` 平行 |

`main.py` 保留四个同名导入，原调用方无需改动：`normalize_provider` 用两个规整函数处理保存和加载的配置；`resolve_chat_provider`、`api_headers` 和 `generate_ai_image` 使用 `effective_protocol` 决定聊天地址、鉴权头和图片路由；平台判断及拉取模型入口使用 `provider_protocol`。配置文件读取、保存、密钥处理、HTTP 路由和真实供应商连接仍由现有代码负责。

## 本次改动和边界

- 新增纯模块和独立回归 `tests/test_provider_protocols.py`，从 `main.py` 删除被替代的四个函数体及两个常量定义。
- 保留现有 `main.py` 调用位置、HTTP 路径、配置 JSON 字段、模型覆盖优先级与固定平台名单。
- 未移动 `normalize_provider`：它同时依赖 HTTP 错误、平台默认值和 RunningHub 规则；也未移动读写配置、外部连接、素材/画布写入及任务调度。
- 无数据迁移或用户文件修改。若需回退，只需恢复 `main.py` 原函数体和常量，移除新模块的导入与文件。

独立测试覆盖配置归一化、非支持协议过滤、模型覆盖、固定平台规则及空配置默认值。专项测试、语法、旧实现引用检查均通过；完整核心检查通过 Python 107 项、JavaScript 111 项及中英文词条检查，发布预检通过 287 个公开文件。临时公开代码副本启动后，真实 `GET /api/providers` 返回 200 和 3 个默认供应商，确认原入口可用。真实供应商协议组合仍需阶段 3 的独立验证。
