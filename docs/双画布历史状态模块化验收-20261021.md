# 双画布历史状态模块化验收

日期：2026-10-21。基线 `8aeccfc8d47b5340313deb1c6c406c74aa5e17a5`；固定候选树 `6ff07bbdf0f84f37f1e15a8efba1fc69b2af583a`。

本批让两种画布各自持有一个历史控制器，将历史状态及其完整操作迁入 `static/js/canvas-history.js`。普通画布继续保留原 30 步撤销；智能画布继续保留原 40 步撤销/重做和手势延迟记录，不强行统一功能。

## 职责和数据归属

| 模块/入口 | 负责内容 | 允许访问的状态与效果 |
| --- | --- | --- |
| `CanvasHistory.createClassic` | 撤销快照、数量限制、恢复顺序 | 私有 undo 栈；通过 host 使用原节点存储投影、连接、选择集、拆解失效、渲染和保存入口 |
| `CanvasHistory.createSmart` | 撤销/重做、待提交手势快照、抑制记录、重做基准 | 私有 undo/redo 栈、pending 快照、suppressed 标记和 redo 基准；host 提供画布与选择状态及原效果回调 |
| 普通/智能画布 host | 创建各自唯一控制器，保留原操作函数转发和 live state 接口 | 不再持有原历史数组或标记；画布内容与选择仍归原画布 |
| `smart-save-coordinator.js` | 原保存队列、快照整理、冲突处理 | 通过 `beforeScheduleSave`、`prepareStorageNormalization`、`finishStorageNormalization` 使用历史策略，不再读写历史栈和基准 |
| `smart-navigation.js` | 原清空/返回流程 | 清空成功时调用 `history.reset()`，不再直接修改三个历史状态 |
| 上传/生成/指针 host 和原页面内嵌入口 | 原嵌套编辑的记录抑制 | 经控制器的 `suppressed` 访问器操作标记；不暴露数组 |

历史控制器只拥有历史状态，不注册 DOM/window 监听器，不创建另一个保存调度器，不直接访问文件或网络。原键盘、页面、生成和保存入口仍接入生产实现。两个 HTML 入口加载新模块，并更新受影响脚本版本。

## 原主体与引用检查

完整迁移普通画布 `pushUndo/performUndo` 两函数，以及智能画布 `capturePendingUndo/commitPendingUndo/discardPendingUndo/snapshotForUndo/pushUndo/restoreHistorySnapshot/historyContentSignature/performUndo/performRedo` 九函数。AST 比较将显式 host 前缀还原后，11 个完整主体及其嵌套回调与基线一致。

新控制器私有化原状态；保存前的重做失效、保存投影前后基准维护、清空后的历史重置一起迁移。全项目搜索 14 个相关符号，旧历史数组、基准和 pending 快照在生产脚本中只剩新 owner 内部使用。原函数名的薄转发保留给现有入口和页面片段测试。

固定候选仅包含声明的变换；另外逐项核对混合工作区中的历史 host、转发函数和唯一控制器声明，避免覆盖另一聊天的工作组改动。原历史测试改为加载生产历史模块和 host，保留原断言与真实键盘处理器。

## 验证结果

- 新增 14 项独立状态边界测试：旧树缺模块正确失败；候选通过。覆盖深快照、两实例隔离、原数量限制、存储投影、选择恢复、手势提交/丢弃、抑制、重做失效、保存基准、清空及渲染失败后的抑制释放。
- 相关页面测试基线 80、候选 94 项全部通过，无跳过。固定候选完整核心检查：Python 1494、JavaScript 1207 项通过。
- 差分合同：两画布 24 个场景、393 次操作，完整内容、选择状态、异常与回调顺序和基线精确一致，未归一输出。包括有界撤销/重做、pending、抑制、直接编辑、视口保存、存储整理、重置、渲染错误及空画布。
- 真实 Chrome 使用两画布生产页面，在页面内建立编辑夹具，实际按 Ctrl+Z/Ctrl+Shift+Z。覆盖撤销、智能重做、无内容变动的保存后仍能重做、直接字段修改使重做失效、保存重开和强制重启后内容一致且历史不持久化。智能画布通过真实右键菜单和确认框清空，随后撤销/重做均不恢复旧节点。普通画布仅覆盖原有撤销，不新增重做或改变其清空策略。
- 候选页面对新 owner 的调用计数覆盖原键盘转发及保存接口，确认不是测试副本在执行。智能图片恢复会写入运行时间，故两次浏览器执行前固定 `Date.now`，保留实际快照中的时间字段参与完整比较。基线和候选页面快照逐项比较；调用计数属于额外验收探针，不属于业务结果。
- 继承的双画布引用目录、图片/视频拖入、真实浏览器下载、任务刷新、保存重开/强制重启、ZIP 实际下载事件及条目字节、原生 FFmpeg 导出到画布/下载均通过。六张候选截图拼图已检查。
- 原停止/恢复、结果检查隔离、32 进程 store 锁、固定候选本地 preflight 均通过。后端与 main 相对基线没有改动。

两画布源码变动要求更新原知识索引的 548 处来源摘要。固定候选摘要根据固定候选源文件计算；混合工作区摘要按当前工作区源文件另外计算，保留其他知识字段。

验收没有删除差异字段或归一实际结果：从两项声明的源码摘要变换及知识快照派生版本，生成预期的完整响应、模型调用和落盘原始字节；再对实际结果精确比较。其他所有字段必须保持，完整原始文件通过 base64 留存并核对预期字节、长度和 SHA。完整知识快照也单独核对，仅允许这三种摘要值更新。此合同表示“只出现声明的源码元数据变化”，不声称实际文件字节与基线完全相同。

## 范围与限制

基线与候选验收使用临时目录、自制媒体、loopback 服务和模型替身，没有读取私人配置或真实画布素材，没有调用供应商生成。供应商效果、长期内存与性能不在本批验收范围。

提交使用独立 index、固定候选和白名单；不纳入另一聊天正在开发的工作组、工具栏、素材封面与其测试文档。两画布、HTML、测试辅助文件和知识索引存在混合工作区版本，允许并行改动继续写入，不用初始摘要覆盖它们；固定候选通过不等于这些并行改动也已通过。
