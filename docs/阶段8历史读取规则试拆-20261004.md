# 阶段 8：历史读取规则试拆

日期：2026-10-04  
范围：把历史列表文件读取、类型筛选、空图片过滤和时间排序规则从 `main.py` 移到 `backend/history_records.py`。这是阶段 8 的局部试拆，不表示历史删除、媒体引用清理或并发写入已经模块化。

## 职责、数据和依赖

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `backend/history_records.py` | 按调用方提供的路径读取 JSON；把传入的记录序列转换为历史 API 的公开列表 | 不决定默认路径、锁、媒体删除、历史写入、FastAPI 响应或用户数据目录 |
| `main.py` | `/api/history` 路由、异常响应、历史写入/删除、媒体引用扫描和锁 | 不再重复实现历史列表筛选和排序规则 |

允许依赖方向为 `main.py` → `backend.history_records`。模块只依赖 Python 标准库 `json`、`os` 和 `typing`，路径必须由调用方显式传入，不读取真实项目目录或私人配置。`read_history_records` 保留文件不存在返回空列表的接口语义；读取异常仍由路由转换为空列表并记录原有固定提示。

## 兼容边界

- `/api/history` 仍保留默认 `zimage` 类型、`images` 非空过滤和 `timestamp` 倒序；非数字时间按 0 排序。
- 历史 JSON 结构、写入上限、删除接口、媒体引用保护和锁顺序没有移动或改变。
- `history_records_for_api` 返回新列表，不修改调用方传入的记录序列；记录内容和公开字段保持原样。

## 验证

- `tests/test_history_records.py` 4 项通过，覆盖缺文件读取、中文 JSON、类型筛选、空图片过滤、时间排序及真实 ASGI 路由入口。
- 历史原子写入 3 项、历史媒体清理 3 项通过；`py_compile` 和 `git diff --check` 通过。
- 所有测试使用临时目录和自制记录，没有读取或修改私人历史文件。

## 限制与恢复

历史写入、删除、媒体引用查询、跨进程锁和格式迁移仍由 `main.py` 负责，阶段 8 整体不勾选完成。若需恢复，可把路由中的读取、筛选和排序函数体移回 `main.py`，删除 `backend/history_records.py` 与专项测试；历史数据格式无需迁移。
