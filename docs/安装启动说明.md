# 安装与启动

## Windows

1. 如果下载的是完整 Windows 发布包，解压到一个文件夹后直接双击 `run.bat` 即可。完整发布包包含 Python 和离线依赖包，但不包含已安装的依赖；第一次启动时 `run.bat` 会自动调用 `安装依赖.bat` 安装一次。同一个文件夹以后直接双击 `run.bat`，无需重复安装；如果后续版本更换了依赖清单或项目 Python，启动时会自动重新安装。也可以先手动双击 `安装依赖.bat`，效果相同。普通源码 ZIP 可能不包含 Python 或离线依赖包，不适合直接给新手运行。
2. `run.bat` 会检查 Python、依赖、3000 端口和可读取的 JSON 配置；通过后启动服务，并打开 `http://127.0.0.1:3000/`。如果仍提示缺少依赖，重新运行 `安装依赖.bat`。安装脚本优先使用 `packages/` 中适配项目自带 Python 3.10 的离线包；缺包时才尝试联网。它按 `requirements.lock` 安装固定版本，会调整当前 Python 环境中已有的依赖版本。
3. 只检查、不启动服务：在项目目录运行 `python\python.exe tools\check-environment.py`。检查器会检查 `API/.env` 中的参数名、引号、数字和地址格式，以及已保存的平台列表；错误只显示配置名和行号，不显示密钥值或完整原行。未配置某个可选供应商密钥不会阻止本地画布启动，使用在线服务前再到“API 设置”填写即可。可选的 `ffmpeg`、`ffprobe` 没找到时会提示，不阻止画布启动。
4. 首次配置可复制 [`API/.env.example`](../API/.env.example) 为 `API/.env`，只填写自己使用的平台。示例文件不含密钥，私人 `API/.env` 不会进入公开发布包。需要在隔离目录检查自制配置时，可追加 `--config-root <目录>`。
5. 停止服务：回到运行 `run.bat` 的命令窗口，按 Ctrl+C。若提示 3000 端口占用，先确认已有服务，再停止相应窗口；不要直接结束不明进程。

`main.py` 默认只监听 `127.0.0.1:3000`，同一网络内的其他设备不能直接访问。确需局域网访问时，同时设置 `NADOU_BIND_HOST=0.0.0.0` 和 `NADOU_ACCESS_TOKEN=一段随机长字符串`；浏览器会弹出 Basic Auth 登录框，用户名可填任意值，密码填写令牌。未配置令牌时服务不会启动。内置的 `run.bat` 仍打开本机地址。

服务入口默认使用跨进程单实例锁，避免同时启动多个服务进程后各自提交任务。若确实需要多实例，显式设置 `NADOU_ALLOW_MULTI_INSTANCE=1`，并为每个实例使用不同端口和独立数据目录；这个开关不会替代任务级鉴权或队列隔离。

图片、视频任务在上游已经返回任务编号后会先写入本地任务记录。服务重启后，画布只允许通过“刷新远端结果”查询原编号，不会自动重新提交；没有获得上游编号的任务仍显示为状态未知，需确认供应商侧状态后再决定是否重试。

## macOS

使用 Python 3.10 或以上版本，运行 `bash mac-启动服务.sh`。第一次启动会自动调用 `mac-安装依赖.sh` 从软件包索引安装 `requirements.lock` 中的固定版本，以后直接启动即可；也可以手动运行 `bash mac-安装依赖.sh`。`mac-启动服务.command` 也会调用同一个启动脚本，但仓库中的该文件尚未设置可执行位，直接运行前需处理权限；用 `bash mac-启动服务.sh` 不依赖此权限。项目内的离线 wheel 只针对 Windows Python 3.10，macOS 需要联网安装。macOS 的实际安装和启动尚未在本机验证。

## 私人文件与升级

`API/.env`、`data/`、`assets/`、`output/`、`history.json` 和可能存在的 `global_config.json` 保存配置或用户内容。升级前按[备份恢复说明](../备份恢复说明.md)留存私人副本；不要用新版目录直接覆盖这些文件。内置在线更新只允许替换 `main.py`、`VERSION` 和 `static/` 下的文件。当前工作区已将 `API/.env` 与 `data/asset_library.json` 从 Git 索引移除，磁盘文件保留且哈希未变；该变更尚未提交或推送。见[Git 迁移证据](evidence/20261003/stage4-private-git-migration.json)。

nadou ai 的正式更新源是维护者的 GitHub 仓库。若新版本只改上述程序文件，左侧更新按钮可直接安装、自动重启；若新版本改了依赖或安装脚本，按钮会打开完整安装包页面。版本发布步骤和两种更新模式见[发布与更新](发布与更新.md)。仓库首次发布前，现有安装无法从新地址获取更新。

迁移提交进入其他电脑之前，先在仓库外备份这两份私人文件，再更新代码并把私人文件恢复到原路径。取消跟踪不会清除旧 Git 历史中的内容；不要把包含密钥或用户数据的备份提交到仓库。新安装缺少 `API/.env` 时，程序首次运行会创建空文件；缺少素材库索引时，程序会创建默认索引，原有素材库仍需从私人备份恢复。

阶段 4 的 Windows Python 3.10 隔离安装、启动和 WebSocket 验收见[审计记录](阶段4安装启动环境审计-20261003.md)。

## 发布包启动验收

公开包生成后，保持导出目录原样，在开发目录运行 `python\python.exe tools\verify-release-startup.py output\release\nadou-ai-版本 --python python\python.exe`。该检查会核对 `RELEASE_FILES.json` 和 `VERSION`，拒绝清单外文件、符号链接及私人路径，再用已安装依赖的项目 Python 在临时副本启动并确认根页和静态页均返回 HTTP 200。另将完整 ZIP 解压到隔离目录，运行其中的 `安装依赖.bat`，验证首次离线安装；不要在导出目录安装依赖，新增文件会违反发布清单。检查通过仍需在独立安装目录人工检查主要页面和升级路径。

要把素材存到其他位置，在主页打开“素材库”，点击“偏好设置”→“素材管理”，分别填写上传、生成和本地素材目录，再点“保存目录”。设置写入 `data/storage_settings.json`，重启后继续生效。修改目录不会自动搬运旧文件；需要保留旧素材时，先备份，再自行复制到新目录并核对。

已用自制数据在隔离目录验证内置在线更新及回滚不会改动私人文件，见[隔离更新记录](evidence/20261003/stage4-isolated-upgrade.json)。外部存储路径在 Windows 隔离副本中设置后，上传、读取、重启恢复均通过，见[外部存储记录](evidence/20261003/stage4-external-storage.json)。这些演练不能代替真实数据备份，也不覆盖普通 Git 更新或 macOS 实机。
