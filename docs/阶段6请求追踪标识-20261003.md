# 阶段 6：请求与任务追踪标识

日期：2026-10-03  
范围：本机 FastAPI 服务的 HTTP 请求、画布后台任务和网络诊断日志。测试使用
ASGI 隔离客户端与自制数据，不读取 `API/.env`，不调用真实供应商。

## 已完成

- 新增 `backend/tracing.py`，集中生成、校验和管理 `trace_id`、`request_id`。
- 每个 HTTP 请求由中间件绑定上下文，并在响应中返回 `X-Trace-ID` 与
  `X-Request-ID`。客户端传入的标识只接受有限字符集和 128 字符以内长度，非法值
  会被替换，不会原样写入日志或响应。
- 画布图片和 ComfyUI 两个后台任务入口保存提交请求的 `trace_id`、`request_id`，
  创建响应和后续任务查询都能看到同一关联字段。任务 ID 仍沿用原有格式，未改变
  前端轮询路径和任务状态。
- `log_net_error` 自动带当前追踪上下文，并继续使用已有 URL、代理和异常内容脱敏
  逻辑。`asyncio.create_task` 继承提交请求的上下文，后台网络错误可以定位到原请求。
- 参数校验错误的 JSON 也返回两个标识，便于页面把提示与服务端日志对应起来。

## 边界与后续

本次保留了原有任务 ID 和响应字段，仅增加关联字段及响应头；服务重启后内存任务仍
会按现有行为返回 404。其他长轮询供应商接口会自动获得 HTTP 请求响应头和网络日志
上下文，供应商返回的业务 JSON 尚未统一改为任务记录字段。日志文件轮转和已识别
供应商失败出口的摘要处理已在后续补验中接入；旧控制台日志、成功回包的数据范围
以及真实供应商错误页面仍属于阶段 6 后续工作。
