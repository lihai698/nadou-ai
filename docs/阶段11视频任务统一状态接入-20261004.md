# 阶段 11：视频任务统一状态接入（2026-10-04）

## 范围

本次首轮只处理画布视频本地任务入口 `POST/GET /api/canvas-video-tasks`，后续补充了视频任务的 `POST /api/canvas-video-tasks/{task_id}/refresh` 单次查询，不调用真实供应商、不读取真实 `data/`、素材或 API 配置。旧的同步兼容入口 `POST /api/canvas-video` 保持不变。

## 实现

- `main.py` 的视频任务记录新增 `input_summary`，只保存提示词长度、供应商/模型标识、参考媒体数量、时长和比例，不保存原始提示词、参考地址或完整工作流。
- 视频任务 worker 接入 `backend/remote_task_protocol.py` 的 `observe_remote_task` 与 `remote_task_decision`，在记录中保存压缩后的 `remote` 观察：统一远端状态、上游编号、是否可重试、是否得到远端终态和操作类型。
- 有视频输出时才记录远端 `succeeded`；即梦排队保留 `pending` 语义；超时、网络异常、查询失败和重启遗留任务记录 `unknown`，不自动重提；明确的 4xx 提交拒绝仍记录 `failed`。
- 观察结果只保留状态和短错误摘要，不落盘供应商原始回包。浏览器/服务重启后仍以本地记录为准，不把本地等待停止解释成远端取消。

## 验证

`tests/test_canvas_video_remote_protocol_integration.py` 使用临时任务目录和模拟 `canvas_video`，3 项通过，覆盖：

1. 成功结果保存统一远端状态和输入追溯摘要，并确认原始回包/提示词未写入记录；
2. 504 超时变为 `unknown` 且可重试标识保留，明确 400 拒绝仍为 `failed`；
3. 模拟重启的运行中任务变为远端 `unknown`，不会再次调用视频适配器。

另外执行了 `python\\python.exe -m py_compile main.py`，通过。

## 未覆盖边界

本次未实现供应商逐家远端取消、跨进程同一任务协调、服务重启后的真实远端查询和视频任务自动清理；这些需要各供应商协议及独立模拟/实测证据，阶段 11 整体仍不勾选完成。

补充说明：视频适配器拿到可查询的受理编号后会在长轮询前落盘；有编号的 `unknown` 记录可通过上述 `refresh` 路由和两种画布的“刷新远端结果”继续尝试一次查询。当前已对 RunningHub、已有 GET 查询适配器和即梦 CLI 视频写入固定查询模式；即梦 CLI 仍只通过专用 `query_result` 查询一次，不声明远端取消能力。智能画布的查询故障会保留原分支和任务编号，避免外层异常清理导致用户只能重新提交。

## 即梦 CLI 视频补充

- `generate_jimeng_video` 从 CLI 得到 `submit_id` 后，先通过任务回调落盘，再进入媒体查询；同步兼容入口没有任务回调时保持原有行为。
- 画布任务记录的 `query_mode` 固定为 `jimeng_cli`，只调用一次 `query_result --submit_id=... --download_dir=...`；成功时保存本地视频，仍排队或 CLI/下载异常时保持 `unknown` 并保留编号，明确失败状态才确认 `failed`。
- `tests/test_canvas_video_jimeng_query.py` 5 项覆盖受理回调先于媒体查询、刷新成功不重新提交、排队刷新保留编号和无错误文字的明确失败状态；测试仅使用模拟 CLI 和临时目录。
