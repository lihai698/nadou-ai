# 阶段 8：画布记录摘要模块试拆

日期：2026-10-04  
范围：把画布类型、颜色和公开摘要的纯规则从 `main.py` 移到 `backend/canvas_records.py`。本次只处理无副作用的记录转换，不触碰画布文件读写、删除、恢复和任务调度。

## 职责与依赖

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `backend/canvas_records.py` | `classic/smart` 类型收敛、允许颜色收敛、画布列表/元数据公开摘要 | 文件、配置、锁、FastAPI、用户数据、任务 |
| `main.py` | 路由、持久化、锁和兼容入口；把内部画布字典交给公开函数 | 不再重复实现摘要字段规则 |

模块只依赖 Python 标准库 `typing`，没有反向导入 `main.py`，也不读取默认路径或私有配置。`main.py` 保留同名导入后的调用方式，真实列表、元数据、保存和回收站接口均继续使用同一摘要函数。

## 兼容边界

- `canvas_record` 的字段名、默认值、所有者长度限制、项目回退、节点计数和颜色白名单保持原接口行为。
- 未修改画布 JSON 格式、文件名、时间戳、删除与恢复语义，也没有迁移或删除用户数据。
- 模块输出只包含公开摘要，调用方仍决定何时加载原始画布和写回文件。

## 验证

- `tests/test_canvas_records.py`：3 项通过，覆盖类型/颜色边界、字段截断和默认公开结构。
- `python\python.exe -m py_compile backend\canvas_records.py main.py tests\test_canvas_records.py`：通过。
- `rg` 确认生产实现只保留 `backend.canvas_records` 一套 `canvas_record`、类型和颜色规则；模块无 `main.py` 反向导入。

## 恢复与限制

删除 `backend/canvas_records.py` 和专项测试，并把 3 个纯函数及颜色集合恢复到 `main.py` 即可。画布文件读写、素材引用、任务调度和并发写入仍属于后续拆分范围，阶段 8 整体不勾选完成。
