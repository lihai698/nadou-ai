# 阶段 8：项目记录规则试拆

日期：2026-10-04  
范围：把项目公开摘要和项目排序、顺序号规则从 `main.py` 移到 `backend/project_records.py`。这是阶段 8 的局部试拆，不表示项目持久化或画布归属迁移已经模块化。

## 职责、数据和依赖

| 模块 | 负责 | 输入与输出 | 数据所有权 |
| --- | --- | --- | --- |
| `backend/project_records.py` | 公开项目记录、顺序号转换、列表排序键、下一个顺序号 | 输入调用方提供的项目字典或迭代器；输出新摘要字典、整数或排序键 | 不拥有持久数据，不读写文件、配置和运行时状态 |
| `main.py` | `/api/projects` 路由、默认项目、加载与保存、项目删除时的画布归属处理 | 按原接口返回项目记录并持久化更改 | `data/projects.json` 和画布文件仍由现有入口管理 |

允许依赖方向为 `main.py` → `backend.project_records`。新模块只导入 Python 标准库 `typing`，不反向导入 `main.py`、FastAPI 或其他后端模块。原 `main.project_record` 名称通过导入继续可用，三个项目 API 路由仍调用同一规则。`load_projects`、`save_projects`、`new_project` 及删除项目时的画布迁移没有移动。

## 兼容和验证

- `project_record` 的五个公开字段、默认名称、60 字符截断、顺序号整数转换和时间戳默认值保持原行为。
- 创建项目的下一个顺序号仍为现有最大顺序号加 1；项目列表仍按顺序号、创建时间排序。创建与更新名称的不同回退行为留在原调用处。
- `tests/test_project_records.py` 4 项通过：纯规则边界、`main` 兼容入口，以及临时目录内创建、列表、更新项目的 HTTP 响应；没有读取或修改私有 `data/`。
- `py_compile` 和 `git diff --check` 通过；全量核心检查由阶段汇总统一执行。
- 已搜索确认 `main.py` 不再有旧 `project_record` 函数及重复的项目排序、顺序号计算，新模块无反向导入。

## 限制与恢复

项目文件读写、删除项目后迁移画布、并发写入和项目名称规范仍是 `main.py` 的职责。此试拆不能证明这些流程已经完成阶段 8 总体验收。若需恢复，可把摘要与顺序规则移回 `main.py` 并移除新模块和专项测试；项目数据格式无需迁移。
