# 阶段 7：版本模块试拆

日期：2026-10-03  
范围：把 `main.py` 中只处理版本文本的纯函数移到独立后端模块。没有读取个人配置、用户数据或调用外部服务。

## 结果

更新检查和更新前校验继续使用原来的输入、输出和比较规则：版本文本提取数字段，比较时把较短的一侧按 `0` 补齐。空字符串、缺少版本段和带前缀的版本文本仍按原逻辑处理。

真实入口保持不变：

- `GET /api/check-update` 通过 `main.version_gt` 比较远端版本和当前版本。
- `POST /api/update-from-github` 的暂存版本校验通过 `main.version_gt` 拒绝不高于当前版本的更新。

`main.py` 只从 `backend.versioning` 导入两个函数，原函数体已删除，没有新增第二套入口。

## 职责、数据归属与依赖

| 项目 | 约定 |
| --- | --- |
| 模块 | `backend/versioning.py` |
| 负责 | 版本文本解析和两个版本的大小比较 |
| 不负责 | 读取 `VERSION`、访问网络、读写配置和用户数据、决定是否执行更新 |
| 数据归属 | 不拥有持久化数据；只处理调用方传入的字符串 |
| 公开接口 | `version_tuple(value) -> list[int]`、`version_gt(a, b) -> bool` |
| 允许依赖 | Python 标准库 `re` 和 `typing` |
| 依赖方向 | `main.py -> backend.versioning`；模块不导入 `main.py`，不反向读取全局状态 |
| 前端状态/样式/事件 | 本次后端纯模块试拆不涉及，页面入口和事件没有改动 |

## 边界验证

- `2026.10.1` 高于 `2026.10`，缺失段按零处理。
- `2026.10` 不高于 `2026.10.0` 和 `2026.10.1`。
- 空文本、`None` 和没有数字的文本不会抛异常。
- `v2` 高于 `v1`，带前缀不改变数字提取规则。
- 更新接口回归仍覆盖 GitHub 版本检查、私有文件保护、更新和回滚。
