# 阶段 7：低风险模块试拆候选（2026-10-03）

状态：实施前的只读架构盘点历史记录。版本模块随后已完成拆分，最终验收见[阶段7版本模块试拆](阶段7版本模块试拆-20261003.md)；本文件保留当时的候选边界和基线证据。

## 结论

首个候选选择 `main.py` 中的版本归一化与比较函数：`version_tuple` 和 `version_gt`。它们只把版本文本转换为整数列表并比较两个版本，不读写文件、不访问网络、不修改画布、素材、任务或配置，也不依赖 FastAPI 和供应商状态，适合先固定接口再试拆。

静态扫描结果和实施前源文件摘要见 [阶段 7 模块候选证据](evidence/20261003/stage7-module-candidate.json)。这份记录只说明拆分前的边界，不代表当时新模块已经存在或已经接入真实入口。

## 当前职责和调用关系

| 函数 | 当前位置 | 直接调用方 | 真实入口和作用 |
| --- | --- | --- | --- |
| `version_tuple(value)` | `main.py:1937` | `version_gt` 内部（`main.py:1941`） | 将任意可转文本的版本值按正则提取数字，返回整数列表 |
| `version_gt(a, b)` | `main.py:1940` | `check_update`（`main.py:1954`）、`validate_staged_update`（`main.py:2178`） | `GET /api/check-update` 判断远端版本是否更新；`POST /api/update-from-github` 校验暂存版本是否高于当前版本 |

调用链是：

```text
GET /api/check-update
  -> check_update
  -> version_gt(best["version"], current)

POST /api/update-from-github
  -> update_from_github
  -> validate_staged_update
  -> version_gt(version, current_app_version())
```

`current_app_version` 负责读取项目根目录的 `VERSION` 文件，更新流程负责网络、暂存目录、备份和回滚；这些职责不能被版本模块接管。现有 `tests/test_update_private_data.py` 通过 `main.check_update` 和 `main.update_from_github` 间接覆盖比较结果，但目前没有直接导入纯函数的独立测试。

## 数据归属与允许依赖

| 项目 | 约定 |
| --- | --- |
| 模块拥有的数据 | 无持久化数据、无缓存、无全局可变状态。输入是版本值，输出是 `list[int]` 或 `bool`。 |
| 模块允许依赖 | Python 标准库 `re` 和内置 `str`、`int`、`len`、`max`；类型标注可使用 Python 3.10 内置泛型。 |
| 模块禁止依赖 | `main.py`、FastAPI、`requests`、`httpx`、文件路径、网络客户端、锁、画布/素材/任务/供应商状态。 |
| 调用方向 | `main.py -> backend.versioning`；测试可直接调用 `backend.versioning`。版本模块不能反向导入 `main.py`。 |
| 异常行为 | 保留当前行为：输入先转成文本，数字提取始终返回列表；比较时对较短列表补零，不新增异常或静默回退。 |

`tools/prepare-release.py` 也有一个同名的 `version_tuple`，它属于发布检查器，当前不导入 `main.py`。试拆时不要让生产模块反向依赖 `tools`；是否在后续统一这份重复逻辑，应另开范围并重新验证发布脚本。

当前根目录没有 `backend` 包。建议的最小目标路径是 `backend/versioning.py`，并用 `backend/__init__.py` 明确它是可发布的后端包。该包只保存上述两个函数，不顺带搬迁更新、配置或数据代码。

## 最小实施范围（下一步）

1. 新建 `backend/__init__.py` 和 `backend/versioning.py`，按原函数签名和函数体语义实现 `version_tuple`、`version_gt`。
2. 在 `main.py` 的导入区加入 `from backend.versioning import version_gt, version_tuple`，删除原来的两个函数定义，保留这两个名称在 `main` 命名空间中以兼容现有调用方和测试。
3. 新增 `tests/test_versioning.py`，直接验证空值、带前缀/后缀的版本文本、不同段数补零、数字段比较和非数字输入；继续运行 `tests/test_update_private_data.py` 验证两个真实更新入口。
4. 在 `tools/prepare-release.py` 的公开目录白名单加入 `backend`，并在发布预检中确认新包被收录；不把 `API/.env`、`data`、`assets` 或 `output` 带入模块目录。

这一步不迁移 `current_app_version`、`fetch_remote_version`、`validate_staged_update` 或任何更新文件操作，也不改变 HTTP 路径、JSON 字段和版本比较结果。
