# 多页面编辑与保存恢复本地验收

本轮按用户“开始吧”执行两页面编辑、保存中断与保存重开的本地验收。已完成实现和自动/界面验证；用户随后明确回复“可以，继续作下一步吧”确认可用，按AGENTS约定选择性同步本轮源码。

## 已复现的问题与修复

- 普通画布收到409旧版本冲突后，原逻辑仅刷新时间戳重试，可能用旧正文覆盖另一页面刚保存的正文。现按共同基线比较本页和服务器版本，不同节点/字段各保留，同一节点字段冲突保留本地副本并明确提示。
- 普通画布远程更新事件可能清掉本页未保存标记；现保留本地编辑和待保存状态，合并后继续保存。
- 智能画布原节点/连线并集合并会复活另一页已删除且本页未修改的内容；现共同基线中的未改节点/连线以删除为准，清理分组失效成员。删除与编辑并发时保留编辑内容。
- 两画布保存失败后刷新会丢失未保存正文。现编辑时将共同基线与本页草稿备份到当前页面sessionStorage，刷新时与最新服务器内容合并恢复；可见提示和原生“重试保存”按钮提供恢复入口。
- 服务器已写入但成功响应丢失时，刷新识别相同内容并清掉草稿，避免重复节点。存储满或不可用时如实返回备份失败并记录警告。
- 同字段冲突副本保留正文和相关连线，清除运行标记，放在现有节点下方，避免新副本盖住原节点。原节点位置不因产生副本而改动。

## 修改范围

共享规则新增static/js/canvas-save-recovery.js，接入static/js/canvas.js及static/js/smart-canvas.js真实入口。两HTML加载共享模块并更新缓存版本；普通HTML增加保存提示，普通CSS复用智能画布已有提示样式。旧409盲目重试、清理未保存标记以及集合并集分支已就地替换。

新增tests/canvas_multi_page_save.test.cjs的13项回归。现有canvas_meta_revision、smart_canvas_history、smart_canvas_return_save三个测试只补齐真实依赖/共同基线/浏览器对象模拟，保留原断言。知识索引仅更新来源摘要和准确函数行号，不改变能力或413项验收状态。

## 实际界面与保存流程

隔离3053运行当前公开源码，供应商列表为空，只使用两份自制测试画布，正式3002/PID20944保持运行。输入框和重试按钮使用真实界面操作；为稳定制造保存次序及故障，通过开发接口调用原生保存入口、隔离服务器503和客户端网络阻断，不新增产品测试入口。

1. 两页分别修改不同节点，保存后两份新中文正文均在。新增节点及不同字段保留另由回归覆盖。
2. 两页修改同一提示词字段，服务器版及本地副本均保留，副本到循环的连线保持，冲突提示在成功自动保存后仍显示；实点重试后隐藏。
3. 一页修改正文、另一页删除原p节点及q-target连线，已删原节点/连线未复活，分组成员不再引用p，本页正文保留。
4. 普通503保存失败、智能客户端网络断连均显示保存失败并保留草稿；解除故障后刷新恢复正文，实点重试正确落盘且清掉草稿。最终源码又对两种画布503、刷新、重试完整复测通过。
5. 两画布分别模拟服务器已保存而响应503。刷新后原正文仍在且节点数量未增加，草稿清理。最终普通7节点2连线、智能6节点2连线；节点数包含本轮多次制造冲突得到的合法副本。
6. 关闭旧测试标签页，以全新标签页重开。节点编号/中文正文、分组items=[q,loop]、全部2条连线、循环count=3及模板“第{{index}}轮：{{prompt}}”与服务器保存前逐字段一致，无残留草稿/失败提示。
7. 最终新副本的y=660，现有节点下边界=620。初期修复前产生的测试副本保持其旧位置；不把旧测试副本重排作为本次新布局保证。

## 使用与边界

正式页面刷新后加载修复，启动仍用run.bat。双页修改同一节点看到提示时，检查保留的两个版本，再点“重试保存”；根据需要自行整理或删除不再需要的副本。

临时草稿保证当前页面会话内的刷新恢复，不是永久备份；未保存就关闭标签页、退出浏览器或清理浏览器存储后重开，不保证恢复。存储不可用时也不保证刷新恢复。已保存关闭重开已验证。

本轮不是实时协作编辑系统；没有验收多用户权限、全局画布设置同字段冲突、长时间高并发、长音频/大素材、macOS实机或真实复杂循环模型效果。现有智能任务/媒体结果合并规则保留，不把本地保存验证扩大到真实供应商验收。
