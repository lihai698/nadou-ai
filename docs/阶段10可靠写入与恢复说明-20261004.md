# 阶段 10：画布与项目 JSON 可靠写入说明

## 本轮范围

已收敛三个画布和项目 JSON 保存入口：

- `main.py:save_canvas`：保存 `data/canvases/<canvas-id>.json`。
- `main.py:save_projects`：保存 `data/projects.json`。
- `main.py:update_canvas_meta`：通过 `POST /api/canvases/{canvas_id}/meta` 修改画布轻量元数据。

三个入口继续使用原有的 `CANVAS_LOCK`。后续为标题和图标补充了可选的 `meta_revision` 字段；画布 `updated_at` 的含义与旧数据读取方式不变。其他 JSON 写入点仍按原实现工作，不能据此宣称阶段 10 整体完成。

## 写入职责

`backend/atomic_json.py:write_json_atomic` 负责文件落盘步骤：

1. 在目标文件的同一目录创建带有 `.tmp` 后缀的临时文件，避免跨文件系统移动。
2. 按现有 `ensure_ascii=False`、缩进 2 格的格式编码 JSON。
3. 写完后执行 `flush` 和 `os.fsync`，再关闭临时文件。
4. 用 `os.replace` 一次性替换目标文件。
5. 编码、刷新、同步或替换失败时删除临时文件，并继续抛出原始异常。

因此，异常发生在替换之前时，旧目标文件仍可读取；替换成功后，目标文件要么是旧内容，要么是完整的新内容。程序启动时不自动扫描或恢复残留 `.tmp` 文件，残留清理属于后续维护工具的范围。

## 并发与恢复边界

同一进程内，`save_canvas`、`save_projects` 和 `update_canvas_meta` 仍由 `CANVAS_LOCK` 串行化。元数据路由的读取、修改和写入现在处于同一锁内，防止两个元数据请求在本进程内读到相同旧值后相互覆盖。不同进程之间没有新增锁或版本协调；同时写同一文件时仍遵循最后一次成功 `os.replace` 的结果，调用方应在部署层保证单实例或另行协调。

`PUT /api/canvases/{canvas_id}` 的完整保存也已把读取、`base_updated_at` 冲突检查、字段修改和 `save_canvas` 放在同一把 `CANVAS_LOCK` 内；WebSocket 广播仍在锁外。两个使用同一有效基础版本的并发请求，在同一进程中只能一个成功，另一个拿到原有 409 结构与最新画布。此规则依赖客户端提交非零 `base_updated_at`；缺失该字段的旧请求仍沿用原兼容行为。

元数据路由继续保留画布原有的 `updated_at`，因此改标题、标签或置顶不会因时间排序移到列表最前。普通 `save_canvas` 仍将时间更新为当前毫秒时间与旧值加一的较大值。元数据路由继续返回 `{ "canvas": ... }`；其中画布摘要新增 `meta_revision`。

原有规则曾允许较早读取的完整画布在标题或图标更新后通过 `updated_at` 检查并覆盖新值。现在标题或图标经 `/meta` 变更时，`meta_revision` 递增；完整保存传入 `base_meta_revision`，若版本落后且仍带旧标题或图标，接口返回包含最新画布的 409。旧客户端未传修订号时，只要提交的标题或图标与现值不一致且已有元数据修订，同样返回 409；元数据一致时仍能保存内容。缺少修订号的旧客户端需刷新后重试标题或图标修改。

写入失败会向原 API 调用方返回原有错误路径，内存对象不会伪装成已落盘。恢复时保留目标文件并重新提交保存即可；若目标文件本身已损坏，本轮没有新增迁移或备份机制，应从外部备份恢复后再启动服务。

## 兼容性与验证

写入内容仍是旧格式的普通 JSON：项目文件继续使用 `{ "projects": [...] }`，画布文件继续使用原画布对象。旧程序可以读取新文件；新程序也继续读取已有旧文件。本轮新增的隔离测试覆盖：

- 同目录临时文件、`flush`/`fsync` 后再替换；
- 替换失败时旧文件保留、临时文件清理；
- JSON 编码失败时旧文件保留、临时文件清理。

测试文件：`tests/test_atomic_json.py`。

追加的 `tests/test_canvas_meta_atomic.py` 在隔离画布目录中通过真实 HTTP 路由验证：元数据成功写入且时间不变，`/touch` 继续递增时间；模拟 `os.replace` 失败时 HTTP 返回 500、旧文件字节不变，临时文件被清理。该专项 2 项、原子写入专项 3 项、画布基线 6 项、`py_compile`、差异检查通过；完整核心检查通过 Python 131 项、JavaScript 116 项及中英文词条检查，公开包预检通过 308 个文件。追加后未单独做页面实测。

本轮汇总检查还通过 Python 123 项、JavaScript 114 项及中英文词条检查，公开包预检通过 303 个文件。隔离预览服务重启到最新代码后，`GET /api/canvases` 返回 1 块自制测试画布，项目工作台刷新后仍显示该画布。

### 2026-10-04 打开、回收和清除的画布锁

`/touch`、软删除、恢复和彻底删除现将同一画布的读取、判断、写入或删除纳入 `CANVAS_LOCK`。`save_canvas` 本身使用可重入的同一把锁，未新增锁序或广播；原有时间、返回结构和回收站行为不变。原先锁外读取后再保存的路径可能与 `/meta` 交错，将过期标题或图标写回；彻底删除也可能与并发写入交错，留下本应删除的文件。这些旧竞态路径已收敛。

隔离并发测试 `tests/test_canvas_meta_route_concurrency.py` 使用临时自制画布，覆盖打开、软删除、恢复与元数据更新交错，以及彻底删除与元数据写入交错。测试确认软删除后元数据接口仍按原行为返回 404；元数据先完成时，新标题随画布进入回收站。未调用真实画布删除接口。
