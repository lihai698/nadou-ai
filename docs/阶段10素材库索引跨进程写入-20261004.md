# 阶段 10：素材库索引跨进程读改写

日期：2026-10-04  
范围：`data/asset_library.json` 的素材库、分组、条目、工作流和分类/认证结果写入。验证只使用临时目录、自制索引和本地 HTTP 请求，不读取真实素材或配置，不调用供应商。

## 修复

此前索引只有进程内 `ASSET_LIBRARY_LOCK`。两个服务进程可以同时读到旧索引，分别完成修改后依次原子替换，后写入者会覆盖先写入者。现在 `asset_library_index_lock()` 先取得原 `RLock`，再取得索引路径的跨进程文件锁；同一线程嵌套的 `load_asset_library()` 和 `save_asset_library()` 复用锁，异常退出后清理嵌套状态。这样也保持了原有画布、历史和会话引用检查的锁顺序。

所有实际 `save_asset_library()` 入口已核对：启动迁移、工作流导出/上传、资产库与分组增删改、媒体导入提交、条目改名/移动/裁剪/删除、分类结果写回、数字人认证提交与状态写回。每个入口在同一锁区间内重新加载并保存索引。媒体分类和认证的供应商 `await` 位于锁区间外；完成后重新加载当前索引并按条目核对再提交。

普通索引读取和首次创建也使用此锁，损坏索引继续返回固定错误，不覆盖原字节。原子 JSON 替换、保存成功后的广播逻辑保持不变。

## 验证

- `tests/test_asset_library_cross_process.py` 4 项通过：两个独立进程通过真实 HTTP 路由并发创建资产库、并发改名和新增分组，最终索引保留两次修改；损坏索引不被覆盖；嵌套锁只获取一次文件锁且异常后可再次使用。
- `tests/test_asset_library*.py` 共 26 项通过，覆盖媒体导入、分类等待期间的并发操作、索引替换失败和素材副本清理。
- `tests/test_asset_classification_atomic.py` 3 项通过；`py_compile main.py tests/test_asset_library_cross_process.py` 与 `git diff --check -- main.py` 通过。
