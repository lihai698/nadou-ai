# 阶段 9：工作台外围导出模块试拆（2026-10-03）

## 范围与目标

本次先整理外围工作台页面的画布导出，不改普通/智能画布编辑器核心。原 `static/js/canvas-list.js` 中的 JSON 下载、含资源 ZIP 下载、资源扫描、ZIP 编码和文件名处理集中在一段代码里，页面的项目状态与导出实现耦合。将导出职责移到 `static/js/canvas-list-export.js`，由工作台现有卡片菜单继续触发相同操作。

## 模块职责与依赖

| 模块 | 负责内容 | 不拥有的数据 |
| --- | --- | --- |
| `static/js/canvas-list-export.js` | 获取画布 JSON、扫描 `/assets/`、`/output/` 和 HTTP 资源、生成 JSON/ZIP 下载、生成资源清单、报告跳过资源 | 项目列表、画布列表、当前项目、状态提示 DOM |
| `static/js/canvas-list.js` | 工作台项目和画布状态、卡片菜单、菜单定位和交互；传入当前画布查询函数、状态函数和翻译函数 | ZIP 编码器和资源收集实现 |
| `static/canvas-list.html` | 按依赖顺序加载导出模块和工作台入口 | 业务状态与导出数据 |

导出模块只依赖浏览器的 `fetch`、`Blob`、`URL`、`document` 和 `TextEncoder`。页面通过 `getCanvas`、`setStatus`、`translate` 三个回调提供状态边界；模块不反向读取 `canvas-list.js` 的词法变量，也不读写用户文件或配置。

## 兼容行为

- JSON 导出仍请求 `/api/canvases/{id}`，使用当前画布标题清理文件名并下载 `<标题>.json`。
- 含资源导出仍把 `canvas.json`、资源文件和 `resources-manifest.json` 放入 ZIP；资源 URL 去重，文件名冲突使用 `-2`、`-3` 后缀。
- 资源请求失败仍记录到清单并显示“已导出，跳过 N 个资源”，画布接口或打包失败仍显示“导出失败”。中英文提示继续由页面 `L` 回调提供。
- 菜单按钮保持原有两个入口，移除后不存在 `canvas-list.js` 中的第二套导出实现。
- 工作台加载同时检查 `/api/projects` 和 `/api/canvases` 的 HTTP 状态及数组结构；任一接口失败或返回结构异常时保留现有状态并显示加载失败，不再把非 2xx 响应误当成空工作台。

## 恢复与限制

恢复时可删除 `static/js/canvas-list-export.js` 和对应测试，恢复 `canvas-list.js` 导出区块及 `canvas-list.html` 的单脚本引用；不涉及用户数据迁移。浏览器实际下载落盘和真实用户资源未在本次专项中重复验收，沿用 F12 既有隔离证据范围。
