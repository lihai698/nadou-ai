# 阶段 8：素材模块拆分边界审计

日期：2026-10-04  
范围：先只读盘点 `main.py` 中的素材文件、索引、上传目录、引用扫描和删除入口；后续修复存储文件删除入口，未读取 `data/`、`assets/` 中的用户内容。

## 结论与首个拆分点

先把无文件读写的媒体元数据规则拆到 `backend/asset_media_rules.py`：`asset_library_media_kind`、`asset_library_safe_extension`、`_local_upload_kind_ext`、`_local_upload_display_name` 和 `_sniff_image_ext_bytes`。它们只根据文件名、Content-Type 或传入字节返回类型、扩展名和展示名；允许依赖 Python 标准库 `os`、`re`，不持有路径、配置、锁、FastAPI 或用户数据。`main.py` 从新模块导入原函数名，保持现有接口与内部调用点。素材库与本地上传支持的格式并不完全相同，应保留各自规则，不强行合并。

此步骤需要给格式优先级、未知格式回退、WebP/PNG/JPEG 文件头、`up_<12位十六进制>_` 展示名补专项测试，并运行本地上传、素材库、画布导出相关回归。验证通过后搜索 `main.py`，确认原函数体已删、生产规则只保留一套。`sanitize_asset_name` 同时供提示词库、画布和共享文件夹使用，本轮不归入素材模块；`normalize_asset_library` 会修改传入字典、生成随机 ID 和时间戳，也不是首个无副作用拆分点。

## 删除与引用边界

- `delete_local_assets`（约 12622 行）按 `CANVAS_LOCK`、`HISTORY_LOCK`、`CONVERSATION_LOCK`、`ASSET_LIBRARY_LOCK` 顺序检查主文件和旁车；历史无法读取，或画布、对话、素材库任一可读索引仍引用它时，保留整组文件。对应 `tests/test_local_asset_delete_references.py` 和 `tests/test_asset_library_atomic.py`。
- `remove_asset_library_file`（约 7393 行）只考虑 `assets/library` 内的库副本；调用者先保存新索引，再按相同锁序检查历史与其他持久化引用。分类、单条、批量删除分别在约 17068、17443、17462 行调用。对应 `tests/test_asset_library_cleanup.py`。
- 画布日志清理（约 17601 行）与历史记录删除（约 18120 行）也扫描引用后清理生成媒体；现已按画布、历史、对话、索引的锁序在检查与删除之间保护索引，画布日志裁剪历史后会再次检查。相关测试为 `tests/test_history_cleanup.py`、`tests/test_canvas_log_cleanup.py`、`tests/test_asset_library_atomic.py`。画布工作流导出通过 `tests/test_canvas_workflow_export.py` 覆盖本地素材引用。
- `/api/storage-files/delete`（约 6997 行）已补同样的引用保护：按 `CANVAS_LOCK`、`HISTORY_LOCK`、`CONVERSATION_LOCK`、`ASSET_LIBRARY_LOCK` 顺序，在锁内核对历史及画布、对话、素材库 JSON；被引用或记录损坏时保留文件，并返回 `skipped_referenced` 与中文 `skipped_reason`。路径越界返回 400；无引用文件继续删除并返回原有 `removed` 数量。管理界面会提示保留数量与原因。隔离 ASGI 回归见 `tests/test_storage_file_delete_references.py` 和 `tests/test_asset_library_atomic.py`。

因此，文件删除、目录迁移和索引写入暂不作为第一块拆分。尤其不能把引用扫描简单搬进素材模块后继续直接读取画布、对话与历史内部文件；应先明确只读引用查询接口与锁序，保证检查到删除之间没有并发写入窗口。现有 `main.py` 仍是这些操作的唯一实际入口，阶段 8 整体不据此判定完成。

## 依赖方向与后续顺序

1. `main.py` 和需要识别素材类型的画布/上传调用方 → 无状态 `backend/asset_media_rules.py`；新模块不得导入 `main.py`。
2. 之后拆存储 URL/路径解析时，把当前目录作为显式输入；保存 `/assets/`、`/output/`、`/api/storage-files/` 兼容语义，并给路径穿越和配置目录场景补测试。
3. 素材库索引现已收敛到 `load_asset_library` / `save_asset_library` 与同进程锁，原子写入及广播边界见[索引可靠写入说明](阶段8素材库索引可靠写入-20261004.md)。后续拆模块时继续保留缺文件初始化、损坏文件拒绝覆盖、成功保存才广播这些规则。
4. 最后处理上传目录迁移、素材删除和跨画布/历史引用查询；统一直接存储删除与其他删除入口的引用策略后，再移动实际删除代码。

初次审计仅凭代码与现有测试确认边界。后续删除入口修复通过自制文件的隔离 ASGI 回归；未在真实用户素材上操作。素材库副本清理由 `CANVAS_LOCK` → `HISTORY_LOCK` → `CONVERSATION_LOCK` → `ASSET_LIBRARY_LOCK` 检查索引及引用后删除；直接存储、本地上传、历史和画布日志清理也已按同序核对。外部进程仍可直接修改文件，因此跨进程的数据所有权仍待处理。此次未拆分文件删除模块。
