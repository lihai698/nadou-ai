# 创作助手功能盘点与下一步清单

盘点日期：2026-10-16。源码基线：`275a28aa827ce475b2cf2539f565e68289692236`，分支 `codex/creative-assistant-agent`。

本轮只盘点，不修改业务功能。用户确定：拆分、循环保持现状；Skill 安装及其规划能力后续再讨论；现有分镜流程只是一种可组合用法，不固定成唯一创作路线。

## 一、结论

创作助手已经具备画布 Agent 的基础执行链：理解需求、读取画布、调用工具、创建和修改原生节点、提出运行方案、按授权执行、查询实际结果、保存和继续原回合。它仍是受限的画布创作 Agent，尚未提供完整 IDE 的代码编辑、终端和任意程序执行能力。

当前主要问题是能力和验收说明没有完全跟上实现，以及真实供应商、多平台、多步骤创作效果仍缺少完整验收。不能把这些统称为“没有实现”，也不能把已通过的模拟链路说成所有模型均可用。

本轮未发现已复现、必须立即停止使用的新增 P0 故障。发现三类明确的说明问题：原生动作目录的确认/服务描述过时、知识验收状态未逐项对齐、早期进度表与后续实施记录分散。先消除这些不一致，再基于真实失败记录改执行逻辑。

## 二、状态含义和证据边界

- **已实现并验证**：真实执行入口存在，相关自动检查通过；部分用户流程另有前几轮实际界面模拟验收。这里的“验证”不代表真实生成质量已通过。
- **已实现但未完整验证**：源码和相关组件测试存在，跨画布/全动作/真实服务或界面组合尚未完整验收。
- **存在问题**：本轮有源码或状态接口证据；说明不一致与实际执行故障分开描述。
- **尚未实现/暂缓**：明确缺少对应产品入口，或现有合同刻意未开放，不当成故障要求现在开发。

本轮浏览器自动访问被安全策略拒绝，因此没有重新点击界面；不绕过策略。本报告的界面结论来自前几轮已保存的验收记录，本轮新增证据为源码、只读能力接口和自动测试。

## 五、已确认的混乱和限制

### P1：能力目录说明与真实执行策略不一致

`backend/canvas_assistant_native.py:native_catalog` 对大部分节点统一返回“原生动作须用户确认”“服务执行仍待逐类接入”。同时，其 availableActions 已列出 run，自动执行规则也允许普通编辑及本轮授权内运行。

这是确认说明过时，不是证明 run 全部不可用。该目录会作为 read_native_capabilities 的实际工具结果送给模型，存在误导规划的合理风险；本轮没有复现“只因该文字就阻断”的具体请求。下一步应先校准说明，不删掉实际执行前的输入/模型/任务归属检查。

### P1：验收状态的粒度不足

本轮只读 status 返回 knowledge.available=true，23 条 documented/readable 通过，但 actionable/verified 均为 0；索引使用 pending，证据说明仍有“阶段B逐类接入”“全动作和真实供应商效果未验收”。

0 是索引内“完整登记为 passed”的数量，不代表所有动作均不能执行，也不能为了好看把全节点标为通过。应区分源码已接入、组件测试、模拟界面、真实供应商、作品质量五种证据，逐类记录，保持未验证项可见。

### P2：早期计划与当前实施记录没有收敛

早期整改计划还有许多未勾选条目，后续已有任务面板、正式结果、模型节点、逐镜配图和恢复验收文档。当前状态应从这些证据汇总，而不是继续把早期“待开发”清单当现状。不要仅批量勾选没有完成的整阶段项目。

### P2：多入口并存，职责尚需清楚呈现

- apply_canvas_operations：整批结构修改；propose_native_action：原生动作与实际 run；execute_plan_step：带依赖的编排。它们有不同职责，不能只因名字重叠就删除。
- create_story_workflow 是保存已写好的内容结果图；create_story_analysis→import_story_analysis 是真实模型分析流程。前者不能被称为后者。
- `OPERATION_GUIDE` 仍含早期确认与类型描述，本轮全项目搜索未发现运行时引用该常量；parse_plan 仍被兼容协议使用。后续可单独确认并清理无调用的旧说明，不能连带删除仍使用的兼容解析。
- 直接画布运行与助手授权运行有不同入口，是否存在可复现的不必要阻断需要按失败记录核对，不能据分支数量猜测。

### 明确保留的必要机制

原任务编号与受理未知处理、实际结果保存、旧图保留、用户选择模型与调用预算、停止/回合归属、分镜修改后的结果有效性。它们与用户成果和费用直接相关，后台运行即可，不以“界面简洁”为由删除。

### 可折叠或后续清理的内容

工具名、读取规则记录、重复状态文案应留在任务详情；不应挤占正式作品区域。无运行时引用的旧说明、实际被替代的渲染分支可按引用搜索和验证逐项删除。本轮没有证明旧结果图/计划/兼容解析可整体删掉。

## 七、下一步只做什么

**建议第一步：校准已有能力说明和验收记录，不新增功能。**

1. 将 read_native_capabilities 返回的确认条件改成实际规则：普通安全编辑、已授权模型调用、必须由用户决定的动作分别说明。
2. 将“服务执行待接入”的统一旧文案改为逐类型/逐模式限制，保留真实未验收部分。
3. 汇总实际验收证据，明确模拟验证与真实服务验证；不把 actionable/verified 简单全改成 passed。
4. 将这份清单作为下一步依据，避免重复开发已经存在的节点与工具。

完成标准：能力接口与实际运行合同不矛盾；助手读取后能区分“可执行但未真实验收”和“没有开放”；本次 522 前端、相关知识/能力测试继续通过。这里是后续建议，本轮没有实施这些修改。

**再后一步：补典型任务验收。**以短文本整理、故事到分镜、单镜修改配图、失败续行四个任务，在两种画布分别确认输入、执行次数、保存和结果。收费模型效果另列范围，当前不自动调用。先用已有工具，不固定未来 Skill 路线。

Skill 安装、自动规划增强、更多模型/引擎、拆分与循环改造继续暂缓。
