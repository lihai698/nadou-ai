# 阶段 8/10：素材库索引可靠写入

日期：2026-10-04。实际索引入口仍是 `main.py` 的 `load_asset_library`、`save_asset_library`；文件仍为 `data/asset_library.json`，库内副本仍在 `assets/library/`。本次不迁移私人索引和素材，也不改变 JSON 字段、`updated_at` 或成功保存后的 WebSocket 素材库更新通知。

`save_asset_library` 现在统一调用 `backend.atomic_json.write_json_atomic`。写入先在目标目录建立临时文件并刷新到磁盘，再原子替换旧索引；替换失败时旧字节不变、临时文件清理，且不广播成功通知。`load_asset_library` 仅在文件不存在时初始化并通知；已有文件无法读取或 JSON 格式错误时返回明确错误，避免后续修改把损坏索引重置成空库。

同进程更新由 `ASSET_LIBRARY_LOCK` 串行。无 `await` 的库、分类、条目和工作流写入路由在读取至保存期间持锁；启动目录整理也持同一把锁。上传、智能分类、数字人认证等需要等待文件或供应商的路由先完成等待，再在锁内重读当前索引、合并本次结果并保存，因此等待期间其他请求修改的条目不会被旧快照覆盖。待写入的新副本遇保存失败或目标分类被删除时，会在锁外按现有引用检查清理。单条、批量、分类删除在保存索引后释放该锁，再按 `CANVAS_LOCK` → `HISTORY_LOCK` → `CONVERSATION_LOCK` → `ASSET_LIBRARY_LOCK` 检查引用并删除副本，避免反向取锁。

`/api/storage-files/delete`、`/api/local-assets/delete` 和 `/api/history/delete` 现按 `CANVAS_LOCK` → `HISTORY_LOCK` → `CONVERSATION_LOCK` → `ASSET_LIBRARY_LOCK` 在同一临界区检查引用和删除文件，避免索引刚更新而删除请求按旧索引清理文件。画布日志清理先在同一锁序下挑出未引用媒体，再调用自带 `HISTORY_LOCK` 的历史裁剪函数；裁剪返回后重新按完整锁序核对历史及持久化引用，并在第二次锁内删除媒体。这样索引在历史裁剪期间新增引用，也会保留文件。通过静态调用链检查，9 个使用 `serialize_asset_library_update` 的路由及其可达本地函数没有 `await`、`async for` 或 `async with`，持有可重入线程锁时不会让出协程执行。

隔离测试 `tests/test_asset_library_atomic.py` 10 项通过：模拟替换失败验证旧索引字节、通知及临时文件；已有 JSON 损坏时真实 HTTP 修改拒绝覆盖；真实 ASGI 两个图片加入请求在分类等待处重叠，最终两条都在索引中；分类期间重命名能与分类结果合并，分类被删除时提交返回 404 且不留孤儿副本；失败加入不残留未入索引副本；库创建和重命名路由仍接收原有 HTTP 参数；四个删除入口在索引事务结束前等待，随后识别新引用并保留文件；画布日志历史裁剪后新增引用也能保留源文件。素材副本删除、媒体规则、工作流导出、两个存储删除入口、画布日志及历史清理的相关回归共 44 项通过。所有测试使用临时目录和自制字节，没有读取或修改真实素材。

限制：此锁只协调当前 Python 进程的上述入口；外部程序和多服务进程仍可与索引写入交错。索引与媒体副本分开落盘，不构成跨文件事务。对于已损坏的现有索引，需从可信备份恢复；本次没有自动修复或改写它。阶段 8 和阶段 10 整体继续保持未完成。
