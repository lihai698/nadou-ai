# 阶段 11：本地任务并发限制

## 已实现范围

新增 `backend/task_concurrency.py`，为图片、ComfyUI 和视频后台 worker 提供本进程异步闸门。默认上限是：图片 2、ComfyUI 1、视频 1；可以分别用以下环境变量调整为 `1..32` 的整数：

```text
NADOU_IMAGE_TASK_CONCURRENCY=2
NADOU_COMFY_TASK_CONCURRENCY=1
NADOU_VIDEO_TASK_CONCURRENCY=1
```

任务提交仍会先写入 `queued` 记录。只有取得闸门后才进入 `running` 和供应商/本地执行，所以等待中的任务不会被误报为已执行；任务记录清理和远端查询仍按原有状态规则工作。`GET /api/maintenance/task-concurrency` 只返回本进程的上限、运行数和等待数，不返回任务输入或供应商配置。

## 并发边界

这是每个服务进程的限制。多个独立服务进程不会共享计数，也不能用该接口推断供应商账户的全局并发；部署多个进程时仍需在反向代理、进程数量和供应商配额层面单独约束。视频默认只允许一个本进程 worker，降低重复计费和本机长轮询同时发生的风险；未知状态不会自动重提。

## 验证

`tests/test_task_concurrency.py` 3 项通过，覆盖环境变量非法回退、闸门阻塞第二个 worker、运行/等待计数和取消等待清理；`tests/test_canvas_task_concurrency_integration.py` 1 项通过，使用真实图片任务 HTTP 入口确认第二个任务在第一个 worker 释放前保持 `queued`。图片、ComfyUI 生命周期及视频远端协议回归继续通过，确认闸门接入没有改变 `queued → running → succeeded/failed/unknown` 语义。测试只使用临时目录和模拟生成，不连接真实供应商。

## 尚未覆盖

本轮没有声称跨进程全局队列、供应商实际配额、远端取消或视频任务自动清理已经完成；这些仍需要具体部署方案和供应商协议证据。
