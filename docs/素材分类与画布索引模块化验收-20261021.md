# 素材分类与画布索引模块化验收（2026-10-21）

本批归并 main 中的素材分类、画布素材提取与索引汇总，保持现有 HTTP、数据和失败边界。整体模块化仍未完成。

## 职责与数据归属

| 所有者 | 本批职责 | 实际入口与依赖 |
| --- | --- | --- |
| `backend/asset_media_rules.py` | 分类维度、标签清洗、去重/限长、模型文本解析 | 分类供应商适配和本地素材旁车服务直接调用；时间函数显式注入，不拥有真实时钟或文件 |
| `backend/canvas_asset_rules.py` | 节点素材提取、画布内去重、公开索引字段、分类计数和排序 | 复用 `canvas_records.canvas_record` 与媒体规则；只处理传入文档，不读写目录 |
| `backend/canvas_store.py` | `asset_documents()` 拥有素材索引所需的画布扫描与回收站清理 | 复用当前共享锁、目录和时钟；读文件/JSON 失败跳过，保留原读取顺序与锁范围 |
| `backend/local_asset_service.py` | 分类旁车的读取与原子写入 | 直接导入分类规则，注入路径/时钟/写入器；坏文件返回 None，原字节不变 |
| `main.py` | HTTP、供应商和存储装配 | `/api/canvas-assets` 保留线程池调用，`canvas_assets_index()` 仅组合存储扫描与纯汇总；分类真实调用已迁移 |

main 中旧分类/提取函数、维度常量及提取专用导入已删除。没有保留旧主体或无用转发。存储的 `records()` 校验版本且只返回摘要；素材扫描原本不校验版本并需要完整节点，故不能复用该接口改变数据合同。

## 边界与复现

本地素材面板地址为 `/api/storage-files/local/...`，旧画布素材索引只收录 `/assets/`、`/output/` 和 HTTP(S)，所以前者仍不计入素材索引；基线与候选都如此，本批未改变 URL 支持范围。Windows 瞬时读取拒绝仍由原有 best-effort 旁车读取回退处理；强杀时会遗留一个已刷盘但未替换的临时文件，既有目标未损坏，未新增清理机制。

仅使用公开源码隔离副本与自制图片/画布，不读取私人配置或用户数据，不调用真实供应商，不发布。未验收真实分类模型质量、完整产品全部功能、动态插件及长期性能。

本机证据在 `.git/modularization/asset-business-20261021/`：`verify.py` 的 `red/baseline/focused/core/audit`、`contract.py`、`browser-verify.py baseline|candidate`、`lifecycle-verify.py baseline|candidate`、`dependency-audit.py`、`preflight.py` 及日志/JSON/截图。浏览器脚本早期的 URL/默认分类假设与并行共享端口记录问题已修正；采用最终分别记录端口的串行基线/候选结果，不采用失败探测结果。
