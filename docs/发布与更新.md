# nadou ai 发布与更新

当前工作目录是开发源码。公开发布使用 `lihai698/nadou-ai`，保留原项目 `LICENSE` 和 README 中的来源说明。原有 `basketikun/infinite-canvas` 是另一套程序，不作为本项目更新源。

## 第一次发布

1. 已在 GitHub 创建公开、空白的 `lihai698/nadou-ai` 仓库，没有初始化 README、License 或 `.gitignore`。
2. 等当前开发与验收结束，备份本机私人数据，完成相关测试。不要把正在修改的开发目录直接当成稳定版。
3. 将 `VERSION` 改成高于上一版的数字版本，例如 `2026.10.04`；在 `static/update-notes.json` 写同一版本、更新内容和 `update_mode`。
4. 运行 `python tools/prepare-release.py` 检查，再运行 `python tools/prepare-release.py --build`。它只导出公开源码，排除 `API/`、`data/`、`assets/`、`output/`、验收证据和旧 Git 历史，同时生成完整 ZIP。
5. 保持导出目录原样，在开发目录用已安装依赖的项目 Python 运行 `python\python.exe tools\verify-release-startup.py output\release\nadou-ai-版本 --python python\python.exe`。它会校验清单哈希和私人路径，在临时目录启动并确认根页、静态页返回 HTTP 200。另将完整 ZIP 解压到隔离目录，运行其中的 `安装依赖.bat` 和 `tools\check-environment.py`，验证新用户首次安装。不要在导出目录直接安装依赖，否则新增的 site-packages 会违反发布清单。任一检查失败时不要继续分发。
6. 在导出的 `output/release/nadou-ai-版本` 目录建立**新的** Git 历史并推到新仓库。不要直接把当前目录的旧历史推送到公开仓库；旧提交中曾跟踪私人文件。
7. 在新仓库创建与版本对应的 `v版本` 标签。GitHub Actions 会核对版本并把完整 ZIP 附加到 GitHub Release。正式对外发布前，在独立安装目录实际启动和操作主要页面。

当前开发目录的 `origin` 获取地址已指向 `lihai698/nadou-ai`，推送地址在本机禁用，以防误传旧历史。首次推送时只在第 4 步导出的干净目录添加新仓库作为 `origin`。

## 以后每次发布

先合并并测试改动，再更新 `VERSION` 和 `static/update-notes.json`，执行发布检查，发布源码与对应的完整 ZIP。`main` 始终保持可用的正式版本；开发和故障修复先在独立分支或隔离目录完成。用户的密钥、配置、画布、对话和素材应在升级前另行备份。

从 `2026.10.07.2` 过渡版本起，左下角发现新版会发亮，点击后在程序内打开更新窗口。按“开始更新”后显示完整 ZIP 的实际下载量；下载完成会校验清单和每个文件的 SHA256，备份程序文件，退出旧服务后安装并自动启动新版。安装失败时自动恢复备份并启动旧版。`API/.env`、`data/`、`assets/`、`output/`、`history.json` 和 `global_config.json` 不参与覆盖。

`2026.10.07.2` 必须发布为 `in_app`：旧版更新器只能安装 `main.py`、`VERSION` 和 `static/`，这次将新更新器送到旧安装中。之后 `full_install` 版本也可通过同一个界面直接更新；首次安装仍使用 GitHub 的完整 ZIP。发布时必须确保对应标签的完整 ZIP 已上传，否则程序会提示稍后重试。

`update_mode` 保留为发布范围标记：

| 值 | 适用范围 | 用户点击更新后 |
| --- | --- | --- |
| `in_app` | 为旧客户端准备的过渡版本，运行文件只改 `main.py`、`VERSION`、`static/` | 旧客户端可直接安装；新客户端走完整 ZIP 更新 |
| `full_install` | 改动依赖、Python、安装/启动脚本、CLI 等其他文件 | 新客户端在界面内下载完整 ZIP、显示进度、安装并自动重启 |

发布检查会对照仓库现有版本：`in_app` 版本中其他运行文件发生变化会被拒绝。文档、测试和发布工具不影响旧客户端运行，允许一并更新仓库源码。无法访问 GitHub 或校验失败时不会安装；完整版本的恢复点也可在“恢复版本”中选择。新版本首次启动若需安装或调整依赖，启动脚本会按锁文件检查并处理。
