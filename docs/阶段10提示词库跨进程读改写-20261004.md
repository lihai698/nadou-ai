# 阶段 10：提示词库跨进程读改写

日期：2026-10-04  
范围：`data/prompt_libraries.json` 的库、分组和提示词读改写。只使用临时目录、自制内容和本地 ASGI 请求，不读取真实提示词库。

## 本轮改动

提示词库之前已有原子替换和进程内锁，但各路由的“读取 → 修改 → 保存”分别加锁。两个服务进程可以读到同一份旧列表，后写入者覆盖前一个修改。现在 `main.py` 的所有提示词库修改路由使用 `serialize_prompt_library_update`，在一段跨进程文件锁与原有进程锁内完成读改写；普通读取和直接保存也使用同一个文件锁。内部无锁读写只供已持锁的路由调用。

修改路由遇到损坏或无法读取的现有 JSON 时返回固定错误并保留原文件，避免把默认提示词库写到损坏文件上。普通只读加载仍可返回默认视图，保留原有页面回退方式。JSON 字段和 API 返回形状未改变。

并发演练还暴露了 `backend/process_lock.py` 在 Windows 首次创建锁文件时的占位字节竞争：一个进程锁定字节后，另一个进程的 `flush` 偶发 `PermissionError`。Windows 可以直接锁定空文件的第一个字节，因此移除了占位字节初始化；锁文件仍长期保留，旧锁文件也兼容。

## 验证

- 提示词库原子读写和损坏保护 3 项通过。
- 临时目录中两个独立进程同时调用真实新增库入口，最终两个库均保存；并发专项连续 12 轮通过。
- 已登记的 HTTP 路由完成“新增库 → 新增分组 → 新增提示词 → 改名 → 删除提示词/分组/库”流程，最后只保留系统库。
- 损坏索引下的修改入口返回固定 500，原始字节不变。
