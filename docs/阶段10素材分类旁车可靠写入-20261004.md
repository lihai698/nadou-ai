# 阶段 10：素材分类旁车 JSON 可靠写入

日期：2026-10-04  
范围：`assets/uploads` 下每个本地素材对应的 `.classification.json` 旁车文件。测试只使用临时目录和自制分类内容。

## 改动

- `main.py` 的 `_write_local_upload_classification` 保留现有分类规范化和文件命名规则，改用 `backend.atomic_json.write_json_atomic` 写入同目录临时文件，完成刷新后再替换目标文件。
- `_read_local_upload_classification` 遇到不存在、损坏或非 JSON 旁车时继续返回 `None`，不会在读取失败时用默认分类覆盖原字节；成功重新分类时仍允许用新的有效结果替换旧旁车。
- 没有新增第二套分类格式或迁移入口，列表、上传、网址导入、重命名和移动路由继续使用原旁车路径。

## 验证

`tests/test_asset_classification_atomic.py` 3 项通过，覆盖规范化结果回读、模拟 `os.replace` 失败时保留旧字节并清理临时文件、损坏旁车读取不覆盖原文件。测试未读取真实素材、分类文件、API 密钥或供应商。

## 限制

原子替换解决单进程崩溃和半截 JSON；同一素材被多个进程同时重新分类时仍是最后一次替换生效，跨进程锁、分类结果与媒体文件的跨文件事务以及备份恢复演练仍属于阶段 10 后续工作。
