# 阶段 10：可重复的项目备份、校验与恢复流程

## 范围

新增 `backend/backup_restore.py` 和 `tools/backup-restore.py`，把备份、完整性校验和恢复拆成三个显式动作。工具只处理调用方指定的目录，不在导入或启动时扫描项目，也不会自动上传或覆盖现有目录。快照清单保存相对路径、文件大小和 SHA256，不保存源目录绝对路径。

创建快照时跳过 `.git` 和 `__pycache__`，拒绝目录或文件符号链接，先在目标同级临时目录复制并写清单，完成后才改名为目标目录。校验会检查清单版本、路径安全、文件数量、清单外文件、大小和 SHA256。恢复先校验源快照，再复制到新的空目录并二次生成清单；已有目录即使只包含一个文件也会拒绝，避免误覆盖。

## 使用

```powershell
python\python.exe tools\backup-restore.py create --source <项目目录> --snapshot <新的备份目录>
python\python.exe tools\backup-restore.py verify --snapshot <备份目录>
python\python.exe tools\backup-restore.py restore --snapshot <备份目录> --destination <新的恢复目录>
```

输出只有格式版本、文件数量和字节数，不打印配置、提示词、历史或素材内容。快照可能包含私人配置和用户数据，必须放在私有备份位置；公开发布仍由 `tools/prepare-release.py` 单独筛选。

## 隔离验证

`tests/test_backup_restore.py` 7 项通过，覆盖普通文件与 `.env` 自制内容的往返恢复、排除缓存目录、哈希变化、清单外文件、清单伪造、文件和目录符号链接、非字符串/大小写冲突清单、复制失败后的临时目录清理，以及已有恢复目录保护。另有一个子进程测试实际执行 `create`、`verify`、`restore` 三个 CLI 命令，确认输出不包含自制配置内容。测试只写入临时目录，没有读取真实项目数据。

该流程为目录级快照，应用服务停止、浏览器 localStorage、外部 ComfyUI 文件和 CLI 登录会话仍需按部署说明分别处理。真实项目备份前应确认任务已停止、备份盘空间充足，并先执行 `verify` 再使用恢复副本。
