# 项目数据流

## overview

普通/智能画布共用后端任务与素材服务，但节点结构、提示词组合和界面入口不同。

## controls

画布保存节点/连接/设置；素材库和本地材料经已有编号索引进入助手。文本模型负责判断，图片模型来自用户独立选择。AssistantStore保存回合、真实工具回执、知识版本及生成方案；保存冲突先重读。禁止从浏览器提供的任意URL或本机路径直接取素材。read_canvas显示范围/总量，read_node_state补读正文和数组，inspect_result实际发送图片给视觉文本模型。
助手主区域显示答复与结果，执行步骤、已完成节点动作和保存差异集中在默认收起的一行“执行详情”。实时状态更新该进度行，不把工具名称当作最终答复。待确认、失败和受理未知外显；继续创作入口独立保留。界面折叠不取消操作、不删持久回执，不改变收费确认和原任务恢复边界。

两画布普通节点支持可选 nodeTag 分类，鼠标悬浮显示，颜色辅助识别，16 字以内自定义或移除；随原生保存、复制、工作流导出保留，不改变提示词、模型输入和费用。frame 工作组与素材分组独立，界面打组不代表素材吸收；助手不能把 frame 按旧素材组聚合运行或重写成员。

## parameters

模型由用户手选，工具预算与确认边界来自AGENT_GUIDE；目录与能力状态不等于已执行。
原生动作先读取read_native_capabilities。availableActions才是当前开放合同，plannedActions仍未接入；propose_native_action仅预检并保存待确认方案。用户确认时绑定画布版本，只允许一张页面领取执行权；回执按保存文档核对，提交或保存结果不明时只查询，不重放动作。历史输出、原提交提示词、模型配置和素材事实不可作为编辑字段。

read_native_task 查询当前节点已持久保存的 depth/image/video/comfy 编号和种类。编号从 read_node_state 的 depthCapture/videoTaskId/pendingTasks/_pending/_directPending 等实际任务字段读取；不能任意传别的任务，也不调用刷新、提交或重试接口。返回公开状态与结果媒体，不透传内部源路径、请求和凭据。只读查询不将结果自动写回画布，也不替代作品读取和评价。

propose_native_action 的 task_refresh 只刷新已保存的原 image/video 任务，通过原生服务的 refresh 入口查询远端编号，不新提交；task_cancel 只调用原深度任务 cancel。先保存确认权，重复确认不重复调用，响应丢失后 query 只查询原任务。返回原任务状态，不把刷新完成当作品合格；图片/视频/ComfyUI没有在此开放远端取消，ComfyUI停止页面等待也不代表远端取消。任务编号、素材归属和来源变动会拒绝旧回执。
原任务返回后，画布通过原生深度状态更新或媒体完成处理器回填，并保存；同步失败可用“同步原任务到画布”重试，不再次提交生成。深度取消返回 running 时仍等待原任务终态，query 只查原编号；取消请求已受理不等于任务已取消。恢复的媒体保留原节点历史，不覆盖素材和模型。
connect 动作连接原生输入，确认后复用普通 canConnect/输入同步或智能 connectInputNode；智能循环输入开关按原生规则打开，保存连线才有回执。自连、依赖环、正在运行源节点和镜头表禁止的端口均拒绝；分组成员变化使用 group_members，不把输入连接当成员吸收。

## limitations

inspect_result 通过真实本地文件核对完整性和像素、确认请求、原任务归属、数量、保存媒体与必要连接。支持视觉时把原结果及可读取本地参考图送给同一文本模型，record_result_review 保存三态、证据及范围；文件或画布变化拒绝旧评价。没有确认请求的素材检查只能说明文件事实，整体要求为无法判断；不自动再生成。本轮已确认的原生 video run 可按 proposalId 读取原任务全视频与确认请求，核验真实时长、比例、明确像素及音轨存在；最多三帧有限取样不能代表全片或音频语义通过。
持久计划的服务任务累计上限默认零。用户在执行详情明确设置0至100的累计任务额度，模型不能调额；每项运行仍须确认并先预留额度，失败或断线不自动退款、不重提。模型/工具/时间累计上限独立保持。这里的任务次数不代表费用金额。

复杂任务持久计划和全节点自动操作仍按阶段B/C实现，真实模型验收需用户配置和授权。
