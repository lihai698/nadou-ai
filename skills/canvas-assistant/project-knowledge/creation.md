# 创作方法与质量核验

## overview

先确认成品要求，读取节点规则和实际素材，再规划组合、执行可用工具并核对作品。
用户要求文案或分镜落到画布时，助手须读取已有正文或实际创建原生提示词节点；聊天回复或工具调用文本不能作为创建成功的证据。可执行文本分析使用create_story_analysis，普通画布创建独立LLM，智能画布创建开启LLM的smart-prompt，并用input连线读取原文。分析模型来自用户当前勾选的文本模型，不需要图片模型。通过原生run方案确认后运行，再用import_story_analysis校验真实JSON输出并落地分镜表。原文变化后必须重跑分析，不能直接复用旧结果；有手动编辑或已创建配图链的表不自动覆盖。
紧凑的故事、分镜与单张配图可批量创建正文节点后通过 propose_image 提出待确认配图，避免先建空生成器后又创建重复方案。复杂且需恢复的执行继续使用持久计划，收费生成仍单独确认。

已有内容结果图使用 create_story_workflow，两种画布均支持：先保存故事文本，工具将原文剧情依据、角色固定外貌、场景、道具、人物音色、旁白、音效、配乐与逐镜引用绑定，落地六份可编辑创作文档、正式原生镜头表以及每镜提示词→配图节点。普通画布使用 prompt→generator→output，智能画布使用 smart-prompt→smart-image；story 连线仅表达来源依赖，不混入生成输入。source.kind=text，不伪装视频分析，不创建音频生成结果。图片设置保留用户手选平台模型，不写死测试供应商。只需局部提取或修改时组合现有读取/创建/编辑工具，按本次要求执行。
每镜节点先显示镜号、独有画面、景别、机位和动作，再附图片提示词与统一资产设定；不要把相同风格与角色描述堆在六镜开头。imagePrompt只需编写本镜内容，工具自动附统一设定。通过apply_canvas_operations更新带工作流归属的逐镜提示词时，程序原子同步对应分镜表imagePrompt、结构化镜头记录和原生图片草稿；模型选择与已生成图片保留，链丢失或图节点忙碌则整批拒绝。编辑后旧工作流摘要失效，不能按旧正文宣称复用。
工具自动按从左到右布置并保存完整连线：正文→剧情拆解；剧情拆解→角色/场景/道具/声音；剧情拆解及四类资产→分镜表；分镜表→每镜提示词；每镜提示词→配图。总览也关联正文。前半程story连线保存真实创作来源与依赖，配图input连线传入本镜完整提示词；不能把整篇小说和全部资产文本混入每次图片生成，不将来源连线冒充重新调用模型。长工作流画面与连线范围随节点扩展，保存/复制/重开保留关系。1至5千字正文可按实际需求使用同一工具，助手编写内容并读取真实正文，不能由固定范文填充。

## controls

使用现有三项Skill目录，手选Skill优先；它们不会扩大工具权限。复杂任务先拆清文本、参考素材、各阶段产物及依赖。明确主题/受众/构图/风格/镜头/角色一致性及禁用元素；按原生模型能力确定参考和尺寸。每阶段检查真实结果，最终按用户要求检查中文文字、人物一致性、画面构图、素材来源和视频时序。inspect_result送入真实图片后才可声称看过，任务成功不能代替作品质量。无图或模型无视觉时明确未验证；付费图片方案等用户点击生成，不擅自重试。

## parameters

inspect_result 可核对本画布真实图片和视频素材编号。图片按本地完整文件、原任务和确认要求核对；视频只支持可独立读取的本地MP4/MOV、WebM/MKV、AVI，读取真实尺寸、时长、是否有音轨，并提取最多三张带实际时间戳的关键帧。视频抽帧不能证明全片连续性和音频内容；未提供可信作品要求时整体结论为无法判断。只有所选文本模型确实收到本次图片/关键帧，才能登记可见语义评价；文件、任务或画布变化后必须重读，不接受旧评价。检查失败不自动重生或重提收费任务。

模型由用户手选，工具预算与确认边界来自AGENT_GUIDE；目录与能力状态不等于已执行。
多步任务通过create_plan保存目标、保留内容、要求和步骤依赖，再通过execute_plan_step执行一个已开放工具。程序核对真实保存回执后才完成步骤；最终步骤完成无需额外模型调用。模型、工具调用次数和累计活动时间默认不限，持续执行至完成、用户停止或真实错误；新生成服务默认额度为0；已有原任务的查询/取消保留原编号，不作为新生成次数。主动停止不自动续行；断线时先恢复真实写入回执或原任务，不重放已执行步骤。
循环专用字段和剪辑编辑先通过原生动作能力合同核对。智能循环values数组保留每个字段的内部换行和空字段；variablePrompt是兼容正文。剪辑移除走原生remove，保留excludedSources，防止上游同步将已移除素材重新导入。原生方案等待确认；看到方案卡不等于已完成，只有保存后核验的回执能作为下一步依据。

## limitations

局部布局修改由apply_canvas_operations的update.x/y完成，仅接受有限数值，可单独移动节点而不重写正文、不更换模型、不触发生成；read_node_state.parameters返回x/y/w/h。不要将原生动作目录没有move误解为此结构操作不可用。故事工作流工具会一次返回本批全部原文、资产/声音引用及剧情覆盖错误，仍整批拒绝，不保存半成品；助手根据完整错误清单修正后再提交。工作流来源线与图像输入线共用原生左右连接点，SVG尺寸和显示尺寸一致，长图不裁线、不缩放偏移。

持久计划、图片硬条件、已确认原生视频任务硬条件和有限视频关键帧检查已接入现有助手历史。本轮 native video run 的 proposalId 绑定原编号、画布/动作/输入/手选模型和原输出保存；不能从当前节点参数或模型描述伪造确认要求。全节点动作覆盖、视频全片连续性和音频语义仍待继续验收，真实模型效果按授权单列。当前计划默认服务额度为0，用户可在计划卡设置累计服务任务上限，不能以计划或模型文字越过生成确认及额度边界。


## 逐镜模型处理与配图

可执行逐镜配图使用create_shot_prompts(tableId,rowIds)建立单镜素材→原生LLM，propose_native_action.run逐个确认运行。真实运行保存shotPromptResult后，create_shot_images(tableId,rowIds)才建立LLM→原生图片生成节点；复用用户已选平台、模型及尺寸质量设置，不创建时提交任务。表行修改同步该镜素材，使旧结果失效，只重新处理所选镜头。其他镜头及原图保留。
shotPromptMap返回每镜sourceNodeId、processorId，generationMap增加promptProcessorId。已有模型处理的镜头不走旧shot_materialize直接配图流程。重复create_shot_images复用同镜节点；reusedIds必须核对任务状态，不能再次运行成功或受理不明的任务。用户明确要求重做同镜才传newAttempt=true，新建结果分支保留旧图；原任务未结束或受理未知时先查询原编号。素材/模型/结果或连线变化时重新运行本镜LLM，再新建对应配图节点。
